## 控制文件

- `expand/HOLD`：只要这个文件在，lane 就不启动新场景，已经在跑的照跑。CARLA 或驱动出问题时由协调员放上，恢复检查通过后删掉。
- `expand/skip/<kind>_<k>`：挡住某一个场景。目前只有 `ped_010`（等孤儿训练结束）。
- `expand/shared_cards.json`：记录协调员与 CARLA 共用的卡，以及每张卡给几个场景，现在是 `{"3": 2, "4": 2, "5": 2}`。G 线程要回卡时，把对应的键删掉或改成 0，lane 在下一轮（约 2 min）就不再往那张卡上开新场景。
- 调度表行：`runs/sched/table.tsv` 的 `nq4-p3-expand`（GPU 6、3、4、5）和 `nq4-p3-veh-prep`（核 178–183）。

## 卡位规则（写在 `scripts/p3/expand.py` 里）

- GPU 6 是测试卡，固定开 2 个场景（核 168–169、172–173）。
- GPU 0–5：写在 `shared_cards.json` 里的卡按那里给的数量开；其余的卡要等 G 线程的表行不再授予它、卡上没有 CARLA、也没有 wm-loop 的需求文件，才开到 2 个。每张卡用它 G 核片段的最后 4 个核（24k+20 … 24k+23）。
- 开新场景前要求这张卡空闲 ≥ 30 GB，保证 CARLA 至少还剩 8 GB。空闲显存用 nvidia-smi 查，最多每 90 s 一次；CARLA 的数量从 /proc 读，不去轮询驱动。
- 场景失败后等 10 min 再重试，最多试 3 次；第 3 次还失败，整个队列就停下（写 `ERROR.<kind>`）。
- 场景子进程在各自的 session 里，重启 lane（`kill $(cat expand/pid)` 之后执行 `scripts/tmux_run.sh p3-expand python3 scripts/p3/expand.py`）不会带掉它们，新 lane 会按 pid 文件接管。**不要直接关掉在跑场景的 tmux 窗口。**

## 检查清单（每级结束时自动判）

重建（行人、车辆相同）：训练和渲染的 rc 都是 0，被删对象缺失 0，同一视角渲两遍 max |Δ| = 0，全图 PSNR ≥ 22 dB。PSNR < 25 dB 只算标记，每 10 个场景最多允许 1 个。某一级不过，那个队列就停在 `ERROR.<kind>`，这时要上报。
插入：有 meta 就算完成。没有合格供体是正常结果，不算失败（按标准构造，视角差 ≤ 20°、供体框内 PSNR ≥ 22 dB）。

## 复核表：渲染一批并追加

复核表是 [research/p3-review-sheet.md](../research/p3-review-sheet.md)，总表下面分三页（`research/p3-review/{ped-insert,ped-delete,veh-delete}.md`），视频放在 `research/figs/p3/review/`。脚本每次按 box 上当前完成的全部题重新生成，所以「追加一批」就是整体重跑一遍。**一批推一次，不要每题推一次。** 建议的节点：车辆 10 道试点过关后推一次；之后每多 20–30 道车辆题，或行人扩量每一级结束时各推一次。

```bash
# on the box (CPU, ~1 min per 10 items)
cd ~/data/jev-drive && git pull
taskset -c 176,177 $DATA_DIR/envs/jevdrive/bin/python scripts/p3/review_sheet.py render --out $DATA_DIR/runs/nq4/p3/review

# on the Mac
cd ~/mycode/jev-drive && git pull
scp -q "autodl:/root/autodl-tmp/ujs/runs/nq4/p3/review/figs/*.webp" research/figs/p3/review/
scp -q autodl:/root/autodl-tmp/ujs/runs/nq4/p3/review/items.json /tmp/p3_items.json
python3 scripts/p3/review_sheet.py md --items /tmp/p3_items.json --stamp "<date time> CST" \
  --pending "**还在路上**：<how many vehicle / pedestrian items are still pending and the ETA>"
git add research/p3-review-sheet.md research/p3-review research/figs/p3/review
git commit -m "research: P3 review sheet, batch <n>" -- research/p3-review-sheet.md research/p3-review research/figs/p3/review
git push
```

**注意**：`md` 会重写整页，用户已经填进「结论」列的内容会被覆盖。追加之前先看分页里有没有用户填的字，有的话先把这些行存下来，重写后再按编号并回去（或者先问 main）。每题的视频约 0.35 MB，150 道左右约 50 MB，要控制在 60 MB 以内；超了就把 `clip()` 的 `quality` 从 62 调低，或者再按类别拆页。

## 什么时候上报 main

- 任何 `expand/ERROR.<kind>`、`p3veh/PREP_ERROR`，或者 lane 进程没了而 `DONE` 也没写。
- 某一级检查清单不过（车辆第 1 级的删除缺失 > 0 尤其要报：说明「所有车辆都建成刚体节点」这个偏离没有生效）。
- 数据盘剩余不到 200 GB（车辆 prep 在 150 GB 处会自己停下）。
- G 线程的每小时路线数明显下降、或协调员要回 GPU 3/4/5：先改 `shared_cards.json`，再报。
- 车辆 10 道试点过关时报一次（附复核表链接），全部完成时报一次；其余时间每 3–5 h 最多报一次。
