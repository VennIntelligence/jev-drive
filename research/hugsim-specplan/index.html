用模型自己的 plan 来转向：转弯路线更差，但没有打转或振荡

结论：联合训练 plan 与 action 的理由，在这个检验里没有得到支持。把 HUGSIM spec 预设的横向曲率从 action 头换成 plan 的曲率（openpilot 的 get_curvature_from_plan，0.275 秒处的偏航与偏航率），其余链路（clip、延迟、纵向）不变。4 个臂（P2 与 P2+hinge 各两个 seed）×64 个场景：全部 HD 0.339（spec 0.394，exam 0.398，WA-JEPA 0.451）；23 条转弯路线 HD 0.170（spec 0.279，WA-JEPA 0.442）；41 条直路线 0.433（spec 0.459）。转弯路线上配对差 -0.109（95% 区间 -0.198 到 -0.029），3 胜 12 负 8 平，每个臂单独看也都是负的。

设置

新预设 spec_plan：横向指令曲率 = 2ψ(t)/(v·t) − 偏航率(0)/v，t = 0.275 秒，ψ 与偏航率取自模型 plan 输出的偏航通道。之后仍经过 clip_curvature、0.25 秒横向延迟，纵向仍由 iLQR 跟随 plan 的速度。对照是同一批臂已有的 spec 与 exam 结果，没有重跑。转弯路线指记录路线的航向变化范围不小于 30°，共 23 条；其余 41 条为直路线。

打转与振荡

四个臂在全部 64 个场景里的打转数分别为 6、1、2、4（spec 为 2、1、2、2，exam 为 8、11、7、11），没有出现 spec 之外新的打转爆发。按「至少 8 次航向率变号且占行驶步数 15% 以上」的定义，没有一次运行算振荡；但每 100 个行驶步的航向率变号数是 2.0 到 3.0，spec 下是 0，航向率均方根 0.8 到 1.0 度/步，spec 下只有 0.26 到 0.29。也就是说车更抖，但没有失控。

为什么更差：曲率请求更大、更抖

转弯路线上请求曲率的平均绝对值 0.022 1/m，spec 为 0.0066；相邻步变化 0.0090，spec 为 0.0018。直路线同样放大（0.0126 对 0.0036，0.0071 对 0.0011）。单点外推 plan 的偏航和偏航率，把 plan 的噪声放大了，这不是 plan 方向错。

局限与偏差

  • 只检验了 openpilot 原样的单点转换；对 plan 做平滑（例如取 0.5 到 1.5 秒的平均曲率）没有检验，那属于声明的执行层选择，不是 openpilot 自己的路径。
  • 每个场景一次运行；单场景差别小于约 0.2 不算证据；转弯路线来自 17 个场景。
  • 本次运行把单场景超时降到 600 秒、重试 2 次，并让 unix socket 连接带重试；P2-F-s0 有三个场景在高并发下起动失败两次，单独重跑后 768 次运行全部完成。
