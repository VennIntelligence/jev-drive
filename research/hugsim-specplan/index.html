用模型自己的 plan 来转向：单点转换更差，平滑转换更好，传统横向 MPC 与 spec 持平

结论：联合训练 plan 与 action 的理由，在这个检验里没有得到支持。把 HUGSIM spec 预设的横向曲率从 action 头换成 plan 的曲率（openpilot 的 get_curvature_from_plan，0.275 秒处的偏航与偏航率），其余链路（clip、延迟、纵向）不变。4 个臂（P2 与 P2+hinge 各两个 seed）×64 个场景：全部 HD 0.339（spec 0.394，exam 0.398，WA-JEPA 0.451）；23 条转弯路线 HD 0.170（spec 0.279，WA-JEPA 0.442）；41 条直路线 0.433（spec 0.459）。转弯路线上配对差 -0.109（95% 区间 -0.198 到 -0.029），3 胜 12 负 8 平，每个臂单独看也都是负的。

设置

新预设 spec_plan：横向指令曲率 = 2ψ(t)/(v·t) − 偏航率(0)/v，t = 0.275 秒，ψ 与偏航率取自模型 plan 输出的偏航通道。之后仍经过 clip_curvature、0.25 秒横向延迟，纵向仍由 iLQR 跟随 plan 的速度。对照是同一批臂已有的 spec 与 exam 结果，没有重跑。转弯路线指记录路线的航向变化范围不小于 30°，共 23 条；其余 41 条为直路线。

打转与振荡

四个臂在全部 64 个场景里的打转数分别为 6、1、2、4（spec 为 2、1、2、2，exam 为 8、11、7、11），没有出现 spec 之外新的打转爆发。按「至少 8 次航向率变号且占行驶步数 15% 以上」的定义，没有一次运行算振荡；但每 100 个行驶步的航向率变号数是 2.0 到 3.0，spec 下是 0，航向率均方根 0.8 到 1.0 度/步，spec 下只有 0.26 到 0.29。也就是说车更抖，但没有失控。

为什么更差：曲率请求更大、更抖

转弯路线上请求曲率的平均绝对值 0.022 1/m，spec 为 0.0066；相邻步变化 0.0090，spec 为 0.0018。直路线同样放大（0.0126 对 0.0036，0.0071 对 0.0011）。单点外推 plan 的偏航和偏航率，把 plan 的噪声放大了，这不是 plan 方向错。

后续检验：平滑转换与 openpilot 旧版横向 MPC

结论：plan 是可以拿来转向的，只是单点转换太抖。把曲率取为 plan 在 0.5 到 1.5 秒内的平均曲率（航向变化除以弧长，开环转换），再走同样的 clip 与 0.25 秒延迟：转弯路线 HD 0.333（spec 0.279，配对 +0.054，区间 +0.006 到 +0.116），平均每臂走完 5.25 条转弯（spec 为 2.0），4 个臂全部 64 个场景零打转，曲率变号几乎为零。全部 64 个场景 HD 0.428（spec 0.394，WA-JEPA 0.451）。旧版 openpilot 横向 MPC 在转弯路线上 0.291，与 spec 持平（配对 +0.013，区间 -0.006 到 +0.033），也零打转。两者在转弯路线上都没追上 WA-JEPA（0.442）。

两个新臂怎么做的

spec_plan_smooth：曲率 = (ψ(1.5 s) − ψ(0.5 s)) / (s(1.5 s) − s(0.5 s))，ψ 为 plan 偏航角，s 为 plan 位置累计弧长，弧长下限 1 米；窗口是事先定的，没有调。

spec_plan_mpc：openpilot v0.9.4（提交 68aba7ce）的 lateral_planner.py 与 lat_mpc.py，加 controlsd 的 get_lag_adjusted_curvature（延迟补偿 0.275 秒、曲率变化率限制）。每一步把 plan 表达在当前车体坐标系里作为参考，代价权重为路径 1.0、航向 0.11、横向加加速度 0.04、转向速率 700，初始偏航率沿用上一步解出的期望偏航率。与原版的差别：acados 的 SQP_RTI 换成小角度线性化后的精确二次规划解，不加状态边界，旋转半径用丰田级常数，不做速度误差修正。圆弧测试：目标曲率 0.030，稳态输出 0.0284。

打转、振荡与曲率请求

两个新臂在 4 个臂 × 64 个场景里都是零打转（spec 为 2、1、2、2，exam 为 8、11、7、11）。每 100 个行驶步的航向率变号数：smooth 0 到 0.08，MPC 为 0，spec 为 0，单点转换 1.9 到 3.0。转弯路线上请求曲率的平均绝对值与相邻步变化（1/m）：spec 0.0066 与 0.0018，单点 0.0220 与 0.0090，smooth 0.0141 与 0.0035，MPC 0.0089 与 0.0013。直路线 smooth 0.0028 与 0.0009，MPC 0.0020 与 0.0003。

怎么读

  • 单点转换的失败来自噪声放大，不是 plan 本身不稳：把窗口拉到 0.5 到 1.5 秒就从最差变成最好。
  • MPC 给出最平滑的曲率，但转弯路线上并不比 spec 好；它的稳态增益约 0.95，转弯保守。转弯路线上剩下的失败主要是前景和背景碰撞（9.5 与 7.0 个），不是转向抖动。
  • 支持联合训练 plan 与 action 的理由比第一次检验强：plan 的曲率经平滑后已经超过 action 头，转弯路线上与 exam（HUGSIM 自带的 iLQR 跟踪）持平；但仍低于 WA-JEPA，区间包含零但偏负。
  • 局限：转弯 23 条来自 17 个场景；单场景差别小于约 0.2 不算证据；MPC 是 acados 的二次规划替代，常数未针对 P2 的 plan 调整。

局限与偏差（第一次检验）

  • 第一次检验只用 openpilot 原样的单点转换；平滑与 MPC 见上一节，平滑属于声明的执行层选择，不是 openpilot 自己的路径。
  • 每个场景一次运行；单场景差别小于约 0.2 不算证据；转弯路线来自 17 个场景。
  • 本次运行把单场景超时降到 600 秒、重试 2 次，并让 unix socket 连接带重试；P2-F-s0 有三个场景在高并发下起动失败两次，单独重跑后 768 次运行全部完成。
