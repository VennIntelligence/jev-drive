## 6. 用户 14:20 的方向：往路线拉可以，但要有车道线 / 边界，不能拉过头

**为什么四次都切内侧（d286 RBSG2、d302 臂 c、d303 APP1X，以及 RBS）**：S 项里的边界只有「路面可行驶区」栅格；路口内整个交叉口多边形都是可行驶的，对向车道也是可行驶的，所以往路线 / 入口拉的横向 hinge 找最短路就是切内角、切进对向道，边界项不响。
d281 的对向 hinge（YSO25）零分最少（37.5 对 41.5）但按 GT 没选上，是这个方向的旁证。

**设计：路线车道走廊 hinge（替代中心线拉力）**
- 标签：每行（日志行与 on-policy 行）取**路线所在车道**的多边形序列（转弯 = 入口车道 → 路口内 lane connector → 出口车道；变道 = 相邻目标车道），加 0.3 m 余量；分三类：走廊内 0 代价；同向相邻车道软罚；对向车道与路沿外硬罚（权重高）。
- 损失：plan 1–4 s 的车身足迹在走廊外的部分（只横向梯度），1–2 s 权重 2；走廊内零梯度，所以不会拉过头；航向项：plan 2 s 航向相对**车道方向**（不是路线折线）超 10° 向内罚。
- 与此前的差别：RBSG2 / 臂 b 是到中心线的距离（死区外一直拉），走廊是带状的（带内自由）；对向道从「可行驶」变成硬边界；变道时走廊是目标车道，回中心先验被走廊压住。
- 先验证（不训练，存档 rollout）：在 RSG / RBSG2 / 臂 c / APP1X 的 held 与 PAI 转弯零分上，看失败前 1–3 s 的 plan 是否已经出走廊（出 = hinge 会有梯度）。登记线：切内 / 对向 / 过转类零分 ≥ 70 % 在失败前 ≥ 1 s 已出走廊，且完成的弯的 plan 出走廊率 ≤ 10 %。过了再训。
- 10-15 13:38：走廊核查作废（d305）：人类自己 13 % / 33 % 在 0.3 m 走廊外（切左转进对向 connector、贴中心线），完成的弯的 plan 也 37 % 出走廊。plan 几何不区分失败与完成。
