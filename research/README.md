# research/

长期的研究主题。一个主题一个文件（或一个子目录）。

- 按主题命名，比如 `qwen-latent-driving.md`。
- 主题文件里放：背景、核心 hypothesis、相关工作、open questions、目前为止的结论。
- 具体的实验计划放 `todos/`，并链回这里对应的主题。

这里和 `todos/`、`tmp/` 都是人与人、人与 Claude 交流用的工作文档，用中文写。
结论稳定下来之后，再在 `docs/` 或代码里写英文的正式版本。

## 写作惯例（research/ 和 todos/ 通用）

### 文字

- 用自然语言写成段落，把推理讲清楚，不要只堆关键词和 bullet。
- 主干中文，技术术语保留英文。
- **术语在每篇文档里第一次出现时加一句注释**，之后直接用。例如：
  "linear probe（冻结 backbone，只训练一个线性分类器，用来测 feature 里是否线性可读出某个信息）"。
  缩写第一次出现写全称，例如 "ECE（Expected Calibration Error）"。
- 结论和推测分开写。推测要标明是推测，并说明用什么实验可以验证。

### 表格

- 凡是对比（方法、层、超参、baseline）和结果，优先用表格。
- 表里写清楚样本数 n 和数据 split；数值统一小数位，最好的结果加粗。
- 表下面用一两句话说明读法和结论。

### 图

图按 CVPR 论文的出版标准来画，之后可以直接放进论文。

- **文字**：图里所有文字用英文（坐标轴、legend、标注）。图内不放标题，标题和说明写在文档里。
- **尺寸**：按论文栏宽出图，单栏 3.25 in，双栏 6.875 in；字号 8–9 pt，和正文一致。
- **字体**：serif，和 CVPR 的 Times 正文一致（matplotlib 里用 `STIXGeneral` 或 Times New Roman），数学符号用 mathtext。
- **配色**：全项目固定一套色盲友好的 categorical palette（Okabe-Ito）。同一个方法或 backbone 在所有图里颜色保持一致，baseline 统一用灰色。
- **内容**：坐标轴写单位；有多次运行或 bootstrap 时画 error bar 或 CI，并在说明里写清楚是哪一种。
- **格式**：每张图同时导出 PDF（矢量，给论文用）和 PNG（300 dpi，给文档预览用）。
- **风格统一**：所有图都通过代码里同一个 plot style 模块出图（第一次画图时建立），不在单个脚本里手调样式。
- **存放**：文档引用的图放 `research/figs/`，只提交 PNG，单张不超过约 500 KB。PDF 和原始数据留在 box 的 `$DATA_DIR/runs/`。
- **说明**：每张图下面写 1–3 句中文，说明该看什么、支持什么结论。
