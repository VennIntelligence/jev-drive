1. **c 的实测**（每 0.25 s 步、每度计划 1 s 方向的朝向变化）：HUGSIM PR#57 按日志 v < 1 / 1–2 / 2–3 m/s 为 0.066 / 0.146 / 0.307（合成首步 0.01–0.10）；B2D `drive` 的横向控制按日志 0.014 / 0.059 / 0.157（合成上界 0.09–0.65）。HUGSIM 在 1–3 m/s 是临界 c 的 4–17 倍，B2D 低于 HUGSIM。
2. **openpilot 真车栈**（估计，常数凭上游记忆，仓库里没有 vendored 源码）：曲率变化率上限 5 / v² 在 0.5–3 m/s 不起作用（单独跑与原生 c 相同），模型期望曲率的等效 c 约 0.2–0.5。所以第 111 条「真车 c 远小于 0.19」在 openpilot 自己的限值里没有依据，真车不打转的原因另找（推断：真实车辆动力学与转向执行器的滞后，或真车起步时的历史本身不同；未测）。
3. **规则**（调参，已披露）：低速对目标转向角一阶低通，τ = 3 s（≤ 2.5 m/s）线性降到 0（3.5 m/s），只由离线 c 选。闭环里 c 降到 0.024 / 0.065 / 0.241，2–3 m/s 档几乎没降。
4. **HUGSIM 64 场景**：打转 10 → 1（线 ≤ 2，过），原 10 个全部不再打转；同日基线重跑 9 个（噪声约 ±2），剩下那个在重跑基线里也打转。按起步事件首次 6/64 → 0/64、再起步 2/27 → 0/32。非打转 54 个 HD −0.028 [−0.058, −0.006]（重跑对基线 −0.005），下界不过 −0.02；一半来自 3000_3200-medium（完成 → 停住），去掉后 −0.016 [−0.031, −0.003]（事后）。路线完成率 0.349 → 0.315。
5. **B2D 没跑**（门槛没过）；NAVSIM 开环，规则不适用。

**对方向的含义**：只改控制器、不碰模型，打转就消失：起步打转是环路问题，不是模型输入问题，不必动 navhard 上需要早转的 token。但无差别低通同时拖慢合法的低速转向与躲避；下一步是选择性规则（小的计划方向变化滤掉、大的全速跟随，打转偏向只有 1–2°），新臂、新预登记。它在 openpilot 真车栈里没有对应物，只能算逐榜 trick，要标注。
