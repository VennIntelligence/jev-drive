# 136. Alpamayo 在真实急弯上不需要 cross 侧向相机：去掉两路 cross 后预测航向增益不变（+0.011 [−0.145, +0.141]），120° front-wide 已够转；剩余失败来自路线歧义与停 / 走决策，nav 修得了前者；比 openpilot 好主要在 nav 与宽前视（**结论**，弱：预注册 pilot，PhysicalAI-AV 10 个急弯，开环，早停）
2026-10-05。用户提议把 openpilot 的视野扩到 Alpamayo 那样；先测 Alpamayo 本身在急弯上是否依赖多视角，作为给 openpilot 加侧视图的上限。结果 [experiments/alpamayo_turns/results/pilot.md](../../experiments/alpamayo_turns/results/pilot.md)（效应表 `results/effects.md`），预注册 [plans/2026-10-05-prereg.md](../../experiments/alpamayo_turns/plans/2026-10-05-prereg.md)，图 `experiments/alpamayo_turns/figs/`。执行者完成；本条由 main 按其报告写，没有复算。

1. **设置**：PhysicalAI-AV test（Alpamayo 自己的 rig，A 臂原样，无相机映射）；12 个随机 chunk 1180 clip 中 168 个合格急弯，rng(0) 抽 5 左 5 右，航向变化 64–129°、最小半径 5–19 m、中位速度 2.7–5.9 m/s，冻结 `physical_ai_av/alpamayo-turns-pilot@v1`。去掉相机用官方 loader 省略 slot，不是涂黑。指标 A_H = 预测航向 / 日志航向。WOD（单帧、侧前视 ±45° 非 120° cross）与 CARLA 没用。
2. **主比较**（有 nav，去掉两路 cross）：An − Bn +0.011 [−0.145, +0.141]，进弯后次 t0 +0.001 [−0.07, +0.06]；无 nav A − B +0.10 [−0.09, +0.29]。去掉 cross 后仍留 120° front-wide（openpilot wide 58.7° 的两倍）。
3. **对 openpilot**（同一 front-wide 重投影到 road / wide）：绝对 A_H An 0.76、A 0.66、openpilot 0.49；An − OP +0.27 [−0.02, +0.58]，A − OP +0.17 [−0.09, +0.48]；按路径形状（事后）An − OP +0.37 [+0.05, +0.70]。nav 增益 An − A +0.11，与 cross 相机同量级，并修掉无 nav 时的直行歧义。低分多与视觉无关：停车标志 / 让行 case 模型停、司机走，所有臂包括 openpilot 都是 0。
4. **事后诊断**（非预注册）：该 checkpoint 对 slot 布局敏感、对内容不敏感：去掉 tele slot −0.39 [−0.61, −0.20]，slot 留着涂黑只 −0.07；只喂 front-wide 一路几乎不转（0.09，有 nav 0.13），是输入格式问题不是看不见。

**对方向的含义**：给 openpilot 加 Alpamayo 式 cross 侧视图不是优先项；有效的是一路约 120° 的宽前视（Alpamayo 每路约 576×320，即焦距约 166 px，本身就是把 120° 压进小画幅）加路线 / 选择信号。第 135 条显示把 116° 压进 openpilot 的 wide 槽 zero-shot 无害但不被使用，所以宽前视只能靠微调让模型学会用；训练时固定 slot 布局或做 slot dropout。PhysicalAI-AV 有原生 front-wide 120° + cross 120°（test + val 约 15 万 clip，单 clip range-fetch 约 65 MB）。

**状态**：**结论**（弱）。限定：n = 10、单 t0 对；nav 是由日志反推的 oracle；NVIDIA 未说明 test split 是否参与训练；只有开环；C / Tblk / B1t / B1n 臂为事后加。
**会推翻本条的证据**：更大的急弯集（尤其 R < 8 m、视线被遮挡的路口）上 An − Bn ≥ +0.10 且 CI 不跨 0，或闭环中 cross 相机减少碰撞 / 走错。
