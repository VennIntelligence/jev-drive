1. **可运行**：部署 commit 0bb4c4b，wizard 原样生成 compose 与 config，`run_native.py` 把每个 service 起成 host 进程，源码未改。环境偏差：torch 2.9.1+cu128（官方 CUDA 12.4 不支持 sm_120）、workspace member 逐个 editable 安装、LTF 用 torch 2.8.0。
2. **成本**（LTF sample，一张卡）：顺序约 20 s / scene；8 并发 2.96 s / scene，16 并发 2.93（瓶颈是单个 renderer 进程）；renderer VRAM 5 / 12.5 / 17.6 GB（1 / 8 / 16 并发），LTF driver 1 GB，`Drive` 37–41 ms；assets 0.38 G / scene，输出 27 MB / scene。
3. **分数**（不是榜单分，private suite 不同）：48 scene mean scene score 0.8735，5 个 0 分（4 个 `left_corridor_laterally`，1 个 `offroad`）；8 个 dev scene 0.8636（7 / 8）。同一批 8 个 scene 两次运行过 / 不过一致，子指标有小漂移，不是逐位确定。
4. **外推**（没跑）：1 485 scene 三卡各一个 stack 约 25 min、约 1.25 card-hour。数据 15 个 shard 458 GiB 压缩、解压约 565 G，mirror 实测下载 20 h 以上，box 当日空闲 434 G。
5. **driver 实际收到的**（tap log）：每 scene 5.5 s、10 次 `drive`（2 Hz）、8 路相机 × 11 个时刻，**t = 0 之前没有任何历史**；同一步内图像、egomotion、route 到达顺序不固定；route 20 点中约一半是 NaN。

**对方向的含义**：本地闭环评测便宜，可以当开发板用；SH30 需要的 1.5 s / 4 keyframe 历史在每个 scene 的前 3 次决策（共 10 次）拿不到，冷启动规则是接入的主要未知。
**状态**：**成立**（中）。限定：与官方 Docker 环境的数值一致性没有 reference 可比；只测了 part001 的 scene；三个 stack 同跑、每卡多 renderer 没测；测量时其它 lane 在用卡。
