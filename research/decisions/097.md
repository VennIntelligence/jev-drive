# 97. NAVSIM 评分器跟踪器滞后的预补偿（单榜 trick）被否：补偿让仿真轨迹真的实现了模型的计划（误差 1.0–1.4 m → 0.07–0.09 m），但计划被精确实现后真实场景反而更差，跟踪器的滞后对 openpilot 近端横向计划是有益的低通（**否**，原生 Cinque + N4，navhard 5 912 + navtest 12 146 + navtrain 3 000，官方评分器）
2026-10-04。报告 [experiments/skill_pack/results/tracker-precomp/report.md](../../experiments/skill_pack/results/tracker-precomp/report.md)，预登记 [experiments/skill_pack/plans/2026-10-04-tracker-precomp-plan.md](../../experiments/skill_pack/plans/2026-10-04-tracker-precomp-plan.md)（一条补充，写在测试榜数字之前）。由另一位执行者完成；本条由 main 按其报告写，没有复算。门槛：navhard Δ > 0 且 CI 下界 > 0，同时 navtest Δ ≥ −0.30。按用户 2026-10-04 的决定，这是单列的适配 trick。

1. **跟踪器**（从 devkit 代码读出，v1.1 与 v2 相同）：每 0.1 s 一步 LQR，横向看 1 s，Q = diag(1, 10, 0)；自行车模型，转向低通 0.05 s；每个 token 起步转角为 0，横向滞后由此而来。原生计划横向在 1 / 2 / 4 s 的实现比例 0.38 / 0.72 / 0.95，复现了总方案里的 37% / 72%。
2. **做法**：不看参考，只用计划和 ego_status，用评分器自己的 simulator 优化提交位姿，提交 p + α(u* − p)，α 只在 navtrain 上拟合。full 版贴时间对齐的位置和朝向（预登记）；path 版贴路径、保留跟踪器自己的速度（事后）。
3. **结果**：full α1 navhard −5.70 [−8.06, −3.30]、navtest −5.91（原生），N4 −10.53 / −8.47；path α1 −1.61 / −4.31；path 取 navtrain 定的 α = 0.25：navhard +0.42 [−1.01, +1.81]、navtest −0.18，N4 −0.66 / −0.05。没有一个过线。
4. **得失来源**：comfort 崩（HC −53 到 −65，EC −24 到 −31）；真实场景（stage 1、navtest、navtrain）DAC、LK、DDC 下降；只有 stage 2 挪偏起点上 DAC +6、NC +2、TTC +3（滞后拖慢了回正）。
5. **不是刷分**：补偿后的非 comfort 各项跟「理想跟踪器」（计划原样当作仿真结果）一致，没有超出；理想跟踪器本身 navhard −2.34（原生）。把 comfort 换回原值后，只有原生 navhard 为正（+2.83 [+0.34, +5.43]），N4 与 navtest 仍为负。
6. **和第 88 条横向增益（−3.38）的区别**：增益改的是意图（4 s 处实现到 1.12 倍、1 s 滞后几乎不变），输在 DAC / NC / TTC / EP；补偿保留意图、去掉滞后，输在 comfort 和真实场景 DAC。共同原因：评分不奖励把 openpilot 近端横向动作实现得更强或更早。
7. **其他榜**：navtest v2 EPDMS 用同一个跟踪器，预计同向；HUGSIM、B2D、WOD 没有这个跟踪器，不受影响。

**对方向的含义**：输出侧不去对准评分器的跟踪器。stage 2 上「偏离后修正太慢」的问题要在计划本身里解决，即第 3 层「朝向 / 横向偏移 → 立刻修回」配对；按不看参考的「起点被挪偏」信号门控补偿是另一条没验证的路。

**状态**：**否**。限定：path 变体与 α 0.25 是事后选的；navhard 比了 6 个臂，没有校正；N4 沿用原生的 α。
**会推翻本条的证据**：带 comfort 约束、或按不看参考的偏离信号门控的补偿，在 navhard 上 CI 下界 > 0 且 navtest 不掉。
