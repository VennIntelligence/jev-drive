# 130. action 曲率「约 0.45」不是解码或控制器问题，是我们微调目标选错：解码与 modeld 逐项一致，车侧控制器增益为 1；真实存在的只有慢速急弯约 0.65 与相机高度造成的速度低估。rc-* 系列的 action 目标被缩到约一半（**结论**；慢速急弯一格待定）
2026-10-06。用户怀疑「控制器有问题」；第 120、128、129 条与 DAgger pilot 都看到 action 约为实际曲率的 0.45。结果 [experiments/op_closed_loop/results/action_scale.md](../../experiments/op_closed_loop/results/action_scale.md)，图 `figs/action_scale.png`。由另一位执行者完成；本条由 main 按其报告写，没有复算。

1. **源码**（openpilot ec95db3f / opendbc 35f7e081）：modeld `desired_curvature = action[0,0] / max(1, v)²`，无 MDN、无缩放、无平滑，v ≤ 0.3 时保持；action_t 0.275 s。controlsd 只做 clip；torque / angle / curvature 三种横向控制器都把在线标定的实际曲率跟到期望值，有效增益 1。我们的 `decode()` 读的是同一切片 [2062, 2066) 的同两个值，单位、时间、符号一致；`lib/op_ctrl.py` 的建模正确。
2. **原生 comma 相机（comma1M，32 窗 6 348 帧）**：解码曲率对 t + 0.25–0.45 s 实际曲率的校准增益，v > 8 m/s 一般弯 1.04 [0.95, 1.09]、急弯 0.97（r 0.97–0.99）；**3–8 m/s 急弯（人开的路口转弯，7 窗）0.65 [0.59, 0.87]**，同格 plan 推出的曲率 0.98。
3. **0.45 从哪来**：1 s pure pursuit 当目标（WOD 0.46 → 瞬时曲率 0.71）、回归方向（预测量带噪偏小），以及开环榜相机高度让模型低估自身速度（WOD 0.92、navtrain 0.81；用模型自估速度解码后校准增益 0.96 / 1.10）。B2D 上：模型自估速度 / 真实速度 1.433 m 相机 0.95–0.97，对齐相机（1.86 m）0.87，即曲率乘 0.76。

**对方向的含义**：闭环路口结果（118、121、122、127–129）执行的就是 openpilot 在车上会执行的曲率，解码与控制器不改。要改的是 `rft.py`：`ACT_ALPHA = 0.45 × 1 s pure pursuit` 让微调只拿到所需曲率的约一半，等于把「路口转少」当成了目标；第 128、129 条的 rc-* 臂都带着这个错。一致的目标是 action[0] = κ_inst(t + 0.275 s) · max(1, v_model)²，增益 1。真正的能力缺口缩小为两项：慢速急弯 action 约 0.65（plan 不欠转），以及对齐相机下的速度低估（视角问题，按用户原则由微调吸收）。

**状态**：**结论**（(a) 解码错、(c) 车侧增益都否，(b) 目标选错是）；慢速急弯 0.65 **待定**（n = 7 窗；没有带 action 的真车 rlog，车侧增益 1 来自源码）。
