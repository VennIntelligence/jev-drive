# 112. navhard 可行驶区（DAC）失败归因：约一半在评分器一侧（评分多边形比真实铺装窄 26–29%，跟踪器滞后 21%），约五分之一是 stage 2 挪偏起点、多数无可行解；真正的计划错误约三成、上限约 4.7 分；「该转没转」与「转过头」都很小（**待定**，原生 Cinque 与 it_dw3 + 选择器，navhard 5 912 个 token，CPU 回放，离线）
2026-10-04。预登记 [experiments/leaderboard_audit/plans/2026-10-04-navhard-dac-prereg.md](../../experiments/leaderboard_audit/plans/2026-10-04-navhard-dac-prereg.md)（含补充 1），结果 [navhard_dac.md](../../experiments/leaderboard_audit/results/navhard_dac.md)，审阅图 `figs/navhard_dac_review.jpg`。由另一位执行者完成；本条由 main 按其报告写，没有复算。

1. **口径**：DAC 失败原生 1 314、最好 1 249 个，96% 在 stage 2。每类都用评分器自己的 LQR 回放与多边形检查，上限用 devkit 两阶段聚合重算（复现 33.33 / 35.76 与第 103 条的 15.10 / 13.00），CI 按 225 个映射组 bootstrap。主类互斥，按预登记顺序取第一个命中。
2. **评分器一侧**：越出部分全落在 nuPlan generic drivable area 上的（M）占 26.3% [21.0, 31.6]，DAC 设 1 上限 5.15 [3.56, 6.90]（最好 5.22），是唯一过「主要原因」线的一类，多为 < 0.3 m 的浅越界，两臂之间来回翻（修好 73、新增 79）。计划在区内、LQR 回放越界的（L）占 20.6%，上限 2.8 / 2.3。两者合计 46.9% [42.2, 51.4]。
3. **起点一侧**：stage 2 起点被挪偏、1.5 s 内越界（E）占 19.6–20.8%，上限约 2.2；其中 56% / 66% 从同一起点没有任何等曲率弧能留在区内，任何减速都救不回（0 / 258）。
4. **计划一侧**：方向反 W 10.9% → 7.0%（选择器拿走 1.0 → 0.3 分），欠转 U 2.7–3.9%，过转 O 3.3–4.0%（U / (U + O) 0.40 / 0.54，混合），其余 R 14–15% 多为弯道内侧切角（画像）。合计上限 4.9 / 4.7 [3.1, 6.3]；指令可修的重叠部分 3.0。第 110 条的早转集合在失败中占 52–56%（全体 39%），失败的计划比通过的转得多、走得远（朝向比 0.77 对 0.36）。同一路径放慢 15% 只救回 6–8%，速度不是主因。
5. **合成历史**：原生失败里 32% 去掉历史转动后能过，最好 driver 降到 13%。

**对方向的含义**：第 103 条「可行驶区 13 分」大半不是更好的计划能拿回的：M 是地图（与第 104 条第 6 点一致），E 多数无解，L 的全量补偿在第 97 条里掉分。能投入的是计划一侧约 4.7 分（方向反、欠转、过转、切角）和一个只在「计划在区内、回放越界」时门控的跟踪器补偿（上限约 2.3，未验证）。不该再把 navhard DAC 当作 openpilot 路沿或转向能力的读数。

**状态**：**待定**。限定：M 以 nuPlan generic drivable area 代表真实铺装，未目测核对；「无可行弧」只试等曲率、两种速度、不含刹车，高估不可行；PDM 参考在 36–39% 的这些 token 上自己也越界，换参考的上限偏低；单次运行。
**会推翻或推进本条的证据**：M 类目测核对；门控跟踪器补偿在 navhard / navtest 上的官方分；含刹车与组合曲率的可行性检查。
