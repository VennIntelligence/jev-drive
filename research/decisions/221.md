臂（P2H10 配方其余不变）：NA（adapter 内把喂入的 ax 置零，训练与 serving 同）、NAH（再把 3 个历史位姿按当前速度沿原路径重排）、LD（NAH + 底模 lead 输出作一个 adapter memory token，带自己的 head 预训练）、LG（LD + 底模报告有 lead 且 v0 ≥ 0.5 的行，模仿目标换成「日志路径在底模 plan 弧长处的点」，占模仿行 42%）、PO（LD + 所有 v0 ≥ 0.5 的行都换，91%）。闸门：改后的 trainer 关掉全部新选项与原版 20 步逐位相同；probe 文件的 plan 与 bench 的 navtest plan 相同。

**对方向的含义**（能力边界）：(1) 在冻结 encoder + 模仿日志的配方里，「保住 nuPlan 榜增益」与「继承底模的起刹」是同一条轴的两端（B0 → NA / NAH / LD → LG → PO：起刹 0.78 → 0.84 → 1.01，navtest 0 → −0.5 → −1.9 → −3.1）；nuPlan 榜给分的就是日志司机的时机。训练侧把它拿掉与 FIX1 在 serving 侧加 lead 限速在 AlpaSim nuPlan 上是同一个结果：at-fault 碰撞略少，进度付出更多。比赛线保持 P2H10-F / APY10m10-AB，不换成本线任何臂。(2) 去掉某个 ego 输入不等于去掉 ego 状态的行为：画面里带着 ego 运动，plan 通路会从那里读回来；闭环的纵向续接要像 yaw-rate rows 那样用「帧与目标解耦」的行来处理，而不是删输入。(3) lead 输出只有作为目标的选择条件时才起作用，作为输入不被使用。(4) 论文：没有可以写成方法的正结果；可写的是这条权衡曲线，以及「重训后 ax 输入只值 0.5」对第 218 条第 6 点「加速度输入另值 3.3」的限定（3.3 是不重训的 serving 上界）。
**状态**：**成立为负**（中）。限定：阶段 0 是 pilot 规模 1 seed，NA / NAH / LD 三者互相不可分（NAH 过 navtest 线只差 0.01）；斜率闸门对所有臂按构造通过，观测斜率是相关读数，「续接搬到画面通路」是由它与 NC / TTC 基本不变推出的，没有对帧做干预；PO 没跑全量和 AlpaSim（低于例外的下限），它是 WOD 上最接近 shipped 的臂；LG / PO 的 navtest 代价大头是 EC，按 p = 0.5 逐行硬切换目标，平滑混合没试；AlpaSim 为本地渲染、27 个 log、1 491 个 scene 都已参与过选配方；box 在 memory.high 处多次 SIGKILL 本 lane 的 job（训练重启两次，结果不受影响）。
**会推翻或推进本条的证据**：把 slot 帧按另一条速度曲线重新合成的「加速度行」（纵向版 yaw-rate rows）上，NA 类臂的观测斜率与 AlpaSim at-fault 碰撞；PO / LG 在 PAI 上的闭环读数（那里没有 nuPlan 日志时机的进度奖励）；目标按 lead 概率平滑混合后 EC 代价是否消失而起刹保持；一个带新信息的前视支路（第 204 条）替代 lead 输出作条件。
