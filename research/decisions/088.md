# 88. navhard stage 2 越界诊断：方向反了的一类（5.7%）由合成历史帧里的自车转动带出来，不是执行器、坐标约定或相机输入；越界的主因是模型自己的路沿输出比地图边界宽 1–2 m；轨迹系统性转得不够，但横向增益校准反而掉分（**待定**，navhard 5 912 个 token + navtest 12 146，只有 Cinque 原生与 N4，离线）
2026-10-03。定义在 [experiments/skill_pack/plans/2026-10-03-navhard-offroad-diagnosis-plan.md](../../experiments/skill_pack/plans/2026-10-03-navhard-offroad-diagnosis-plan.md)，表与图在 [experiments/skill_pack/results/navhard-offroad/report.md](../../experiments/skill_pack/results/navhard-offroad/report.md)。由另一位执行者完成；本条与 report.md 由 main 按其最终报告写，没有复算。执行者的评分回放复现了官方两阶段分（原生 33.33、N4 36.07）。

1. **输出模式**：Cinque 出一条计划（单高斯，33 个时间点，0–10 s，近密远疏）。我们只取 x、y、yaw，转到后轴，插值成 NAVSIM 的 8 个位姿；曲率（action）头没有用。评分器用 LQR + 自行车模型跟踪 4 s，不重规划。**原生模型在全部 token 上 desire 关闭，路线指令没有进模型**；N4 只在选轨特征里看到指令。
2. **方向反了是一类，原因是历史帧的自车运动**：原生在 stage 2 有 5.7%（312 / 5 462）的 token 终点落在参考的另一侧（stage 1 是 1.3%），N4 6.6%。这 312 个里 96% 的计划方向与历史帧的偏航方向一致。把历史帧的转动去掉，仍然反向的只剩 15%，DAC 通过率 46.8% → 71.8%；补上与指令一致的 desire 脉冲无效（75–84% 仍反向）。右转已经在原始计划里，不是跟踪器带出来的；符号与坐标约定逐项核对无误。stage 2 的合成历史以一个被挪偏的位姿结尾、带着错误的转动，模型照着它继续转（这句是推断）。
3. **不是相机输入**：两路输入都只来自 CAM_F0，没有侧向相机；虚拟相机偏航改 ±2° 不消除转向；把广角输入置空几乎无影响（91% 仍反向）。把输入裁到中央 25% 时反向降到 25%，说明画面两侧的内容有贡献，但小于历史运动。
4. **越界的构成**：stage 2 的 DAC 失败原生 1 266 个（23.2%）、N4 1 308 个。首次越界时越出的中位只有 4.7 cm，一半在 1.5 s 内发生。「方向对但修得晚」只占约 5%（66 / 57 个）；多数失败的计划是在远离参考。特权反事实（横向动作提前、向参考侧放大、第一秒换成参考）对全部 token 施加时得失相抵，即使只施加在失败 token 上也留下一半以上。
5. **路沿**：59%（原生）/ 74%（N4）的失败里，模型自己的路沿输出在越界处比地图边界宽 1 m 以上（中位 +1.5 / +2.0 m），计划待在它自己的路沿之内；路沿对而计划穿过去的只有 7.3% / 3.8%。是模型看到了地图多边形之外的真实路肩，还是合成视图上路沿头出错，没有分开。
6. **幅度**：正常场景上计划系统性转得不够，对人类轨迹的横向斜率 1 / 2 / 3 / 4 s 为 0.87 / 0.77 / 0.75 / 0.74，转过头（> 1.5 倍）只占 3%。但在 navtrain 上拟合横向增益（1.143）后，navtest PDMS −3.38 [−3.74, −3.02]，navhard −1.71 [−3.79, +0.28]：转得不够是向均值回归，不是比例误差，放大轨迹没有用。只用近端曲率外推比整条计划更差。
7. **其余丢分**（N4，各项若为满分可得的两阶段分）：DAC 12.5，扩展舒适度 EC 7.6，进度 EP 5.9，方向 DDC 4.7，NC 3.5，LK 2.9，红绿灯 TLC 0.7，TTC 0.7。起步慢约 0.6。红绿灯和起步在这个榜上不值钱。

**对方向的含义**：navhard 上最便宜的一步是处理历史帧的自车运动（只对输入做处理，不改模型），它针对的是 5.7% 的 token 和其中约四分之一的通过率差。横向增益校准不做。路沿这一项要先分清是地图窄还是模型宽。

**状态**：**待定**。限定：类别规则里 `early_clip` 与 `junction` 较粗；相机变体在 312 个里只跑了 100 个；反事实用的是未挪偏位姿的 PDM 参考；「模型跟着历史转动」「训练导致的滞后」是推断；去掉历史转动是对输入的干预，没有做成一条不看参考的规则再用官方评分器全量打分。
**会推翻或推进本条的证据**：一条不看参考、只处理历史帧运动的输入规则在 navhard 全量上的官方分数；路沿输出对真实路肩（而非地图多边形）的核对；把指令真正喂进模型（适配后的 desire）之后反向率的变化。
