# 63. Cosmos 没有「恢复」CARLA 行人的可读性：Cosmos 全量 75 对上 CARLA 行人本来就读得出来（池化 stage 3 AUC 0.815），Cosmos 格 0.746 略低；可读性由行人大小决定，< 500 px 的两格都是 0.57（**待定**，75 对 / 75 个 instance，1 seed，线性池化 + 空间 probe）

2026-09-29。登记（数据名单、四格管线、probe、判据）写于任何数字之前，[fc65452:todos/2026-09-29-e1-cosmos-probe.md](https://github.com/VennIntelligence/jev-drive/blob/fc65452/todos/2026-09-29-e1-cosmos-probe.md)；小表 [results/e1-cosmos/](../../experiments/feature_adapter/results/e1-cosmos)；设计与结果见 [feature_adapter README](../../experiments/feature_adapter/README.md) E1。
问题：E0（第 62 条）说 CARLA 行人在池化特征上读不出；同一批 x⁺ / x⁻ 渲染成 Cosmos 后，openpilot 每层的可读性恢复多少（2 × 2），以及池化是否把小行人藏掉了（空间 probe）。做法：G4 全量起跑时刻已完成的 75 对，四格同一条单相机管线，格内 5 折按 instance 训练 / 测试的线性池化 probe；GT 框内 cell 池化（S1）与 stage 3 图上的 1 × 1 conv + max 头（S2）。约 0.5 GPU·h。

**结论**：
1. **按登记判格：K-restore 不成立、K-none 不成立、G-a 落灰区**（Cosmos stage 3 ≥ 0.65，但对 CARLA 格 Δ 为负）；画风份额的分母近 0，无意义。Cosmos 像素级重画没有带回任何 CARLA 格没有的可读性。
2. **CARLA 行人不是一般性地读不出来**：这批的 CARLA 格池化 stage 3 = 0.815，框内 cell 池化 0.95。第 62 条的 G-none / 「adapter 判不可行」收窄到 P5 评测那一批。
3. **行人大小是主导变量**：x⁺ mask 像素数 < 500 的读数 slot，stage 3 两格都是 0.57（Cosmos 0.577 对 CARLA 0.569，重画外观没有帮助），500–1 500 为 0.63 / 0.60，≥ 1 500 为 0.92 / 0.83。P5 的 x⁺ / x⁻ 行上按同样方式直接训练只有 0.54–0.60（conv 头 0.61），所以 E0 与 E1 的差不是 probe 训练方式造成的；P5 行人的像素数没有量，「P5 多为小 / 远行人」是推测。
4. E2（CARLA → Cosmos 的特征 adapter）的动机变弱：Cosmos 格读数不高于 CARLA 格，配对监督没有「更可读」的方向可学；下一个问题是小行人（分辨率 / 距离），不是画风。
5. 空间读法：S-local-big（P5 上 conv 头 ≥ 0.65）不成立（0.521，池化 0.523）；nuScenes 上 conv 头 0.868 对池化 0.831，Δ CI 含 0（[−0.011, +0.092]）。

**状态**：**待定**。限定：(1) 75 对、65% 是 DynamicObjectCrossing、probe 训练行 1 886，CI 宽；(2) 行人大小分档与 P5 配对训练桥是看到第一批数字后加的描述性读数，分档边界取整数没有调；(3) 框内 cell 高分有平凡成分，只说明信息在特征图的那个位置；(4) Cosmos 格低于 CARLA 格的原因（混合区重画损失 vs Cosmos 行人更难读）没有拆；(5) 「小行人不可读是分辨率问题」是推测，没有做输入放大的对照；P5 行人大小分布没量。
**会推翻或推进本条的证据**：量出 P5 评测行人的像素数分布，若中位数与 Cosmos 全量这批相当（≥ 1 500 px）而 P5 仍读不出，则本条的「大小」解释被推翻，回到 P5 场景 / 相机拼接差异；G4 全量完成后（≥ 300 对）重跑，若 Cosmos 格与 CARLA 格的差变为不显著，则「Cosmos 略低」撤回；对 < 500 px 的行人把输入放大后可读性升到 ≥ 0.65，则确认是分辨率限制，反之则是别的原因。
