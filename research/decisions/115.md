# 115. 真车起步为什么不打转：comma1M 的 122 个真实起步上，c 不小、历史不同、画面增益低这三条都不成立；可测的差别是真车约 1.8 s 就离开 0–3 m/s 敏感窗口，HUGSIM 要 6 s 以上；「低速横向没接管」最可能但本地测不了（**待定**，离线，Cinque TRT 回放，无 engagement / CAN）
2026-10-05 凌晨。接第 111、113、114 条。报告 [experiments/hugsim/results/real_car_launch.md](../../experiments/hugsim/results/real_car_launch.md)。由另一位执行者完成；本条由 main 按其报告写，没有复算。

1. **数据**：本地没有带模型输出、CAN 或 engagement 的 openpilot rlog；只有 comma1M（视频 + localizer 位姿）。前 600 个 id 里找到 122 个起步（静止 ≥ 1.8 s 后 v 到 1 m/s，119 个 segment），Cinque TRT 20 Hz 回放，真实历史与 HUGSIM 式静止预热两种条件。
2. **c 不小**：每 0.25 s 步、每度计划方向的实际朝向变化，v < 1 / 1–2 / 2–3 m/s 为 0.050 [0.035, 0.067] / 0.125 [0.106, 0.146] / 0.181 [0.160, 0.201]，HUGSIM 0.066 / 0.146 / 0.307，临界 0.018–0.034。限定：这是真车加驾驶员的响应，车道几何同时推动计划与朝向，会抬高 c。
3. **起步偏向与历史**：步 1–2 |phi1| 中位 0.39° [0.30, 0.50]（HUGSIM 不打转 0.43、打转 0.76、WOD 0.58），≥ 1° 占 22%。起步前 2 s 偏航率 std 0.02°/s；真实历史换成静止帧，偏向配对差 −0.009° [−0.046, +0.018]，历史不是差别。
4. **画面增益同样存在**：计划方向对实际朝向变化的回归斜率，步 1–4 为 6.1 [4.3, 8.1]，步 5–12 为 1.2 [1.0, 1.4]，与 WOD 的 9.3 / 5.2 / 2.3 同量级。
5. **离开敏感窗口的速度不同**：真车起步后 +1 / +2 / +3 s 为 1.5 / 3.4 / 5.1 m/s，约 1.8 s 离开 0–3 m/s；HUGSIM 基线 2–3 s 才到 2.1–2.6 m/s，前 10 s 里低于 3 m/s 的时间中位 6.4 s。真车 +2 s 朝向变化中位 0.26°；HUGSIM 打转 run 步 4 到步 8 从 0.4° 到 9.8°。

**对方向的含义**：第 113 条「真车 c 小」的读法第二次被否。剩下两个解释：(i) 低速横向没接管（凭记忆的 openpilot 行为：横向有最低速度门限、各车型 minSteerSpeed 不同；未验证，需要带 latActive 的 rlog，或用户的实车经验）；(ii) 真车在高增益窗口里只待约 1.8 s，增益来不及把种子放大，而 HUGSIM 的起步慢 3 倍以上。(ii) 可在仿真里直接检验：第 90 条第 4 点的特权起步辅助（前 5 s 带到 5 m/s）6 个打转场景消掉 5 个，与此一致。一个非特权的版本是让起步纵向更快通过 0–3 m/s（不改横向，对 navhard 开环无影响）。

**状态**：**待定**。限定：无 engagement；c 含驾驶员和车道几何；n = 122，车型与驾驶员不详；HUGSIM 速度剖面重算时打转子集只匹配 3/10。
**会推翻或推进本条的证据**：带 `carControl.latActive` 的 rlog 上起步时的接管率；HUGSIM 上只加快起步纵向（非特权）的打转数与 HD。

**更新（2026-10-05，第 117 条）**：解释 (ii) 在 HUGSIM 闭环里检验不成立：起步纵向加快到真车剖面后打转 11（基线 10）。剩下解释 (i)。

**用户实车经验（2026-10-05）**：实车低速起步时横向是接管的（场景都很简单），没有复现过打转。所以解释 (i)「低速横向没接管」至少在用户的使用里不成立。与第 100 条第 2 点合读（零偏航附近每步增长只有 0.55–0.86，不放大；大信号才放大）的推断：简单真实场景里起步偏向小（comma1M 中位 0.39°，尾部轻），种子落在不放大的小信号区；HUGSIM 打转场景的偏向大（画面内容给出），越过阈值后进入放大区。未检验。
