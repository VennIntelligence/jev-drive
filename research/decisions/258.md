**与 DA-WAM 的 v1 / v2 翻转（2026-10-11 补记）。** DA-WAM（arXiv 2608.19085，32 candidates + learned scorer）v1 PDMS 93.7、v2 EPDMS 87.7；我们 `SH30-F-s0` v1 89.27、v2 89.47。
其 v2 子分（论文表）：NC 98.4、DAC 98.4、DDC 99.1、TL 99.9、EP 88.6、TTC 97.9、LK 97.6、HC 97.8、**EC 79.6**。
对 `SH30-F-s0`（98.6 / 97.0 / 99.5 / 99.8 / 87.2 / 98.0 / 97.4 / 98.4 / **88.7**）：它在 DAC（+1.4）与 EP（+1.4）领先，这两项正是逐帧候选选择器直接优化的、也是 v1 权重最大的；
它在 EC 落后 9.1 pp（逐帧换候选打断相邻帧 plan 的一致性），按 2/16 权重折合约 1.1 EPDMS，超过其 DAC + EP 领先的折合值（约 1.3 + 0.45，不计门控交互）。
其余子分差距都在 0.6 pp 以内。均值级算术得我们 +0.7，实际 +1.8，余下在逐 token 失败的共现里，没有它的逐 token 文件分不开。
结论：v1 付钱给进度、不罚 plan 抖动，v2 罚抖动；我们的 EC 不是调出来的，是逐帧跑同一个 policy 自带的。

DA-WAM 的 v1 子分（论文表）：NC 99.1、DAC 98.9、TTC 96.8、Comfort 99.8、EP 90.0、PDMS 93.7；对 `SH30-F-s0` v1（98.6 / 97.0 / 95.5 / 100.0 / 83.1 / 89.3）：差距几乎全在 EP（−6.9 pp，按 5/12 约 2.9 分）与 DAC（−1.9 pp，门控约 1.7 分），Comfort 相同。
**其 v1 / v2 两行不是同一份预测**：v2 的 human-penalty filter 只会抬高 NC / DAC / EP / TTC（我们的 NC、DAC 在两个 devkit 下逐位相同，EP / TTC / DDC 上升），
而 DA-WAM 的 NC 99.1 → 98.4、DAC 98.9 → 98.4、EP 90.0 → 88.6 都在下降，同一份预测做不到；其 v2 行来自别的模型 / 训练设置 / 评测配置，论文没说明。
写论文表时要注明：我们的 v1 / v2 是同一个 pose 文件过两个 devkit，别人的未必；可比的是子分（v2 EC 79.6 对 88.7，v1 EP 90.0 对 83.1），不是总分的降幅。
