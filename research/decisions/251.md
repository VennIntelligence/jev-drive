1. **按 flip 读**：|ΔHD| > 0.05 的 fixed 3 / broken 17，结局相同 51 / 64。broken 的 17 个里 8 个在参照里 complete：3 个变成 fg 碰撞（如 `scene-090-hard-01` 0.996 → 0.031），5 个仍 complete 但分低。
2. **起步如第 250 条所预测**：到 2 m/s −0.62 s；v < 2 m/s 的 plan arc ×1.46（离线 +44%）；step 0 的 arc ×4.20 [4.01, 4.45]（离线 4.2×）。launch stall 没有变（1 对 1）。warm、v > 3 m/s 时 plan 相对速度不变长（1.014 [0.994, 1.036]），离线的 +9–12% 在闭环里不出现。
3. **代价在碰撞**：车整体更快（mean v 4.82 对 3.64 m/s），episode 短 30%，fg 碰撞 27 → 33，complete 21 → 19。按预登记属于「起步更快但 HD 不更好」，NC / TTC / PDMS 的 CI 不含 0，指向净损失。
4. **参照的 spread**：三个参照 HD 0.3870 / 0.3882 / 0.3880，两两差 ≤ 0.001，各类计数相同，repeat 之间 broken 最多 1 个。这只是执行噪声（这条路径没有随机种子），不含 checkpoint seed 的 spread。
5. **Off-path identity 的登记判据字面上没过**：opt 关的 `r3` 对 `rr1`，step-0 plan 64 / 64 相同，全程 plan 相同只有 33 / 64，而 `rr1` 对 `rr2` 是 54 / 64（判据写的是不大于后者的分歧）。改动之前今天的 run 对 `rr1` 在同 16 个 scenario 上是 5 / 16，`r3` 是 7 / 16，分歧都从 episode 中段 6–10 mm 开始；「来自日期 / 负载（TensorRT session 共卡），不是这次改动」是推断。HD 与各类计数上 `r3` 与 `rr1` / `rr2` 无差。
6. **Latency**：agent 每 decision median / p99 152 / 397 ms 对 62 / 202 ms，多约 90 ms（lattice CPU 54 ms），在 HUGSIM loop 的容忍范围内。
7. **限制**：option 一次改了帧来源、slot 数、时钟、desire pulse、static warm-up → 未训练过的 back-warp cold start、lateral delay 0.25 → 0.2 s、traffic flag，没有逐项归因；一个 checkpoint seed、一次 run。pilot 的 8 个 scenario 上 stateless 更好（0.718 对 0.632），全量不是。

**状态**：「帧 / 时钟 mismatch 是 HUGSIM 差距的原因」**降级**（中偏弱）；不上线。
**会推翻或推进本条的证据**：seed 1；保留 static warm-up 的臂，或按 cold-start 规则训练过的 checkpoint；把时钟与 cold start 拆开。
