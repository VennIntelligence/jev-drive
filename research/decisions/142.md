1. **设置**：视觉冻结，新输入经零初始化 token 进 temporal policy，初始输出与 shipped 逐位相同（验过）；navtrain 4 874 token、600 步；P1 = 同配方新输入置零，P2 = + ego（vx, vy, ax, ay）、4 个位姿历史、指令，P3 = P2 + 侧 / 后相机。navtest 全量 12 146 token，评分与复现 WA-JEPA 91.71 的同一 devkit。
2. **小样本**（GIMM）：P2 86.57，P2 − P1 +4.84 [+4.11, +5.55]，距 WA-JEPA −5.14；ADE 2.12 → 0.85 m、速度比 0.83 → 1.006（不是速度假象）；P3 86.10，侧 / 后相机测试时遮掉只差 +0.06（无用，同第 136 条）。
3. **A 阶段**（不训练，1 499 个有真实 10 Hz 帧的 token）：GIMM 对真实帧 −0.38 [−1.73, +0.96]；帧对间隔是主因：冻结 encoder 按 0.2 s 读速度，原生 0.5 s 帧对让计划快 1.93 倍（−30.7）；队列格数 8 → 4 不掉分，格距 0.2 → 0.5 s 约 −4.4。
4. **B 阶段**（协议 {G, W, N} × {P1, P2} × 2 seed，各在自己协议上测）：P2 G 86.63 / W 85.73 / N 82.63；交互 (P2 − P1)_N − (P2 − P1)_G −2.08 [−2.63, −1.52]：显式速度不能替代帧对运动线索。G − W（P2）+0.90 [+0.47, +1.31]，按预登记规则全量用 W（速度比差 < 0.5%，EP / DAC 同向小降）。改用真实帧测，P2 各协议只差 −0.47 到 +0.78：有了 ego 输入，历史帧怎么来的几乎不重要。seed 差 ≤ 0.17（P2）。
5. **HUGSIM `spec`**（10 个打转场景 + 第 118 条另外 19 个卡死场景，P0 复现第 118 条）：HD P0 0.306 / P1 0.349 / P2 0.453；卡死 24 / 17 / **0**，起步停滞 7 / 6 / 0，打转 0 / 1 / 2（P2 两次 61°、63°，线 60°），**前景碰撞 1 / 3 / 10**。P2 − P1 +0.104 [−0.042, +0.248]。场景是按 shipped 失败挑的，有回归均值。旧 iLQR 口径（`exam` + `fixed`）下 P2 打转 7 / 10 不变（小样本）。

**对方向的含义**：输入对齐把 NAVSIM 上与 WA-JEPA 的差距从 10.6 缩到约 5，余下约 5 分是预训练与规模之差（trick or trade 的主比较，待全量）。启停：显式 ego 输入在真实控制链下把卡死与起步停滞清零，但车开始撞上 P0 会停下来的目标，与第 140 条同一现象：shipped 的「停」有一部分是对的；P2 修好了起步，代价是丢了这部分谨慎。下一步要看全量训练后这个代价是否缩小，以及碰撞是否集中在 P0 本就停着的那些场景。
