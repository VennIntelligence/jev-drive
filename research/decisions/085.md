# 85. Qwen3-VL-4B 读红绿灯的延迟：0.8–1.1 s 里大部分是低效，一次前向 + 降分辨率到 68–125 ms 而读数基本不变；截断语言模型只再省 2 成，薄 head 没有超过 zero-shot（**待定**，离线，21 条路线 3281 帧，测试 8 条路线）

接第 84 条：Qwen3-VL-4B 读得准但每次 0.8–1.1 s，登记的延迟线是 p95 ≤ 600 ms。问题：只跑视觉塔加语言模型前 N 层、在第 N 层的 hidden state 上接薄 head，能不能把延迟压下来。按路线切分：训练 9 条 / 验证 4 条 / 测试 8 条（1107 / 722 / 1452 帧）。

batch 1、空卡、JPEG 进到答案出；准确率在第 84 条的 233 帧子集上。

1. **主要的杠杆是去掉文本生成和降分辨率，不是截断**：564 ms 里视觉塔 235 ms、36 层语言模型 328 ms、预处理 2.6 ms。降到 559 token 时红灯读数不变，绿灯答对从 63/68 掉到 57/68。
2. **答案在第 24 层左右才可读**：N < 20 时线性 head 在所有分辨率下都不行；N = 24–32 在 7 折按路线分组的交叉验证里与 zero-shot 持平，比 N = 36 省 19–22% 延迟（559 token 下 53 对 68 ms）。只用视觉塔的特征读不出灯，所以视觉塔是延迟下限（20–238 ms，随分辨率）。
3. **在 CARLA 帧上拟合的 head 没有在任何一格超过 zero-shot 的一次前向读数**；原分辨率下 N = 24–32 的 head 在测试路线上绿灯答对只有 49–61%（zero-shot 100%）。训练集很薄（147 个红灯帧里 119 个来自一条路线）。head 是域内有监督的，zero-shot 行不是。
4. **测试 8 条路线上的 Phase A**：zero-shot `generate` 的 ego 红灯召回 95.6% [88.3, 100]、别的方向红灯误报 6.4%、无灯答成红 0%，Q-light 三条线都过，延迟线不过（p95 885 ms）；559 token + head 的快速版 96.1% / 9.7% / 0%，延迟 p95 69 ms 过线。stop sign 76.2% 过线但只有 1 条路线 42 帧。静止障碍不过：锥桶 99.5%，停着的车 0.0%。
5. 快速通路只覆盖红绿灯一题；stop sign、障碍、绕行侧仍走联合提示词，p95 1607 ms。

**对方向的含义**：红绿灯这一题用 zero-shot Qwen3-VL-4B、一次前向、1153 或 559 token，不训练、不截断，就同时过了读数线和延迟线，可以接进 `vred`。「停着的车」是模型读不出来的，不是延迟问题。

**状态**：**待定**。限定：只有带帧的 3281 次请求（约 3.8 万次旧请求没有存帧，不在内）；测试 8 条路线里 5 条有红灯、3 条有绿灯、1 条有 stop sign，区间很宽；闭环行为没有测；延迟 bench 时三张卡同时在跑，单独复测 5 格相差 1% 以内；head 的正则网格多格取到边界。
**会推翻或推进本条的证据**：更多带帧路线（尤其是绿灯与 stop sign）上 559 / 1153 token 的 zero-shot 读数仍过 Q-light 线；接进 `vred` 的闭环里闯红灯下降且没有新增卡死；真实图像上同一做法的读数（本条全部是 CARLA 帧）。
