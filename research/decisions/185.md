1. **接入**：`experiments/alpasim/lib/sh30_core.py` 复用 NAVSIM serving path（W 协议 CPU warp、冻结 encoder、`PModel`），`sh30_driver.py` 提供 gRPC 服务；AlpaSim 源码未改。离线一致性（300 个 navtest token，喂真实 JPEG 与 index ego state）：vision token 相对误差 0.08%，ego feature 完全一致，导出 pose 与 bench 预测最大差 0.045 m。
2. **48 scene**（part001，8 并发，seed 0，默认 controller gains）：SH30 0.9465，满分 35，零分 2（`collision_at_fault`，都在减速到 3 m/s 以下时），另 11 个 progress 0.65–0.79（偏慢）；LTF 0.8735，满分 34，零分 5（1 `offroad`，4 `left_corridor_laterally`），这 5 个 scene 上 SH30 为 0.94–1.0。480 次 `drive`，`inference_error` 0，无 fallback。
3. **冷启动**（每 scene 前 3 次决策缺历史）：离线上只有 1 个 keyframe 时，`backwarp`（恒定速度与 yaw rate 倒推 pose，首帧沿倒推轨迹做路面 warp）与全历史 plan 的 8 点平均距离 0.89 m，置零 slot 5.39 m（4 s 处多走约 7 m）；2 / 3 个 keyframe 时 0.38 / 0.15 对 0.58 / 0.22。3 个 scene 闭环两条规则都 3 / 3，对 GT 横向距离 0.47 m 对 2.07 m。默认 `backwarp`；第 0 次决策的 plan 仍偏短（离线 4 s 处 −1.4 m）。
4. **command**：由 route waypoint 按官方 sample 的规则推出，在第 3 次决策上与 NAVSIM `driving_command` 40 / 48 一致，8 个不一致中 6 个是 route 判左、NAVSIM 判直行。
5. **时延**（与下载并行，有噪声）：`drive` 内中位 105 ms（CPU warp 60、encode 20、policy 17），p95 166 ms；runtime 侧 RPC 均值 147 ms（LTF 41 ms）。driver 显存峰值 3.5 GiB（限额 16）。超出部分是 CPU warp 与推理锁排队。
6. **未分解的偏差**：第 3 次决策上 online plan 与同 token 离线 plan 平均差 1.64 m（离线对 log 0.56，online 对 log 1.82），是 MTGS 渲染（无畸变 pinhole）、command 来源、`vy` 报 0、相机 x 差 0.116 m 与闭环状态漂移的合计。

**对方向的含义**：SH30 进这个闭环不需要重训，NAVSIM 上的 plan 交给 MPC 跟踪可用（第 133 条的低速打转在这 48 个 scene 上没有以越界形式出现）。提交前剩下的是工程项：时延（warp 上 GPU 或跨 session batching）、一台有 Docker 的机器、read-only root 下的实测。
