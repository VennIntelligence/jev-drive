**对方向的含义**：(1) 论文 driver 的 NC 修法：在冻结 Cinque token 与 SH30 隐状态上，「为了不撞该在哪里减速」在 5.7 万 token、约 1 000 个正例的标签规模下读不出来；这是继 plan 头上的 agent hinge（第 158 条）和真值占用走 memory 通道（第 197 / 200 条）之后第三个负结果，也是最干净的一个，因为这里的头不受模仿 loss 和通道的牵制。带信息的是显式的对象级测距：模型自己的 lead 输出 < 真值 t0 间距 < 对方的未来运动。所以纵向 NC 修法需要一个更好的近距对象信号作为输入或作为支路的监督目标，不是在现有特征上加选档头；「选档头」作为方法成分关闭。(2) 速度缩放族的分数增益大半不是 NC 而是 DAC 的视野效应；以后任何带速度候选的 selector（F19 的速度轴）要把 DAC 改变的 token 单列。(3) 比赛 driver：本线没有可上的东西；学出来的减速门拿 progress 换的是 AlpaSim 不这样计分的出界效应，也没有去掉它本来要去掉的 at-fault 碰撞。唯一可用的线索是 openpilot 原生 lead / meta 输出对同向前车类失败的召回，带 lead 的纵向项应从这些输出出发（第 157 条：固定余量规则已否），并且要在 AlpaSim 里读。
**状态**：**成立为负**（中）。限定：non-reactive、4 s、no-EC，逐帧独立选档；navtrain plan 来自一个 seed 的折模型；学习器是通用的（PCA-32 上的 boosted trees、第 191 条的小头），没有逐臂调参；约 1 000 个正例，曲线持平只排除「同样的标签再多一倍」，不排除大得多的标签量或在其上训练的表征；G0 的对象速度用了 0.5 s 的日志位移；第 2、3 点是读完阶段 1 之后加的事后读数；登记的阈值规则本身就会越过 EP 条件，按登记线判负的直接原因是 EP 而不是增益。
**会推翻或推进本条的证据**：一个从前视图监督出近距对象间距（或其未来占用）的支路，其输出在同一选档装置上对 `y_fail` 的 AUC 过 G0 的 0.76；同一装置在 reactive 或闭环（AlpaSim）标签上的读数；把 DAC 改变的 token 去掉后任一非特权臂在 EP ≤ 0.3 下仍有 CI 高于 0 的 NC + TTC 失败下降。
