# 220. AlpaSim 碰撞里「绕行 / 转弯不避让」是 plan 自己的净空估计失败，不是执行也不是弯道车速：66 个 at-fault 碰撞 rollout 全部在撞前 3 s 内已有 served plan 的 ego 扫掠足迹穿过被撞物体（首次中位提前 3.0 / 3.3 s），「plan 清空而执行没清空」一类为 0；nuPlan P2H10-F 22 次里直撞前车 4、绕行 / 转弯 6、漂移 10、其他 2，PAI 12 次里 6 / 5 / 1 / 0；横向加速度限速在 1.0–4.0 m/s² 任何档都避开 0 次；特权足迹刹停上限 20 / 22 与 8 / 12（干净 rollout 代价 1% / 0%）；底模丢弃的几何头在 nuPlan 上都读不出「扫掠会碰到」（lead 0.49、路沿 0.72、车道线 0.46），只有 plan 自身横向 std 过线（0.786 [0.738, 0.865]，换配方 0.70）；没有可转给 FIX1 的 serving 开关（**中**：已有 rollout 的离线读数 + 运动学反事实，预登记）
2026-10-10。lane SWV1，接第 219 条（COL1）、205、207、218；邻居第 157、158、179、203 条（区别写在预登记开头）。预登记及补记 1 [experiments/alpasim/plans/2026-10-10-swv1-prereg.md](../../experiments/alpasim/plans/2026-10-10-swv1-prereg.md)（任何读数之前 push），结果 [experiments/alpasim/results/swerve_clearance.md](../../experiments/alpasim/results/swerve_clearance.md)，表 `results/swerve/`，图 `figs/swerve/`，页面 [research/alpasim-collisions/](../alpasim-collisions/index.html) 第八节。执行者完成并写本条，main 没有复算。没有闭环仿真、没有训练、没有提交；simulator 的框、日志路径、物体的已记录运动只作标签与 oracle，用到它们的反事实都是上限。

1. **分类（描述性）。** 每次决策把 served 轨迹（4 s、0.1 s 一个位姿）上的 simulator ego 框与同一时刻的物体框求交。nuPlan P2H10-F s0 + s1（22）：(i) 直撞本车道前车 4（18%），(ii) 转弯 / 绕行且 plan 自己的扫掠已穿过被撞物体 6（27%：n05、n07、n11 三个转弯 scene 的 5 次 + n04 一次），(iii) plan 清空而执行没清空 0，(iv) 无机动意图的漂移 10（45%），(v) 其他 2。APY10m10-AB（24）：9 / 8 / 0 / 6 / 1。PAI 基线（12）：(i) 6（p01、p03、p05、p09、p10、p11），(ii) 5（p02、p04、p07、p08、p12），(iv) 1（p06）。PAI re-timed 臂 v1（8）：5 / 2 / 0 / 1。
2. **每一次碰撞都已经在 plan 里。** 撞前 3 s 内 plan 扫掠穿过被撞物体：22 / 22、24 / 24、12 / 12、8 / 8；首个相交 plan 的提前量中位 3.0 s（nuPlan，受 5 s scene 限制）、3.3 s（PAI）；让扫掠清空所需的最小整体横移中位 0.85 m（nuPlan P2H10，转弯 scene 1.0–2.6 m）、1.6 m（PAI）。MPC 照 plan 执行：横向跟踪误差 p95 逐 rollout 中位 0.02–0.04 m（最大 0.17 m），实际 / 要求 yaw rate 1.0–1.08（PAI 3 个 rollout 例外）。
3. **不是弯道车速。** 碰撞 rollout 里 plan 的 v²κ 最大 2.8（nuPlan）/ 3.0–3.3 m/s²（PAI），逐 rollout 最大值的中位 0.4 / 1.4 m/s²。按横向加速度上限限速（沿执行路径重定时）在 4.0、3.0（openpilot `MAX_LATERAL_ACCEL_NO_ROLL`，主工作点）、2.5、2.0、1.7、1.5、1.0 m/s² 各档避开 0 / 22、0 / 24、0 / 12。openpilot 源码里 3.0 m/s² 是对指令曲率的裁剪（另有 5 m/s³ 的 jerk），不是限速器。
4. **缺的信息有很大的上限。** 特权臂（用 simulator 框，在 plan 首个相交点前刹停）：0.5 m 余量 11 / 22、13 / 24、5 / 12；2 m 余量 20 / 22、21 / 24、8 / 12（class ii：6 / 6、6 / 8、3 / 5）；干净 rollout 掉 > 10% progress 的 2 / 198 = 1.0%（nuPlan）、0 / 21（PAI）。同一规则换成模型自己的 lead 输出（登记的非特权臂）：0 / 22、0 / 24、1 / 12，原因是 lead 头近距偏远（第 157 条），刹停点跟着 ego 往前退。shipped 权重同 token 的 plan 在 20 / 22、11 / 12 个 rollout 里同样穿过被撞物体，只是因为短而相交的决策比例低（0.57–0.80 对 0.78–0.90；PAI 0.56 对 0.94）。日志人类路径清空 class ii 的 4 / 6（nuPlan）。
5. **非特权信号（登记线：AUC ≥ 0.75 且下界 > 0.65）。** 标签 = served plan 的扫掠与物体框相交；碰撞 rollout 的相交决策对干净决策（按车速配重，按 log 整簇）。nuPlan P2H10-F（122 对 1827 个决策）：lead 扫掠 0.489 [0.365, 0.644]，路沿 margin 0.718 [0.643, 0.822]，车道线越界 0.456，meta 0.36–0.70，desire 0.659，served 与 P0 plan 的差 0.58，全部 13+ 个信号的组合 0.707 [0.557, 0.870]；过线的只有 served plan 自己的 2 s 横向 std 0.786 [0.738, 0.865]（4 s 0.766，候选），它在 APY10m10 上 0.697、在「全部决策相交对不相交」上 0.651，撞前 ≥ 1.5 s 标出 10 / 22。特权参考（simulator 当前框、不带未来运动）0.728。PAI：lead 类信号全过（lead 扫掠 0.876 [0.735, 0.975]，9 / 12 提前 ≥ 1.5 s，中位 6.1 s），但 lead 横向位置相对 lead 概率（0.850）不加信息；PAI 的回放没有存车道线 / 路沿 / meta / std，Tokyo 两张卡被 FIX1 占用，未读。
6. **登记线判定。** 线 B（非特权开关避开 ≥ 30% 的 class ii + iii，且干净 rollout 掉 > 10% progress 的 ≤ 5%）：两个登记臂都是 0 / 6（nuPlan）、0 / 5（PAI）；该类每域不足 8 次，按登记只作描述；按全部碰撞算也是 0 / 22 与 0–1 / 12。线 C：nuPlan 只有 `plan_std2_FT`，PAI 是 lead 类信号。

**对方向的含义**：(1) 用户读片得到的第 2 类成立且可量化：它是 plan 的净空估计失败（ii），nuPlan 上占 27%、PAI 上占 42%；nuPlan 上更大的一类仍是漂移（45%），两者共同点是 plan 把自己的车身扫过一辆站着的车而不改道也不停。执行与弯道车速都不是杠杆。(2) serving 侧没有可交给 FIX1 的登记臂：有上限的规则需要物体框，模型自己的 lead 头只在本车道前车上提供（FIX1 的 lead cap 已覆盖，且带静止保持）；`plan_std2_FT > 0.46 m` 是唯一过线的触发，但没有刹停点，同路径减速在反事实里避开 0 次，不建议上环。(3) 训练侧要监督的是 adapter 自己 plan 的后果：预测轨迹上 ego 框对日志 agent 框（同一时刻、带运动）与道路边界的扫掠相交（0 / 1、首次接触的时间与弧长、横向缺口），并且需要 on-policy 的行（碰撞发生在偏离日志 0.5–2.4 m、或超前日志 13–39 m 的状态；干净决策里约 7% 会短暂相交随后自行移开）。这个标签从冻结模型现有输出里学不出来（nuPlan 上各几何头 ≤ 0.72，连 simulator 当前框也只有 0.73）：需要新的近距对象信号，监督里要有对象运动；与第 158 条的区别是把后果作为可被刹停 / 重规划读取的输出来预测，而不只是给 plan 加 hinge。
**状态**：**成立**（中）。限定：反事实是运动学、开环的（执行路径 + 已记录决策，模型看不到改变后的状态，交通回放，刹停后可能被追尾），特权臂是上界；nuPlan scene 只有 5 s（约 10 次决策、物体 2 Hz），记录之外按匀速外推，提前量封顶；计数小且成对（22 次 = 12 个 scene、9 个 log，class ii 是 4 个 scene；PAI 12 次、单 seed）；分类以日志路径为车道参照，规则在第一张表之后改过三处（转弯以日志为准、绕行对象须 4 s 内可达、贴着日志路径擦到旁边静止物体算机动），都列在结果文档；「机动意图」是由日志转弯和前方物体推断的；APY 的正例用的是 P2H10 的对照；lead 框只用了 t = 0 的 lead 加其速度外推（登记写的是 0 / 2 / 4 s 插值，读数前改并写明）；`plan_std` 未做标定；26 个非特权读数没有多重比较校正。
**会推翻或推进本条的证据**：闭环里带净空项的臂（训练出的接触预测 + 刹停 / 重规划）在 class ii / iv scene 上的碰撞数；更长的 nuPlan scene 或更多 PAI scene 上 class iii 是否仍为 0；PAI 上车道线 / 路沿 / plan std 的同口径读数；`plan_std` 触发在第三个配方或新 log 上是否仍过线；一个从前视图监督出近距对象框（含运动）的支路，其输出对本标签的 AUC 是否超过当前框参考 0.73 / 0.87。
