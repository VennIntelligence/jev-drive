# 250. HUGSIM 录下的渲染帧上的离线 frame A / B（`P2H10-F-s0`，`spec`）：同一批 decision 改走训练协议（8-slot warp lattice、真实时钟），plan 在 3 s 处移 2.28 m [1.55, 3.41]、变长 12%（arc 比 1.124 [1.073, 1.181]）；变长来自去掉 1.25× dilation（arc 1.143 [1.116, 1.164]），不是帧来源（raw 对 → warp lattice，arc 0.971 [0.932, 1.012]，变短不成立）；相对变化集中在起步（v < 2 m/s 时训练协议的 plan 远 44% [31, 57]）；PAI 上「真实帧让 plan 短 10%」不能照搬到 HUGSIM（**中**：16 个 scenario、845 个 warm decision，open loop，三个 gate 过，无第二读者）

2026-10-11。lane「10 Hz 帧来源」，接第 249 条。只测量：一次录制 run（agent opt `trace_frames`，默认关）加离线 replay；serving 路径没改，没有闭环重跑，没有训练。结果 [experiments/hugsim/results/frame_ab.md](../../experiments/hugsim/results/frame_ab.md)，小表 `results/frame_ab/`，预登记 [plans/2026-10-11-frame-ab-prereg.md](../../experiments/hugsim/plans/2026-10-11-frame-ab-prereg.md)。本条由协调 session 按执行 agent 的报告写，没有第二个读者复算。plan 都在 simulator 时钟上比（0.5 … 4 s）。

**Gates**：离线 ONNX replay 逐位复现日志里的 plan（989 个 decision 0 个超 0.03 m；bias 置零的 control 989 / 989 超）；`sh30_core.Core.plan` 复现 bench 的 navtest 预测（32 / 32 在 0.05 m 内，去 adapter bias 的 control 32 / 32 超）；HUGSIM 侧 warp 的 pose 约定（warp 后 luma MAE 10.0，不 warp 13.0，镜像 12.1，反向 16.3）。

Warm decision（n = 845，16 个 scenario，四个数据集各 4 个；CI 是 scenario cluster bootstrap）：

| 步骤 | 3 s 位移 (m) | arc 比 0–3 s | 3 s 横向绝对差 (m) |
|:--|:--|:--|--:|
| served → 训练协议（真实时钟），合计 | 2.28 [1.55, 3.41] | 1.124 [1.073, 1.181] | 0.27 |
| 9 → 8 slot | 0.69 [0.51, 1.02] | 1.007 [0.989, 1.022] | 0.06 |
| 像素来源（raw 对 → warp lattice，时钟不变） | 1.52 [1.12, 2.26] | 0.971 [0.932, 1.012] | 0.21 |
| 时钟 + key 网格（去掉 dilation） | 2.14 [1.72, 2.83] | 1.143 [1.116, 1.164] | 0.22 |
| desire pulse（第 249 条没列的第四处不同） | 0.22 [0.07, 0.44] | 1.003 | 0.14 |
| torch port 残差（地板） | 0.07 | 1.004 | 0.01 |

1. **合计是纵向的**：3 s 处沿路 +1.87 m [1.05, 3.07]，带符号横向 +0.04 m；16 / 16 个 scenario 上训练协议的 plan 都更长（1.013–1.325）。按预登记的规则属于「PAI 同量级」，方向相反。
2. **像素来源单独**：位移是 PAI 级（1.52 m，navtest stand-in 是 1.20 m），但变短不成立（CI 含 1，9 / 16 个 scenario 更短）。这一步拆不干净：raw 对间隔 0.25 s、lattice 对间隔 0.2 s，在录下的帧上无法单独变；保住时钟的桥接臂里有两张 key 比声称的 pose 新 0.125 s，误差随速度增大，与该步位移的走势（0.62 → 2.34 m）同向。1.52 m 是帧来源加这个 artefact，比例没量。
3. **去掉 dilation 是变长的来源**。第 249 条说的「时钟不是 bug」仍成立（各 consumer 的换算是对的）；本条量到的是它留下的输入偏移的大小：告诉模型真实速度、给它真实时钟上的帧，plan 长 14%。这一步同时含 key 网格的变化，没有再拆。
4. **集中在起步**：v < 2 m/s 时 arc 比 1.435 [1.308, 1.565]（272 个 decision，8 个 scenario），2–5 m/s 1.116，> 5 m/s 1.094；起步处像素来源一步只有 0.62 m、arc 1.018（来源是时钟加 cold start，这一句是推断）。warm-up（n = 144）：合计 2.01 m [1.67, 2.37]、arc 1.226 [1.196, 1.256]，基本只有 step 0 特殊（served plan 比训练协议的 cold-start plan 短 4.2 倍），step 1 起落回 warm 的范围。横向在转弯时最大，3 s 处 0.60 m。
5. **desire**：serving 喂 `desire-sim+onehot`，训练行 desire 恒 0；163 / 989 个 decision 超 0.03 m，最大 6.2 m，集中在有 turn command 的 scenario。
6. **限制**：open loop，训练协议臂在 served 臂走到的状态上评估，不是分数预测；一个 checkpoint（seed 0）、一次录制、16 / 64 个按结局挑的 scenario；launch stall（1 个）、spin（2 个）、off route（2 个）都是个例。没做：真实时钟 lattice 配 dilated ego 的臂（把时钟项与 key 网格拆开）、9-slot lattice、seed 1。

**状态**：plan 上的 mismatch 大小**已量**（中）；对 HD-Score 的影响**待定**。没有修。
**会推翻或推进本条的证据**：用 stateless 训练协议 serve 的一次 HUGSIM 闭环；把时钟与 key 网格拆开的臂；seed 1 与其余 48 个 scenario。
