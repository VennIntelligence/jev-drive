# 111. 起步的环路增益在真实 WOD 起步上同样存在、且比 HUGSIM 更大：模型侧的放大是 openpilot 自身的性质，不是渲染画面的产物；会不会发散取决于控制器传递 c，HUGSIM 的 0.19 比临界值大约 10 倍（**待定**，Cinque 原生，300 个真实起步 / 292 个 segment，离线）
2026-10-04。接第 110 条（打转场景只由起步偏向区分，环路增长处处 > 1）与第 109 条（渲染增益解释不复现）。预登记 [experiments/hugsim/plans/2026-10-04-wod-launch-gain-prereg.md](../../experiments/hugsim/plans/2026-10-04-wod-launch-gain-prereg.md)（含附录：HUGSIM 同形状扰动对照是看到首批数字后追加的），结果 [experiments/hugsim/results/wod_launch_gain.md](../../experiments/hugsim/results/wod_launch_gain.md)，图 `figs/wod-launch-gain.png`。由另一位执行者完成；本条由 main 按其报告写，没有复算。

1. **局部增益**：第 106 条 `lwod` 的真实起步（静止 ≥ 1.8 s 后第一个运动帧），与第 100 / 110 条同一读数（±2°/s 假偏航，HUGSIM 同形状扰动），步 1–3 为 9.34 [9.12, 9.59] / 5.15 [4.84, 5.46] / 2.32 [2.09, 2.71]；HUGSIM 打转 5.85 / 2.27 / 1.05，不打转 4.87 / 2.20 / 1.13。真实画面增益更高、衰减更慢。原来的全历史扰动给 8.99，两种扰动逐行相关 0.93；CPU 与 TRT 相关 0.9999。
2. **环路增长**：c = 0.19/步（HUGSIM PR#57 控制器）时步 1 z = 2.77 [2.73, 2.82]，按预登记判「openpilot 自身」。z = 1 的临界 c：真实 WOD 步 1 0.018（步 2 0.032、步 3 0.072），HUGSIM 0.028–0.034。
3. **起步偏向**：真实起步步 1–2 的 |phi1| 中位 0.58° [0.39, 0.94]，均值 2.4°，39% ≥ 1°；比 HUGSIM 不打转（0.43°）大（p 0.005），与打转（0.76°）分不开。
4. **速度**：CPU onnxruntime 约 55 分钟 / 事件（cgroup 75 核，每次 136 步、其中 100 步静止预热），改 TRT 单卡后 1.8 s / 事件，300 个约 9 分钟。各条件的预热输入不同（静止帧本身被旋转），状态不能共享。

**对方向的含义**：模型对起步偏航的高敏感在真实画面上也有，所以不是仿真伪影，也不是适配能轻易压下去的（第 106 条）。真车上不打转，按这组数字只能是因为车辆与控制器的传递 c 远小于 0.19（临界约 0.02–0.03）；HUGSIM 的 PR#57 控制器（与 B2D 的控制器）在低速对计划朝向的跟随太紧，是环路的另一半。这把问题从「改模型的历史输入」（navhard 上会伤到 51–66% 需早转的 token，第 110 条）移到「闭环里控制器在低速的传递」，后者对开环的 navtest / navhard 无影响。真实 c 本条没量。

**状态**：**待定**。限定：it_dw3 未跑（用户叫停）；扰动是纯转动 warp；窗口核是上界、没跑闭环；WOD 帧由三相机重渲染到模型帧；c 的临界值是按每步线性近似。
**会推翻或推进本条的证据**：HUGSIM / B2D 控制器在低速的实测 c 以及降低 c（低速限制朝向跟随速率）后的打转数；openpilot 真车控制栈（横向 MPC、曲率速率限制）在起步时的等效 c；真实起步上的大信号增益。

**更正（2026-10-04 夜，第 113 条）**：「真车上不打转只能是因为 c 远小于 0.19」在 openpilot 自己的限值里找不到支持（其曲率速率上限在 0.5–3 m/s 不起作用，等效 c 约 0.2–0.5），这一读法降为未证实；但只改控制器就消掉打转，环路解释本身得到确认。
