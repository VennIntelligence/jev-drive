# 118. 用 openpilot 自己的横向控制路径（action 头曲率 → clip_curvature → lateralDelay）代替跟踪计划位置：HUGSIM 打转 10 → 0，起步事件 0/99；有效 c 0.013（iLQR 0.127），起步偏向基本进不了 action 头；非打转 HD −0.009 [−0.058, +0.042]，「不伤」线不过，代价来自更多卡在停车计划的 run（**待定**，64 场景单次，B2D 未跑）

1. **源码路径**（openpilot master ec95db3f，opendbc 35f7e081）：Cinque 在车上用 action 头，desired curvature = action[0] / max(1, v)²，不平滑，v ≤ 0.3 m/s 时保持上一次；controlsd 100 Hz，latActive 要求 v > max(minSteerSpeed, 0.3)，clip_curvature（曲率变化 ≤ 5 / max(v, 1)² 每秒，横向加速度 ≤ 3 m/s²，|κ| ≤ 0.2）；车按 lagd 的纯延迟 lateralDelay 实现（在线估计夹在 [0.15, 0.65] s）。仿真取延迟 0.25 s，与 action_t 自洽；代表车 RAV4 TSS2；纵向不动（仍 iLQR 跟踪计划）。
2. **离线 c**（考试基线 64 个 run 开环回放，2 121 步）：openpilot 路径 < 1 / 1–2 / 2–3 m/s 为 −0.003 / 0.026 / 0.003，合并 **0.013 [0.001, 0.024]**；同数据 iLQR 0.055 / 0.145 / 0.247（合并 0.127）。action 曲率与计划 1 s 方向同号只占 0.56，幅度是计划推曲率的 1/2–1/5。环路增长 1–2 m/s 0.96–1.07（iLQR 1.82–2.34）。
3. **HUGSIM 64 场景**：打转 **0**（考试基线 10，三次重跑 9 / 9 / 9），起步事件 0/99 对 8/91，背景碰撞 13 → 5，HD 均值 0.286 对 0.278。非打转 54 个 HD −0.009 [−0.058, +0.042]，下界不过 −0.02（区间两边都宽：没证明不伤，不是有害）。丢分不来自欠转，来自卡死：max_steps 15 → 24，新增 9 个 run 里车 84–97% 的步停着、模型在停车计划；0930-hard 停车后被撞（1.00 → 0.26）。涨分：0013-medium 0.06 → 1.00 等。闭环 c 0.033 / 0.066 / 0.146，约 iLQR 的一半。

**更正第 113 条第 2 点**：「openpilot 等效 c 0.2–0.5」只对计划推出的曲率成立；车上实际跑的 action 头几乎不响应起步偏向。

**对方向的含义**：第 111 条的悖论有了不依赖「车辆 c 小」的解释：仿真器跟踪的是 **plan**，真车跟随的是 **action**；action 头对 1–2° 起步偏向基本不响应，环路断开，与用户实车经验一致。这不是逐榜 trick，而是 openpilot 在车上的实际控制方式，应作为两个闭环榜的默认方向；先解决卡在停车计划的问题：纵向也换成 openpilot 路径（action 加速度 → LongControl）。
