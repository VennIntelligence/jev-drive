## 来源可访问性与代码状态

抽样涉及的 8 个唯一论文 PDF URL、7 个唯一 `code_status_source` URL 在复核时 `curl -L` 均返回 HTTP 200。四类“未检出官方仓库”的 GitHub 搜索链接虽可访问，却是动态搜索页，并非可复现的无仓库证明；以 `gh search repos 'LinkVLA'/'RoG-DAgger'/'NTR driving'/'Poutine driving'` 查询，均返回空列表。这只支持“截至 2026-09-24 按这些关键词未检出”，不支持断言永无官方代码。Senna、SimLingo、DrivoR 的固定 SHA 与本地克隆一致，其 README permalink 可访问。

## 跨条目/Codebook 问题

1. `w5_codebook_additions.md` 的 `efficient_action_decoding` 举 Poutine，但 `W5-041` 缺提速证据且最终 CoT 推理表述冲突；应删除该例或另立推理模式类。
2. `metric_proxy_candidate_selection` 的定义要求榜单分数代理，却把未披露 scorer 目标的 NTR 列作例子；保留“目标待核”注释仍不足以满足定义，应移出例子或下调为中性类。
3. `output_representation` 未区分输入导航形式，造成 `W5-004` 错类；DrivoR 的 backbone 初始化与 scene-token 压缩也应拆开编码。两处说明当前单列 `category` 会把一行里的异质设计压成一个类别。
4. 多行数字出处精确，但方法设计往往位于所引表格以外：例如 `W5-001`、`W5-010`。建议为设计加同论文的 section/Figure 页定位。此项未计失败，因为当前数字来源明确且设计可在该 PDF 中核到。
