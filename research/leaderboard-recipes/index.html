3 名字里的那个东西值多少

3.1 语言 / CoT

LLM 怎么「变成」planner，有文档的 recipe 很朴素：把过去 4 s 的 ego 轨迹写进 prompt，输出 5 个文本 waypoint（或接一个 flow / DiT head），在 WOD-E2E 上 SFT 一两个 epoch，就到 test 7.8–7.9 推断。例子：Qwen3.5-2B + LoRA r16，只用 WOD-E2E 训一个 epoch，test 7.873（TTVLM 团队论文，消融）。

  • 轨迹写成文本是唯一被一致判负的接口：text waypoint 71.31 对 action token 80.54 PDMS（AutoVLA，消融）；Bench2Drive 上纯文本 DS 42.23 对 VAE head 77.74（ORION，arXiv 2503.19755）。
  • 语言当训练监督有小而一致的增益：Poutine 的 caption 监督 val RFS +0.18（7.94 → 8.12）；DriveMA 的 meta-action 接口 test RFS +0.06；NAVSIM 上 IL 阶段的 CoT +0.5 到 +2.9 PDMS，RL 之后缩到 +0.6 到 +2.0（只有 text-waypoint 的 VLM）。消融
  • inference 时开语言（图 2）：Poutine 8.08 对 8.12 val RFS（479 帧，噪声内）；AutoVLA test RFS +0.041；SimLingo 开 / 关 CoT 是 85.07 ± 0.95 对 84.41 ± 1.76 DS，作者自己说不显著；ReCogDrive 开 CoT 90.7 对 trajectory-only 90.8 PDMS。
  • 闭环上净负：BLUE 在 SimLingo 上，语言对 14.5% 的路线有益、61.8% 无影响、23.6% 有害。消融
  • 学一个 gate 是唯一稳定拿到分的方式：BLUE 比 never 高 6.63 SR；AdaThinkDrive never 88.3 / always 88.9 / adaptive 90.3 PDMS 消融。做 gating 的只有这两家；其余要么根本不生成 reasoning（六个 VLA），要么 inference 时去掉 CoT（Poutine），要么在 RL reward 里惩罚 CoT 长度（AutoVLA）。
  • 最强的负证据，但设置很小：nuPlan test 上的 Open-Loop Score @3s，CoT 92.56，Plan（无 CoT）92.58，Plan NoV（无视觉、无 CoT）92.92，去掉文本里的 ego / history prior 后 54.56（More Than Meets the Eye，消融）。这是 nuPlan，不是 NAVSIM 也不是 PDMS；Qwen2.5-VL-7B LoRA，61 个 scenario。
  • 相反方向的证据：DiffVLA++ 的 VLA 分支在 navhard 上 48.0，同文 E2E 分支 43.7（分支对比，不是干净消融，两者都低于 DrivoR）；ChainFlow 的 VLM states 在 94.1 的 scorer 模型上 +0.7；ForeDrive 把预测的 future 置零掉 1.4，说明确实被用到。
  • 延迟：AutoVLA 快 1.07 s 对慢 10.52 s；Alpamayo-R1 带 40 个 reasoning token 是 99 ms，trajectory-only 29 ms；ReCogDrive 文本输出 0.58 s 对 diffusion head 0.075 s。

3.2 world model 的三种用法

  • (a) future prediction 当训练目标：弱 baseline 上 +7 到 +23（LAW 77.5 → 84.6，Epona 78.1 → 86.2，DriveVLA-W0 +12 到 +23）；87–89 的 baseline 上 +0.3 到 +1.8。弱 baseline 那里 WM loss 是在补 dense supervision：7–8B 的 VLA 只用 action 监督是 62–70，低于 50M 的 TransFuser（79–84）。消融
  • 不带条件的 future 在强底座上为负：DA-WAM 无 future 93.31，shared global future 92.81（−0.50），action-conditioned 93.46（+0.15），加 hard negatives 93.68。消融，20 epoch，单 seed
  • 目标的形式有影响：WA-JEPA joint 无 future 监督 91.1，加 regression 90.7（−0.4），加 flow matching 91.7（+0.6），EPDMS。消融
  • (b) inference 时 rollout 给候选打分：弱 scorer 上 +2.4（WoTE 83.2 → 85.6，20 epoch 的消融，不是 88.3 的主表数）；强 scorer 上 +0.21 EPDMS（EditWM 90.84 → 91.05），朴素的 WoTE 式 rollout 是 −0.33。选择机制本身更大：DA-WAM candidate 数 1 → 32 是 +6.57。EditWM 的 oracle 差距 6.7 EPDMS，瓶颈在打分精度。消融
  • inference 时生成 video：Metis 生成与否 PDMS 89.0 对 88.9，延迟 1.38 s 对 0.17 s。消融
  • 预测的 future 有没有被用到：ForeDrive 在 89.4 的变体上置零 88.0、换成 persistence 87.0、换成 oracle future 89.6。用到了，上限很低。消融
  • (c) 当 data engine：见 §4.4。三种用法的榜外证据都几乎为空；唯一真测了规模的闭环（VaVAM）是负结果：minADE 改善，NeuroNCAP 正面碰撞 44.4%（S，38k）对 70.0%（B，139k），数据量是混杂变量。

5 这些榜没在考什么

  • ego status 和 memory 就能答的部分（NAVSIM）。ego-status MLP 65.6 PDMS；只有 ego 的 DrivoR 72.9 / 28.3；ego + HD map 86.6 / 40.8；MemoryDrivoR 91.1 / 45.0 对带相机 93.7 / 46.7，差 2.6 PDMS / 1.7 EPDMS。MemoryDrivoR 是把当前相机换成从同地点历史 traversal 检索的特征，保留 ego status、当前 pose 和 learned PDM-scorer planner。作者的解释：4 s 的 horizon 内 ego status 部分泄露了 log 里的 maneuver 陈述。能把两者分开的榜：Bench2Drive DS 61.0 → 34.7、SR 30.5 → 9.5；RealEngine 闭环 88.2 → 72.3，counterfactual safety test 53.8 → 28.1。HUGSIM 的 nuScenes 子集分不开（相机 / memory / ego-only 是 36.4 / 32.2 / 29.1）。不是权重记住了地点：去掉 Pittsburgh 训练再测 Pittsburgh 是 39.0 → 42.7。消融 本仓库：速度置零让 DrivoR 掉 22.1 PDMS、WA-JEPA 掉 8.2（决策 35）。
  • ego prior（WOD-E2E）。匀速外推 val 约 7.02，ego MLP test 7.41，MTR-VP 空白图 7.3409 对有图 7.3433；可用的区间 7.41 → 8.167 约 0.75。
  • progress 偏置（NAVSIM）。PDMS = (NC × DAC) × (5 EP + 5 TTC + 2 C) / 12；human 只在 EP 上丢分（87.5）；RL 的增益进了 EP（§4.3）。
  • rater 轨迹的构造（WOD-E2E）。只有三条被打分的 mode，从模型采样，不含 log；trust region 纵向宽 4 倍，低速时收紧；下限 4 分；没有公布 rater 数量、质控或一致性。后果：log 的 val 是 8.10–8.13；八个 intent 上 oracle best-of-128 是 9.14（DIAL，只有图）；top-rated rater 轨迹 val 9.587，我们到它的差距约一半是速度剖面（决策 164）；从 20 条候选里做特权选择 +1.07（决策 168）。已发表的批评：FluidTest 在 151 个 val scene 上，最高 RFS 档里仍有 40% 的轨迹带新增 threat；带新增 threat 的 scene 占比 Poutine（复现）65%、VMA 53%、RAP 51%。消融
  • val label 训练（WOD-E2E）。见 §4.3。val 是很差的 test 代理：DiffusionLTF 六次提交的 val − test 在 0.12–0.71 之间。
  • corridor 归零（AlpaSim）。Alpamayo 1 在 441 个公开 val scene 上，25.2% 的 rollout 离开 4 m corridor，多于 off-road 10.9% 加 at-fault 碰撞 5.5%（笔记从公开 bundle 重算）。这些是不是「另一条合法路线」属于 推断。后训练在贴这条规则：RoaD 丢掉偏离超过 4 m 的 rollout，AlpaGym 的默认 reward 带 distance_to_gt 项。
  • controller 和延迟。同一个 VaVAM image，nonlinear MPC 换成 linear，mean scene score 0.110 → 0.314；OPTED 给 MPC 加 friction-circle 约束，VaVAM + OPTED 37.1 → 50.6。planner_delay_us: 0：每次调用 1.47 s 的模型在仿真时间里等于 50 ms 的模型 推断。SimLingo 注入 100 ms 控制延迟 85.94 → 28.45 DS；BridgeDrive 把 temporal waypoint 换成 path waypoint 81.97 → 87.99 DS。NAVSIM 只 query 一次，用 LQR + bicycle model 执行 4 s。
  • scorer 的数值基（NAVSIM v2）。false-penalty filter：human log 在某项上失败，agent 该项记满分。Score Basis Audit：在受影响的依赖栈上（NumPy 1.23.4 / OpenBLAS 0.3.20，NAVSIM v2.2，navtest single-stage），盲走直线的 Ignore-All 是 79.6 EPDMS，高于 human replay 74.0、DiffusionDrive 73.7、PDM-Closed 67.1；健康的基上 human 88.9 对 Ignore-All 13.3。消融 作者对官方榜不下结论。本仓库：这个 bug 审过，所有 NAVSIM 分数都在 OPENBLAS_CORETYPE=Haswell 下算，不用改（决策 73）。

6 大模型对小模型

  • 准确的说法是「没有尺寸趋势」，不是「小模型占优」。WOD 上秩相关 −0.089，同时前 13 行里 10 行是 2B–4B 的 VLM；NAVSIM v1 上 DrivoR（41M）93.1 / 93.7 高于所有列出的 VLA（ReCogDrive 90.8、AutoVLA 89.1、DriveVLA-W0 90.2），这是跨系统比较。
  • 没有任何论文在同数据、同 head、同后训练下在闭环上比较过小模型和大模型。HUGSIM / navhard 上的「小模型同分」意思是没人用同样的 recipe 跑过大模型。
  • 大模型有数字支持的赢面：同域放大，Alpamayo-R1 0.5B → 10B 的 AlpaSim 分数 0.35 → 0.72（训练数据是否对齐未说明）；open-loop 长尾，Alpamayo-R1 的 reasoning 在 challenging 集上 minADE6 0.994 → 0.868，DriveVLA-W0 在 70M 内部帧上 ADE 1.06 对 TransFuser-50M 1.26；语言可控性，SimLingo Action Dreaming 24.5% → 81.1%。
  • 没赢的地方：Bench2Drive 总分（camera-only ResNet-34 的 TFv6 91.6 ± 0.7 DS，与最好的 VLA 90.58–91.01 同档）；Fail2Drive 的 shifted SR（TFv6 70.7、BridgeDrive 75.0 对 FIVE-VLA 67.0、BLUE 59.0、SimLingo 55.0）；HUGSIM；navhard；navtest；AlpaSim nuPlan track；AlpaSim PAI 上对 Alpamayo 1 anchor 的 mean scene score（0.597 对 0.560）。
  • NVIDIA 自己的消融里，闭环分数来自 action head 和后训练，不是 reasoning：autoregressive token 换成 flow matching，AlpaSim at-fault 分数 0.59 ± 0.17 → 1.27 ± 0.34；reasoning 开 / 关（75 个 scene）at-fault close encounter 6.0 ± 1.0 → 5.0 ± 3.0，off-road 3.0 ± 2.0 → 4.0 ± 3.0，在误差内。消融

8 可借鉴的做法：面向冻结小 encoder + 轻 adapter

排序来自精读笔记，全部是 推断。判据：论文有没有冻结 backbone 下的数字；增益有没有出现在没为它调过的环境里；label 或 objective 是不是榜单 metric 本身。(a) 类是预期能迁移的能力，(b) 类是 metric-specific、要按榜披露的调参。「最便宜的判决实验」都只是设计，没有跑。

先过的一道闸：我们的 NAVSIM 数（navtest PDMS 89.55，navhard 33.67，决策 170）低于不看当前相机的对照（91.1 / 45.0）；navhard 还低于 ego + HD map 的对照（40.8），高于只有 ego 的（28.3）；navtest 只比 HD map 对照的 86.6 高 2.9。所以这两个数本身不能证明冻结 encoder 提供了 dynamic perception。需要的是我们自己的 Δ(相机 − memory)，加一张 counterfactual 或闭环的榜。推断 这篇 audit 不适用于 WOD-E2E（没有 pose），RFS 8.099 不在它的范围内。
