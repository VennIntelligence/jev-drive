基准、榜单与评测陷阱：四大基准地形、分数成分解构与榜单完整性

核心结论（基准地形、归因与完整性）：
1. 四大基准各有结构性盲区，HUGSIM 是隔离混杂的必要控制列：WOD-E2E（真实开环，ADE 饱和，空间全在 RFS；test 仅打分不重跑）；NAVSIM（大规模非反应式回放 v1 与扰动合成伪闭环 v2，顶部被 learned scorer 占领，且不测真实脱困）；Bench2Drive（CARLA 合成闭环，220 条路线顶部饱和且单次噪声大）；HUGSIM（3DGS 重建真实场景闭环，HD 指标），它将「闭环本身难」与「合成图像难」两个混杂变量彻底分开（决策 19）。
2. 榜单分数中属于突发反应（E 层）的成分极少，高分主要由常规路径（R 层）配方与指标针对性机制构成：W1 账本（31 个方法，1,121 行）显示，nuScenes 由 ego-state prior 独占（速度 ×0.5 影响是图像全黑的 35 倍，但闭环反跌 −3.95 DS）；NAVSIM v2 顶部被 EPDMS 代理评分器垄断（五个非 DrivoR 基座加 TOAD 全部收敛到 49–52，若计入 DrivoR 六变体收敛到 49–56，配方项占 10–15 分）；Bench2Drive 依赖控制接口与规则（TFv6 相同 checkpoint 走 route + target speed 比自己 waypoint 高 14.3 DS [5.1, 25.9]，决策 31；前几名差距全在评测噪声内，决策 38）。W1 账本中能确证属于 E 层的增益全表仅 4 条（RAM 同权重推理 +2.72 DS / +4.85 SR、RoG-DAgger SR +7.15、LiDAR SR +6.1、RAP 恢复数据 +4.4，决策 35）。
3. 跨榜排序一致性极低，前 10 族交集主要由训练数据生态决定（决策 46，待定）：CARLA 闭环族与真实数据开环族的多榜前 10 交集几乎为空。跨榜相关性仅在同代码族内 scaling（TFv6 6 变体 B2D↔Longest6 ρ=0.87）和代际分层（TransFuser vs scorer 族）显著；排除后 B2D↔Longest6 独立方法 n=5 ρ=0.05，NAVSIM v1↔v2 顶部 11 方法 ρ=0.21。开环 L2 与闭环 DS 无关（ρ=−0.16），与 Efficiency 反向同向。按决策 46 就地降级，交集里的 DrivoR 与 WA-JEPA 两族在真实外观车辆配对上均有约 25 pp 选择性反应（约 openpilot 线性读出的一半），WA-JEPA 零样本亦超匀速外推（CV），但纯 scorer 族出生态后低于 CV。
4. 纯上传轨迹榜单无法核实来源，人类基准普遍失真：WOD-E2E 与 NAVSIM 私有 test 只接收轨迹坐标，服务器不重跑模型，离线手标或模型拼接在结构上无法区分；WOD-E2E 没有真实人类上限（logged future val RFS 8.13 为自动与人工混采，openpilot Cinque [加验证集选出的纵向 ×1.06 校准，原生 val RFS 8.005] test RFS 7.921 居 19/115 名）；NAVSIM human 94.8 是过滤后高分并带违规豁免；CARLA / B2D 全行业尚无官方 DS 下真实人类闭环基线（决策 2、文献调研）。
5. 评测底层依赖与算力陷阱已全量排查：NAVSIM 的 numpy 1.23.4 在 Sapphire Rapids 上因 OpenBLAS 自动选 Cooperlake 导致静默求逆错误（第 37 条附带发现，非换机引入）；经系统审计，09-28 之后所有 85 个 eval run 与 metric cache 均强制锁定 OPENBLAS_CORETYPE=Haswell，重算逐位一致，零历史分数受影响（决策 73）。

HUGSIM 作为控制列的核心价值（决策 19）

在基准体系中，若只有 NAVSIM（开环真实外观） 与 Bench2Drive（闭环合成外观） 两列，任何模型在 B2D 上的掉分都会被审稿人解释为「闭环本来就更难」，而无法区分到底是「闭环控制/反应难」还是「合成图像 domain shift 导致表征崩溃」。 HUGSIM 填补了这一空白：它是闭环评测，但画面由 3DGS 光栅化真实街景重建。它彻底将「闭环属性」与「图像仿真鸿沟」解耦。WA-JEPA 在 HUGSIM 上拿到 0.4462 HD，证明真实视频自监督表征能直接零样本迁移至闭环控制。

二、指标冲突与读数陷阱

1. ADE 与 Trust-region (RFS) 的优化目标冲突

在同一特征与模型结构下，轨迹回归（Regression）与模式分类（Classification）在两个指标上表现出系统性冲突：

  • 回归赢 ADE，输信任域（RFS）：ADE 惩罚 L2 均方误差，鼓励输出条件均值。面对分支路口，回归会输出一条「既不像直行又不像左转」的折中均值轨迹，导致 3 s 和 5 s 预测点同时跌出所有 rater 的信任域，被截断至下限 4.0 分。
  • 分类赢信任域，输 ADE：分类器（从离散轨迹词表中 argmax 抽样）输出的是物理上真实存在的单一 mode，能稳稳命中某一 rater 的信任域，但在 ADE 指标上会因单 mode 偏差而输给平滑均值（nuScenes 同特征实测分类 ADE 较连续回归高 0.512 m [+16%，CI [+0.254, +0.748]]，决策 8）。
  • Waymo 饱和度实测：官方 test ADE 已饱和（公开模型如 RAP 2.6457 m、最新榜单 PlusAI 2.545 m，而 logged future 自身为 2.699 m，模型已超越历史预测极限），所有性能区分空间全在 RFS 上，因此纯回归架构在 WOD-E2E 上存在结构性劣势。
  • 词表大小 K 的读数陷阱：按 ADE 口径，K=64 词表的 oracle minADE 已达 0.39 m（nuScenes）与 1.115 m（Waymo），看似充裕；但按 Trust-region 口径，K=64 时 Waymo 上有 9.6% (8/83) 的帧（nuScenes 为 16.2%）无论如何选择均无法命中任何 rater 信任域而被罚到底线；扩大至 K=1024 时 Waymo 样本测得 0/83（单侧 95% 上界 3.5%，nuScenes 为 1.0%；K=8192 降至 0.2%），盲区显著收窄（决策 9）。

2. Logged Future 陷阱与 RFS 机制底线

RFS 机制不仅惩罚模型，对真实驾驶轨迹同样苛刻： 在完整验证集（479 个 rater 帧）上，车端实际行驶出来的真实轨迹（logged future）自身也有 9.4% 的概率落在所有人工 rater 信任域之外被惩罚；在车辆自身先验差异最大的第十十分位（s_ego 最高 10% 帧），logged future 的 RFS 仅有 5.92 分，其中 41.7% 被强制截断到底线。 当前学出来的模型在底线截断率上为 23.6%–25.6%，仅略好于零参数匀速直线模型（CV，27.1%）。

3. 代理评分器跨协议失效陷阱

4. 仿真器耗时测量陷阱：Server FPS ≠ 闭环 tick

CARLA 评测常引用无阻塞 server 天花板（如 1.69 倍实时）或多实例聚合吞吐（如 4 实例测出的 86.5 FPS，决策 16），但这不能作为单实例真实闭环成本外推依据。在真实闭环 tick（单相机 92.4 ms，3 相机 1600×900 达 158 ms）中，128 ms（79%）为阻塞等待相机帧。针对 Python RPC 的微小优化对端到端 Wall-clock 收益几乎为零，真正的加速杠杆在于让 CARLA 直出模型所需分辨率（800×450）以及跳帧 decimate 渲染（决策 17、83）。

三、榜单高分的真实构成：消融账本与机制解构

通过对 31 个方法（跨 31 篇论文）、1,121 行论文单项消融的系统审计（W1 账本，决策 35），各大榜单的高分成分展现出清晰的规律：

1. 三类榜单的三种增益构成

  • nuScenes 开环：Top-3 增益全部来自 ego-state prior（自车历史速度、加速度输入），视觉感知几乎不参与决策。VAD-Base 探针测试表明，将自车速度输入 ×0.5 造成的 L2 误差上升（+2.82 m）是整幅图像完全置黑（+0.09 m）的 35 倍。
  • NAVSIM v2 (navhard)：Top-2 全部是 EPDMS 代理评分器（TOAD、GTRS）。同一套 TOAD CEM 搜索加载在 6 个基座上，5 个非 DrivoR 基座分数瞬间收敛至 49–52 分（若计入 DrivoR+TOAD 的 56.3 则 6 个变体收敛到 49–56 分；iPad 从 34.7 暴涨至 49.8，净涨 +15.1 分）；其中单换 DrivoR 评分器而不搜索即带来 +10.9 分。榜单前排分数中 10–15 分纯粹是评分器与 EPDMS 公式的贴合度，与视觉表征和规划能力无关。
  • Bench2Drive (B2D)：包含真实能力（RAM 记忆、DAgger 恢复、LiDAR 测距），但受未消融的控制接口与启发式规则严重放大。
  • WOD-E2E：95% 的分数由大规模领域数据预训练决定（Poutine 领域预训练 5.59 → 7.95，+2.36 分），而直接针对 RFS 奖励的强化学习（RL）仅增加 +0.08–0.09 分，且在难例场景上反而出现负迁移（spotlight 难例 −0.102）。

2. 控制接口选择的巨大收益（决策 31）

TFv6 论文报告的 95.2 DS 在第三方重测中仅为 89.6（决策 38）。我们对 TFv6 官方冻结 checkpoint 进行了严格配对实验（48 对路線，cluster bootstrap）： 仅改变控制接口，使用 route + target speed 输入驱动控制器比使用模型自身预测的 waypoint 高出整整 14.3 DS [5.1, 25.9]，成功率 SR 提升 29 个百分点。这解释了 TFv6 为何在其自身闭环评测控车中选用 route + target speed 而非 waypoint 通道（决策 31、35）。而 SimLingo 系方法原生即采用 path + speed 解耦接口，B2D 头部方法若存在差距，主要对应测距传感器（TFv6 纯相机 91.6，加装 LiDAR 升至 94.7，+3.1 DS，决策 35）。

3. 属于突发反应（E 层）的证据极度稀缺

在跨 31 篇论文的 1,121 行消融账本中，能够确证属于突发事件反应（E 层）的增益全表仅有 4 条：

  1. FIVE-VLA RAM（动作记忆机制）：同权重推理 bypass → accumulation 带来 +2.72 DS / +4.85 SR，Emergency_Brake 子项 +6.1（论文报的 Give_Way 76.67 超出该项 50% 上限，已就地降级，决策 35）。
  2. RoG-DAgger 离线 DAgger 数据：同 backbone 带来 +3.75 DS、SR +7.15（收益集中在状态恢复）。
  3. TFv6 LiDAR / 雷达测距：+3.1 DS、SR +6.1（为密集碰撞场景提供测距保障）。
  4. RAP 恢复扰动数据：在开环 v1 上增益为 0.0，但在伪闭环 v2 上带来 +4.4 EPDMS（证明纯开环协议完全不奖励恢复能力）。

3. 单次评测噪声抹平名次差异（决策 38）

在 Bench2Drive 209 条有效路线上，同一 checkpoint 的重复评测标准差 SD 达 0.80（BLUE 6 次评测），两次单独评测之差的 95% 置信带达 ±2.3 DS、±5.0 SR。 BLUE 6 次评测总分仅差 0.8，但有 58 / 206 条路线的成败发生翻转（总分稳定靠路线间正负抵消）。 B2D 榜单第 3–7 名（LinkVLA 91.01 到 RoG-DAgger 90.34，第 1 名为 BridgeDrive 96.34、第 2 名为 TFv6 95.28）的总分差距不足 0.7（仅 0.67），完全淹没在训练 run 间约 1.5 DS 的噪声之中。头部方法在 5 个突发 hazard 场景上已近乎饱和（多达 100%），拉开分差的实质是无保护转弯（unprotected turn）与规划避障路线。

五、榜单完整性、人类基线与评测审计

1. 上传式只打分榜单的完整性漏洞

WOD-E2E 与 NAVSIM 私有 test 采用离线推理、上传轨迹 pickle/protobuf 机制，服务器只计算几何误差，并不实际重跑模型。 在这种机制下，无法在技术上排除参赛者离线手工标注或使用大语言模型（LLM）前向生成轨迹的可能（按每帧 1 分钟计算，WOD 1,505 帧仅需 25 人时即可全人工绘制）。 对于纯上传榜单，最坚实的信誉防线不是排名，而是开源端到端推理代码、冻结权重与提交包 SHA-256 哈希，实现逐字节可重现（决策 2、文献调研）。

2. 人类基准的真实状态调查

  • WOD-E2E 无人类上限：论文中 3 条 rater 参考轨迹并非人类驾驶产生，而是由 Wayformer 采样 64 条候选后经人工筛选打分；官方 logged future 在验证集上 RFS 为 8.13，且源自「自动驾驶与人工混合采集」，不能作为纯人类基准。
  • NAVSIM Human 分数构造虚高：v1 在筛选 navtest 时直接剔除了 human PDMS < 0.8 的场景；v2 的 EPDMS 引入了人类违规豁免机制（human 犯规项 agent 自动免罚），使 human 在惩罚项上结构性拿满。模型在 EP（进度）上超越 human 仅代表其更激进地贴近特权规划器上限，不代表超越人类。
  • CARLA / B2D 人类基准空白：文献检索证实，全行业尚无任何在 Bench2Drive 或 CARLA Leaderboard 官方路线及 DS 规则下对人类手柄/方向盘驾驶打分的基准记录。

3. 环境计算陷阱审计：NAVSIM OpenBLAS Bug（决策 73）

系统审计确认（第 37 条附带发现，非换机引入）：numpy 1.23.4 绑定的 OpenBLAS 在 Intel Sapphire Rapids 架构上会自动选择 Cooperlake 内核，导致矩阵求逆（inv / pinv / SVD）出现严重静默数值错误（pinv 相对真实最小二乘解误差达 3.5），直接使无参数 constant velocity 模型在 NAVSIM 上刷出 64 EPDMS 的虚高分数。 通过对 09-28 之后全部 85 个评测 run 与全部 metric cache 进行全量扫描与逐位比对： 所有评估运行均显式声明并注入了 OPENBLAS_CORETYPE=Haswell 环境变量，缓存参考轨迹最大速度均在正常范围（15–19 m/s），四组代表性配置在全量 12,146 与 5,912 token 上重测结果逐位完全一致。确认没有任何一个已归档 NAVSIM 分数受到该 bug 污染。
