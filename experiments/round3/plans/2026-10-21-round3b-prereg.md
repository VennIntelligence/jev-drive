# ROUND3b 预登记补记：归因 J 系起步损失到拉伸行或静止 / 低速人类行（2026-10-21，写于任何 3b 训练输出之前）

## 为什么

- 第 414 条：J-W（去掉站着行）与 J-NF（去掉抹平历史）的 PAI-FIX G-LAUNCH 都是 0.51–0.52，对 R2C 0.865（起步 3 / 6 对 5 / 6，被追尾 4 / 6），
  与 R2J 的 0.535 一样 → H1（站着行）被否，抹平历史不是原因、可以去掉。损失在三个 J 系臂的共同部分：PAI 人类行本身，或时间缩放拉伸行。
- 拉伸行的机理疑点：静止时画面与历史都不带速度，f 读不出来；起步标签按 f² 缩放（f0.5 → 约 0.25 倍距离），模型在静止状态上看到的是
  「同一个画面，一会儿走 0.25 倍、一会儿走 2.25 倍」，平均起来可能偏向慢起步。

## 训练前的离线表（已做，`r3.py launchrows`，CPU，结果 `results/launch_rows.{md,json}`）

起步行 = 输入速度 v0 < 0.5 m/s 且本行 4 s 标签路径 ≥ 0.5 m（人在标签窗里离开）。可抽行 = R2JF 权重 > 0。

| PAI 普通 | 114 453 | 6 566 | 5.74 % | 4.16 [1.86, 7.70] | 1.00 | 0.92 / 1.84 / 0 | 20.8 % |
| PAI f0.5 | 104 415 | 5 089 | 4.87 % | 1.72 [0.97, 2.88] | 0.27 | 0.39 / 0 / 0 | 28.9 % |
| PAI f1.5 | 83 671 | 5 852 | 6.99 % | 8.90 [4.08, 15.75] | 3.03 | 0.56 / 0 / 0 | 17.4 % |
| navtrain_full | 103 288 | 8 349 | 8.08 % | 8.28 [6.10, 10.89] | — | 4.12 / 4.12 / 4.12（51 行中） | — |

- f0.5 起步行的距离是本体普通行的 0.27 倍（≈ f²），f1.5 是 3.03 倍；同一个静止画面配三种距离，正是上面的疑点。
- **但普通 PAI 起步行本身就慢**：4 s 中位 4.16 m，只有 navtrain 起步行（8.28 m）的一半；J 每批 PAI 起步行 1.87 行（加权中位 5.07 m），
  NS 1.84 行（4.16 m，比 J 还短），MV 0 行。所以 NS 去掉了拉伸的歧义，但留下更慢的人类起步；MV 把起步全交还给 NTV0 配方（navtrain 4.12 行 / 批）。
  若 NS 不收回起步而 MV 收回，损失更像来自 PAI 人类低速行本身（含普通行），不只是拉伸。

- 不加新 flag、不加新 loss；`r3.py weights` 断言非 PAI 权重逐位不变、合池行与源池 speed / fut 逐位相等、总权重 1。
- smoke（`r3b.sh smoke`，各 60 步）：标量有限；池模仿行在 32 的 0.75–1.25 倍；这些行无 hinge、agent_ho 为 0；无抹平记录；
  训练记录的各池份额与抽样文件一致（NS：ph 0.5、ph05 / ph15 0；MV：0.25 / 0.125 / 0.125）。两臂都过才训练。

  `--save-at` 只存权重、不取随机数、不更新；同一性检查：NS 的命令 60 步 eager，不带 / 带 `--save-at 20,40`，`df.py bitcmp` 逐位相同

## 读数与登记线（与第 3 轮相同，对 R2C 同场景，`r3.py gate --stem gate3b`）

1. **G-LAUNCH 均分 ≥ 0.815（CTRL 0.865 − 0.05，硬线）**；
2. **T281 路线转零分 ≤ 7（CTRL 12 − 5）**；
3. **TARGET（val160 60 场景）均分 ≥ 0.503（CTRL 0.523 − 0.02）**。

- 两臂 PAI-FIX 原生（VC + LEAD，`v t` 两组 chunk）；报告对 R2C 与对 NTV0 各一份（附 R2J、R3JNF 作参照）。
- **惯性闸（只报告，不决定 281）**：两臂与 R2C、NTV0、RSG 一起跑 `inertia.py cf --name round3b`（P160 行），`lon_anchor.py inertia` 对 R2C 出表：
  停车比、转弯比、空路 v24 斜率（第 412 条 J 停车比 0.753 / 转弯 0.942）。
- **停止规则**：某臂三条都过 → 立刻提交它的 **PAI 281 ACC + GAP**（PRIO 30，NTV0 + ACC + GAP 的 chunk 表，g10、FAST=1，同第 2 / 3 轮），
  对存档 NTV0 + ACC + GAP 与 R2C + ACC + GAP 配对（均分 CI、按类零分、起步数 / 37，另列对 R2J）。两臂都过就两份都读。
  没有臂过 → 只报告，不读 281，不加臂。281 之后不再自动提交任何读数（原生、其它 serve 都不读），结论交主会话。
- 预期（读之前写）：拉伸是原因 → NS 收回 G-LAUNCH、保留转弯修复；MV 也应收回（它不给静止行）。若只有 MV 收回 → 原因是 PAI 低速人类行本身
  （普通行起步就慢，见离线表）。两臂都不收回 → 损失不在静止 / 低速标签，在 PAI 行对在动状态的影响（如跟车间距、速度水平），下一步查在动行。
  MV 可能丢掉 STOP 修复（停车末段 < 2 m/s 的行被去掉）与部分 T281 停车修复，只记录。
- 噪声：G-LAUNCH 只 6 场景，一个起步约 ±0.17；单 seed，TARGET 种子差约 ±0.04（第 406 条）。
