Status: **freeze candidate metric definitions and held-out selection in the commit containing this file, before reading any Task 10 cross-controller outcome**. Governing rules: [controller-eval-rules.md](controller-eval-rules.md). The only pre-freeze CARLA runs were a single `author_route` development pilot on 24240 (completed; 570 ticks, CTE RMS 0.072 m, speed-reference RMS 0.608 m/s) and one truth-pose reference generator on the same route (completed; 441 ticks). ## Frozen split, plans, and runs

Development: 24240, 26966, 17563, and the W2 Dev10 logs for threshold distribution pilot only. Held-out CARLA scenario routes (from `bench2drive220.xml`, selected by scenario family and town before results): **24816, 25845, 24252, 26990, 26944, 25863, 25928, 3364**. These eight are absent from W2/W2b formal and lateral-v2 development runs. The committed `controller-eval/selection.json`, `l1-heldout.xml`, `l23-heldout.xml`, controller configs, and perturbations are frozen inputs. Same seed and weather per controller; L2/L3 use scenario-bearing original routes, L1 no scenarios/background actors. Candidate tuning, if any, remains on dev; final held-out data is read only after this freeze.

L1 has two **separate** references on each route. `route oracle`: the dense global path with RouteAdapter's 8/6 m/s cruise and 2 m/s² endpoint deceleration, fed at 5 Hz. Its ideal time trajectory is integrated at 0.05 s with start acceleration ≤2 m/s², cruise cap, and endpoint braking ≤2 m/s². `expert`: a diagnostic privileged controller (`prod-truth`, truth rear pose, the same route oracle) actually drives the same CARLA MKZ from the nominal spawn; its 20 Hz truth rear-axle positions, starting at the first controlled tick and including terminal hold, become an immutable absolute time trajectory. It is privileged through perfect pose, with no model and no scenario actors; it is a driving reference, not LEAD's expert. Its source run must complete without collision and with all invariant telemetry. Both references are used by every candidate; time is measured from each candidate's first controlled tick. A/B receive the same 20×0.25 s trajectory through the documented adapter: B uses the first eight 0.25 s points; A receives eight ~1 m arc-distance route checkpoints and p2-to-p4 0.5 s speed. C/D use the original 20 points. All four receive identical sensor-pose filtering; truth is evaluation-only in candidates.

L1 perturbations: p01–p05 (committed independent GNSS/IMU seeds and start pose offsets), applied to every arm and route. Interface tests on the same five seeds and route subset 24240/17563 plus four held-out routes: nominal 20×0.25 s; `short_2s` 4×0.5 s; `sparse_5s` 5×1.0 s; `stop_jitter` 0.05 m Gaussian waypoint jitter while the first point is <0.25 m and ego speed <0.2 m/s, seed 20260924+CARLA frame. All are applied identically, no parameter retune. L1 frame validity: complete monotonic 20 Hz truth/control/trajectory telemetry, exact frame alignment, no exception; a legitimate collision/blocked/tick-cap is a driving outcome, not a retry. Infrastructure failure may retry at most three times, preserving attempts.

L2/L3: TFv6 and TCP each run the eight held-out scenario routes × seeds 0,1 × controllers, with original planner weights/code untouched. TFv6 uses the W2 wrapper and common author heuristics. TCP uses `only_traj`, one strict model forward per controlled tick; its native target arbitration is reported separately from trajectory-only controls. Both model heads and final executed controls are logged. Every case checks source predictions, sensor/truth frame alignment, control selection, official result, no shadow state mutation, and monotonic contiguous controlled ticks immediately after the attempt. On a driving or runner **bug** stop the batch; ordinary scored driving failures remain valid and are never rerun. Budget: no more than three infrastructure retries per case.

## Frozen metrics (all case-first)

Sample unit is route×seed. Within each case, include all controlled frames before the first collision for behavior metrics; collision/tick-cap counts for L3 regardless. Do not drop low-speed frames for L1. The evaluator is never given the controller's internal pose or progress. Angles use the same rear-axle/CARLA axes as the existing independent TruthProjection.

**L1:** At each 0.05 s reference time, linearly interpolate actual rear XY/speed from valid run frames; if a collision/early termination occurs, hold its last XY and set speed 0 until the reference end (explicit censoring penalty). For an unfinished run at the tick cap, use the same rule. Oracle and expert separately report: spatial CTE RMS to the fixed world reference polyline; time-aligned XY RMS; time-aligned speed RMS; signed final-path overshoot maximum; start convergence time (first 1 s continuously within 0.5 m/s of reference while reference speed ≥3 m/s); terminal hold compliance (<0.1 m/s, within 1 m for 5 s); and `extra_jerk_rms`, RMS of actual minus reference longitudinal jerk after both speeds are smoothed with the same centered five-tick moving average, acceleration = centered 0.25 s difference, jerk = centered 0.25 s acceleration difference. Boundary samples without the full stencil are excluded. The primary L1 error is `sqrt((CTE_RMS/0.5)^2 + (time_XY_RMS/2)^2 + (speed_RMS/0.5)^2)`; lower is better. A candidate is L1 significantly better than an applicable baseline only if its paired route-cluster bootstrap 95% CI upper bound for primary difference is <0 **on both reference types**. Robustness is the worst-case primary over interface modes divided by nominal primary on the same route/seed; report, do not silently drop failing modes. Distinct L1 controller baselines: A for route control; B for waypoint/trajectory control, with A also shown as shared overall reference.

**L2 plan classification:** Obtain the controller's accepted *speed plan*: TFv6 native A uses its target-speed head; TFv6 B/C/D use the waypoint p2-to-p4 distance divided by 0.5 s; TCP native and all adapted controls use the mean p1-to-p4 segment speed over 1.5 s. Set `a_req=(v_plan−v_ego)/0.5 s`. For waypoint plans also calculate `a_internal` as the largest absolute adjacent waypoint-segment speed change divided by waypoint dt; for A's target-only speed head this term is undefined, not zero. Use three-point curvature of future path points 2–4 and `a_lat=v_plan²·|curvature|`; if speed <0.5 m/s, set lateral test to zero. **Feasible** iff all defined values are finite, −4≤a_req≤3 m/s², a_internal≤6 m/s² when defined, and a_lat≤6 m/s². Otherwise **infeasible**, with nonfinite plans additionally marked invalid and treated as case invariant failure. Pilot on A's Dev10 seed-0 predictions (4314 valid frames): |a_req| median 1.15, P75 5.48 m/s²; internal acceleration median 4.68, P75 6.54; these bounds deliberately keep both feasible and infeasible strata. No threshold is adjusted after this commit. L2 compares controller behavior **conditional on its accepted plan**; TFv6 A's route/target heads differ from B/C/D's waypoint head, so A's L2 metrics are reported separately and are not treated as a pure-controller paired contrast to B/C/D. TCP's common waypoint head permits direct paired controller contrasts.

For feasible frames: 0.5 s rear-axle displacement error to the accepted predicted path (A route head has no 0.5 s timing, so this cell is `N/A`); speed-plan error `|v_ego−v_plan|`; `extra_jerk_rms` on longitudinal speed versus the accepted plan's implied speed trajectory using the L1 derivative stencil; full-pedal saturation share when |a_req|≤1.5 m/s²; pedal reversal count per simulated minute when the sign of a_req does not reverse within ±0.25 s; false stop (v_plan≥2 m/s for ≥2 s while actual v<0.5), missed stop (v_plan≤0.2 for ≥2 s while actual v>0.5), and feasible-frame coverage. Aggregate each metric within case; L2 feasible non-worsening requires each shared, defined primary metric (0.5 s displacement error, speed-plan error, extra jerk) to have paired route-bootstrap 95% CI upper bound ≤0.05 m, ≤0.10 m/s, ≤1.0 m/s³ respectively, and at least one improvement's CI upper bound <0. No case with <50 feasible frames may be treated as a pass.

For infeasible frames: collapse adjacent frames into events, add 2 s after first onset, and report event count, actual/reference-subtracted jerk, distance to reach v≤0.5 after a stop request, rear gap to nearest leading vehicle (when actor telemetry is available), and collision frequency. Also report same-frame shadow controls where available, but only real closed-loop cases support conclusions. Do not penalize a controller for the planner's commanded zero speed or strategic stop duration itself. An infeasible event with no visible leading vehicle has `gap=N/A` rather than invented clearance.

**L3:** official DS, collision count, route completion. For each planner separately, native TFv6 A and official TCP `only_traj` are the guards. A candidate is non-inferior iff the paired route-cluster bootstrap 95% CI *lower bound* for mean DS difference (candidate−native) is ≥−3 points. Report counts and exact CI; no route removal for failures. This is a guard, not a quality score.

**Statistics/verdict:** 10,000 route-cluster bootstrap resamples with deterministic NumPy seed 20260924, resampling all seeds within each sampled route; two-sided percentile 95% CI. Route is the cluster, no frame-level significance. L1 primary significance, L2 feasible non-worsening plus one significant improvement, and both planner L3 guards are all required for “better”. If L1/L2 pass but L3 fails: “better execution, planner-incompatible”. Otherwise “not established” or “worse” as evidence warrants. Ease-of-use requires **one identical parameter set**, no planner-specific tuning or adaptation except documented shape/axis/time contract, satisfying the same gates on both planners. Descriptive L2 infeasible findings cannot overturn these frozen gates.
