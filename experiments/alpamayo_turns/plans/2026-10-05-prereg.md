# alpamayo_turns 预登记：Alpamayo 1.5 在真实急弯上是否需要侧向相机（2026-10-05，写于看任何模型输出之前）

## 问题
openpilot wide 输入 58.7°，90° 急弯时出口离开视野；d135：把更宽的画面塞进 wide 槽 zero-shot 无用，转向来自 road 相机。
下一步想给 openpilot 一个 Alpamayo 式多相机输入（cross-left / front-wide / cross-right 各自原生分辨率，不挤压），要做侧视 adapter + 微调。
做之前先定上限：**Alpamayo 1.5 自己用它的多相机 rig 能不能过这些急弯；把侧向相机拿掉后还能不能过。**

## 数据：为什么只用 PhysicalAI-AV test split
- PhysicalAI-AV（`nvidia/PhysicalAI-Autonomous-Vehicles` @ `33f9bf4`）就是 Alpamayo 的 rig：cross-left 120°、front-wide 120°、cross-right 120°、
  front-tele 30°（另有 rear 三路，Alpamayo 1.5 默认不用），f-theta 1920×1080，processor 缩到约 576×320。不需要任何相机映射，A 臂就是 as shipped。
- `clip_index.parquet` 有 split 列（train 153 625 / val 90 928 / test 61 599）。只从 **test** 取，降低训练集重叠（Alpamayo 是否用过 test clip 未知，
  model card 没写，记为限定）。
- openpilot 能在同一 clip 上喂：front-wide 120° f-theta 按 clip 自己的标定重投影到 road / wide 模型帧（`zeroshot_openloop/archive/pai_openpilot.py`
  的做法，不拼接、不挤压），机位高度是 PAI 车的原生高度（逐 clip 记录）。
- 不用 WOD-E2E：每条记录只有当前帧、邻帧散在别的 shard，Alpamayo 要 4 帧 @10 Hz，只能重复帧（分布外）；FRONT_LEFT/RIGHT 是 ±45° 斜前视，
  不是 120° cross 相机，映射本身就是一个混杂。PAI 结果模糊时再用 WOD 做复现。不用 CARLA（先看真实数据上限）。

## 选例（`scripts/turns.py scan`，冻结为 split `physical_ai_av/alpamayo-turns-pilot@v1`）
- 候选：test split 中 rng(0) 抽 12 个 chunk（约 1 200 个 clip），只下 egomotion；`clip_is_valid` 且 4 路相机都在。
- 10 Hz 重采样，航向 ψ（rig 系，左正，unwrap），速度 v。t0 网格：5.1 s ≤ t0 ≤ 18.4 s（clip 时钟；openpilot 要 5 s 预热，Alpamayo 要 1.6 s 历史；
  相机只覆盖约 0–20 s，次 t0 = 主 t0 + 1.5 s 也要在视频内），步长 0.1 s。egomotion 约 140 s，所以 6.4 s 的日志未来可以越过视频末尾。
  H(t0) = ψ(t0+6.4) − ψ(t0)。（更正，仍在看任何模型输出之前：第一次扫描把 t0 放在整段 egomotion 上，选到了视频之外的 t0，作废重扫。）
- 急弯：max|H| ∈ [60°, 135°]（排除掉头）；该窗口内速度中位 2–10 m/s；窗口内 1 s 平滑曲率峰值 ≥ 1/20 m⁻¹（半径 ≤ 20 m）。
- **主 t0** = 最早满足 |H(t0)| ≥ 0.9·max|H| 的 t0（车在弯入口前后，几乎整个弯都在 6.4 s 预测窗内）。**次 t0** = 主 t0 + 1.5 s（已进弯，出口更偏侧向，
  侧向相机理论上更有用；GT 航向变化更小，比值噪声更大）。
- pilot：rng(0) 取 5 左 + 5 右，每 clip 一个转弯。

## 臂（Alpamayo 1.5 @ `7aba829`，代码 NVlabs/alpamayo1.5 @ `36aeb4c`，as shipped）
| 臂 | 相机 | 导航 |
|---|---|---|
| A | cross-left + front-wide + cross-right + front-tele（官方默认） | 无 |
| B | front-wide + front-tele（拿掉两路 cross；官方 `load_physical_aiavdataset(camera_features=...)` + 按 camera index 标名，README / `inference_cam_num.ipynb` 支持的可变相机数，**省略不是涂黑**） | 无 |
| B1 | 只 front-wide（官方 notebook 的 1-cam 配置；次要） | 无 |
| An | 同 A | 有 |
| Bn | 同 B | 有 |
| OP | openpilot 出货 Cinque，front-wide 重投影到 road / wide，零状态 5 s 预热，无 desire、无导航 | 无 |

- 导航文本：`"Turn left in {d}m"` / `"Turn right in {d}m"`（训练格式，见 `notebooks/nav_demo_samples.json`），d = 从 t0 沿 GT 路径到 GT 航向达到
  ψ_g(6.4) 一半处的距离，取整米。这是 oracle 导航（方向 + 距离来自日志），只为把「选不选这个出口」和「转不转得过来」分开。
- 每 (case, t0, 臂) 6 条样本，seed 固定（`num_traj_samples=6`，top_p 0.98，temperature 0.6，flow 10 步，SDPA；smoke run 已证 SDPA 与 FA2 drift 0.01 m）。

## 指标（每样本算，case 值 = 6 样本均值）
GT 航向 ψ_g(t)、预测航向 ψ_p(t)，t = 0.1…6.4 s（Alpamayo 用其输出的 rot 取 yaw；openpilot 用 plan_yaw，插值到同一时刻）。
- **主指标 A_H**：航向增益 Σψ_p ψ_g / Σψ_g²（过原点回归，1 = 幅度和时序都对上；欠转 < 1）。
- **时机 lag50**：t50_p − t50_g，t50 = 带符号航向首次达到 0.5·ψ_g(6.4) 的时刻（正 = 晚）；6.4 s 内没到记 6.5 s（删失，报个数）。
- 次指标：R_end = ψ_p(6.4)/ψ_g(6.4)、转弯率（R_end ≥ 0.5 的样本比例）、ADE64、minADE6。
- 效应：case 配对差，按 case bootstrap（`jevdrive.stats.paired`，B 10 000）。主 t0 上判定；次 t0 单报。

## 判定（事先固定）
- **主比较 = An vs Bn**（知道该转哪边时，侧向相机是否帮它转过来）；A vs B 为次（无导航时还混着路线歧义）。
- **侧向相机要紧**：ΔA_H(An − Bn) ≥ +0.10 且 95% CI 下界 > 0。
- **侧向相机不要紧**：|ΔA_H| < 0.05 且 CI ⊂ [−0.15, +0.15]。
- 其余 = 不确定 → 扩到 n = 30（同规则再抽 20 个转弯，含 pilot），只按 n = 30 判定。
- **Alpamayo 上限**：An 的 A_H ≥ 0.80 记为「能过这些急弯」。Alpamayo vs openpilot：报 A − OP、An − OP 的 ΔA_H 与 Δlag50，不设门槛。

## 小步与提前停
1. 先跑 1 个 case 全部臂，看喂进去的图（每臂一张）、输出形状、航向符号与 GT 一致（左转 ψ_g > 0）。
2. pilot 10 个 case；pilot 判定明确（要紧 / 不要紧）即停，不扩。
3. 估时：每次推理 n=6 约 2.2–2.7 s，10 case × 2 t0 × 5 臂 = 100 次 ≈ 5 min；数据 10 clip × 4 路相机 ≈ 650 MB（Clash 约 3.7 MB/s，约 3 min）；
   egomotion 12 chunk 约 400 MB。全部远低于 1 h，不需要分阶段放大。

## 不做
不微调、不改模型代码、不碰 decisions.md、不用 CARLA。
