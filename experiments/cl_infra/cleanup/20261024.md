## Opus audit of the ASK items (2026-10-24 evening; nothing deleted, moved or compressed)

Read-only audit. Scan files on the box are in `$DATA_DIR/tmp/audit_1024/`. `asl_cls.tsv` classifies every `rollout.asl` in `cleanup_1024/asl.txt`. Each line gives
bytes, score class, read root, chunk sim dir and path. The class comes from the chunk's `aggregate/results-summary.json`: `zero` = the scene scored 0, `pos` = it scored above 0. `by_root.tsv` sums this per read root.
`del_<item>.txt` / `keep_<item>.txt` are the exact file lists for each item below (`$DATA_DIR/<path>\tbytes`). `opruns.txt` gives the `op_parity/runs` sizes. The generators sit next to
them: `cls.py` (classify), `gen.py` (asl lists A-F), `gen2.py` (H1 / H2), `keep.py` (KEEP sizes). GB = 10^9 bytes, counted from file sizes. Regular files only: the scorer_v2 mirror trees (`*/sv2*/new`,
`runs/alpasim/scorer_v2`, `pai_pcs_v2/rescore*`) hold symlinks to these files. They are never targets, and they become harmless dangling links.

### Findings that change the inventory's reading

1. **808 of the 865 GB of asl are zero-score asl, and only 56 GB belong to scored (>0) rollouts.** `pai_box.sh run` already deletes the asl of every
   rollout with score > 0 unless `KEEP_ASL=1`. So a stored PAI read's asl is exactly the set that `scorer_v2.py` (decision 453) needs to re-evaluate the
   read under a new scorer. "One sample per `rollouts` dir" does not trim a read: it removes that read's ability to be rescored. Earlier cleanups already
   cost us this once. Decision 455 had to drop 11 of decision 392's 13 strong-band reads from the PCS ruler, because their zero asl had been deleted down to one sample.
   The ruler now rests on two reads (RSG-s0, NTV0-s0). That is why this audit keeps full zero asl for every read that a future comparison will reuse. The sample
   rule is applied only to closed arms.
2. **Regeneration is cheaper than the inventory says.** Measured from `pool/log.txt` `total_s`:
   - a PAI 281 read with Harmonizer off is 8 chunks and about 3.2 GPU job-h (about 1.1 card-h at 3 stacks per card). Decision 466 showed that a re-read with the same chunk lists is bit-identical.
   - an agH read (Harmonizer on) is about 9.7 job-h and is *not* reproducible bit for bit (decision 442, noise about ±0.007).
   - a val160 read is about 1.7 job-h.
   - a nuPlan arena read is 18 chunks and about 6 job-h.
   - the two PCS-V2 anchor re-reads (GS 4.2 + G0014 4.7 job-h, `ALPASIM_FAST=0`) cost about 9 job-h, not "several hundred card-h".
   - garage v0.2 is about 2 job-h per read.
   A re-read needs the arm's checkpoint, so `op_parity/runs` stays (item H).
3. **`route_mem/feat` is a trainer input, not a closed-line file.** `rm_train.py` (line 326) loads `runs/route_mem/feat/<pool>.npz` for every training pool. That
   includes the live `on1_JTDC2` / `on1_JTDCK` / `on1_JTDCI` (hard-linked, nlink 3). KEEP.
4. **`pai_rows/cache` and `pai_rows/stretch` are encode intermediates. `pai_rows/rows` is the irreplaceable part.** Every `on1_PAIH*` / `PAIHN*` /
   `CPAIX` pool carries its own `front.npy` (nlink 1, no symlink into `pai_rows`). `python -m jevdrive.tokens refs` (run now) pins no file under `pai_rows`.
   Only `pr.sh cache|pool|r1|stretch` read cache / stretch, and only when the H / N / S passes are rebuilt. `stretch/PAIHN10` has no pool at all.
5. **The facts / tax that the loss pages, `pai_fix report`, `spin_events` and `log_sync` read already exist.** All 32 closed round-9 / round-7 / round-6 reads
