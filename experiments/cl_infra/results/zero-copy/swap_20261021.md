# Zero-copy swap of five copied merged pools (2026-10-21)

User-approved (exactly these five, all at once): `on1_PPM160`, `on1_JT`, `on1_JTX`, `on1_JTCP`, `on1_JTPH` under
`$DATA_DIR/runs/op_parity/cache/`. `on1_L18RB0J` was not touched (its source is gone). Plan and table of sources: [README.md](README.md),
"Copied merged pools that a zero-copy index could replace". Pool job `zc-swap` (`1020-234547-77a2`, CPU only, 10 cores, run order
PPM160 first as the smoke, then JT, JTX, JTCP, JTPH); the script was a one-off at `/tmp/zc_swap.py` on the box (not committed), output
`$DATA_DIR/runs/cl_infra/zc_swap_20261021/swap_<pool>.json`.

Per pool, in this order:
1. Sources: the part order and row counts come from the pool's `tab.npz` names (`on:<prefix>:...`); every source's `@warp/front.npy`
   must exist with exactly that many rows. `jevdrive.tokens.refs(cache)` must list no manifest that indexes this pool's `front.npy`
   (at the start no `front.parts.json` existed anywhere in the cache, so no pool had dependents; each swapped pool then became a
   dependent of its sources, as intended).
2. Open files: `lsof` is not installed on the box, so `/proc/*/fd` and `/proc/*/maps` of every process were scanned for anything under
   `<pool>@warp/` (same meaning as `lsof +D`). Empty before the verification and again just before the delete.
3. Index: `jevdrive.tokens.link_front` (the call `rf_pait.py merge` makes) into a scratch dir `on1_<pool>@zctmp/` next to the pool (so
   the relative part paths are the ones a real manifest has), then `os.replace` into `<pool>@warp/front.parts.json` after the check.
4. Verify before deleting: `open_front(<scratch>/front.npy)` (a `CatMM`, no `front.npy` there) against `np.load(<pool>@warp/front.npy,
   mmap_mode="r")`, every row, bitwise (uint8 view), chunks of 256 rows, 8 processes. Each chunk dropped its pages (`madvise` +
   `posix_fadvise DONTNEED`) and waited if `(memory.current - inactive_file) / memory.max` exceeded 0.80, so the 630 GB of reads (two copies of 316 GB) did
   not load the cache against the kill line (docs/remote-box.md, "Host memory").
5. Delete only `<pool>@warp/front.npy`; then `open_front` on the old path must return the `CatMM` with the pool's row count, and 68-86
   rows (first, last, every part boundary +-1, 64 random) must equal the source files read directly.

## Afterwards

`python -m jevdrive.tokens refs $DATA_DIR/runs/op_parity/cache` now lists the five manifests: the sources L18RB0 (all five), L18RTB1 / L18YS / L18Y / NR1TV (JT, JTCP, JTPH, JTX), CPAI570 (JTCP), PAIH / PAIH05 / PAIH15 (JTPH), PN0-PN5 (JTX), PPAI160 (PPM160). Those source pools' `front.npy` must stay while any of the five is in use (docs/storage.md). A plain `np.load` of one of the five pools now raises FileNotFoundError; readers use `open_front`. No job had any of the five open; the queued jobs (`fx-tax`, `r2-s2gate`) do not name them in their commands, and `open_front` serves the manifest anyway.
