# S3（后果行）怎么进配方：一页草图（10-21 夜，D3 之后，未登记）

依据：[../results/d3_outcome_variance.md](../results/d3_outcome_variance.md)。150 个训练场景 × 4 种 serve 扰动，有信息的场景 42 %。
稳定信号只有一条：**部分分（被追尾 / 慢）上「快」赢**，11 上 0 下，起步类 +0.124。
零分上 S / L 能救 14 / 43，但同样的臂会把满分打成零，按类定不出规则。停车类够不到（17 个过点零分有 14 个不动）。

## 1. 行从哪来

- 每个有信息的场景（best − worst ≥ 0.2）只取**胜者**那条 rollout。
- 只取它从「与最差 rollout 分开」那一刻起的决策（D3 里每场景约 85 %，起步约 60 %）。分开之前各臂的状态逐位相同，没有后果对比。
- 胜者是 A（当前 serve）的场景也收（22 个，约 3.3 k 决策）。这些行等于「这里原样开就对」，用来抵消扰动在满分场景上的混沌破坏。
- 输家的行**从不作目标**：AWR 的权重恒正，表达不了「别这样」，这与 awr_onpol 预登记的选择一致。
- 画面：D3 没存帧。胜者 rollout 用 `PAI_DUMP` 原样重滚（逐位可复现，D3 里 119 / 119 一致），再走 d402 的 onp_rows → cache → pool 管线。

## 2. 目标是什么

- **胜者在自己状态上的 served plan**，即 drive.jsonl 的 `poses`（ACC 加上该臂旋钮之后、track_ref 之前的 8 个位姿）。
  **不是 `poses_model`。** 在 F / S 上，模型在同一状态的 plan 与 A 完全一样，差别全在 serve 里。拿模型自己的 plan 当目标，学到的只是状态分布，学不到后果。
  这与 awr_onpol 预登记「ACC 是环境、目标取 poses_model」的规则相反，原因是那里比的是不同策略，这里比的是同一策略的不同 serve。
- 这个目标在 ACC serve 下能不能被模型表达出来，要分开看：
  - F 的「设定速度 ×1.15」**可以**。模型 plan 快 15 %，就等于 v_set = max(v_hand, plan) 涨 15 %。部分分 / 起步的信号正好在这一项上。
  - F / S 的弯道限速部分**不能**。ACC 自己另算弯道限速，模型 plan 慢下来也压不低它。S 的「慢」只有在模型自己刹车（触发 stop / brake 守卫）时才会被送出。
  - L 的几何（横移 / 曲率增益）**可以**。ACC 只重定时间，不改路径。
- 备选：胜者实际走过的 4 s 轨迹（事后重标）。它和 served plan 只差控制器跟踪误差，先不用，免得多一个变量。

## 3. 权重和份额（第 379 条的教训）

- **份额固定，不挤占任何现有行。** 第 379 条的 BN 行顶替了 on-policy 抽取，trainval 行每批 38 → 33.6，static −0.059。
  所以后果行走 awr_train.py 的第二次前向：每步额外 K 行，主 batch、它的抽取和其他项全都不动；λ = 1，即每行等于一条日志模仿行的重量。
- **只一个旋钮：过滤式 BC，不按 exp(A/β) 加权。**
  - 优势 A = 胜者分 − 该场景 4 臂均分。
  - 收 A ≥ 0.1 的场景、均匀抽。
  - D3 里的分数差多是 0 / 1 的跳变，exp 权重只会放大几个场景。
- **按结果类型配份额，不按场景类：**

  | 结果类型 | K 行中的份额 | 内容 |
  |---|--:|---|
  | 部分分（胜者多是 F） | 1 / 2 | 稳定信号 |
  | 零分被救（S / L） | 1 / 4 | |
  | A 胜（原样） | 1 / 4 | 护栏 |

  理由：零分行是逐场景的，每类混在一起；部分分行才是可迁移的规则。
- K 起点 8（第 379 条的 8 / 70），剂量只扫 K（4 / 8 / 16），不拆子设计。

## 4. 在第 5 轮里的位置

- 和 S1（人类行）同一配方。第 2–3 轮的起步损失（R2J 起步 33 → 21 / 37，d412 / d414）正是 S1 把起步拉慢；S3 的 F 胜者行往反方向推。
  所以 S3 不是单独的线，是 S1 的配重。闸先看 PAI-FIX G-LAUNCH。
- 停车不靠 S3。要让 S3 管停车，得有作用在模型 plan 本身的扰动（例如守卫内对模型 plan 做弧长缩放），这是新的 serve 逻辑，D3 没测。
  停车留给 S1 / S2。
- 迭代：第 1 轮训完，用新模型在同一批场景上重滚 4 臂（DAgger 式），胜者变了就换行。

## 5. 数据与卡时（719 个非 held 合格场景）

- 4 臂全滚：约 10.7 卡时（D3 实测每 100 场景 × 4 臂 1.49 卡时）。
- 预计约 300 个有信息场景、约 5.5 万个胜者决策（10 Hz），其中非 A、分开之后的约 2.7 万（2 Hz 约 5.4 k）。
- 胜者带帧重滚：约 300 场景 × 1 臂，约 1.1 卡时。
- 先做小 pilot：150 个 D3 场景的 63 个有信息场景直接重滚胜者（约 0.25 卡时），按第 409 / 412 条的 1 000 步 pilot 读 PAI-FIX。
  起步不回来就停，不铺满 719。

## 6. 未决

- 胜者是 F 的行把「快」教给模型后，在动态场景上会不会像 VSET 1.1 那样多出出路 / 走廊零分（281 上 +4–5，D3 上 F 打掉 6 个满分）。
  过滤式 BC 只取 F 赢的场景，应能避开，但要看 TARGET 的零分护栏。
- 1 seed、单 rollout 的胜者有偶然性。PAI 读数是确定的，没有 seed 可换；可以在有信息场景上加相邻剂量（F ×1.1 / ×1.2），胜者在相邻剂量下也赢才收行。
