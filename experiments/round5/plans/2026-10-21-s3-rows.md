## 2. 胜者与结果类型（sel，全集 719 个）

每场景 4 个分数 s_A, s_F, s_S, s_L（results-summary.json 的 score）。best = max，worst = min，有信息 = best − worst ≥ 0.2。

- 优势 adv = best − s_A。adv ≥ 0.1：胜者 = 分数最高的非 A 臂（并列按 F、S、L 的顺序）；否则胜者 = A（并列与 0.1 以内都归 A）。
- 收行的场景与类型（只用胜者那一条 rollout；输家的行从不作目标）：
  - **partial-fixed**：胜者 ≠ A，0 < s_A < 0.98；
  - **zero-rescued**：胜者 ≠ A，s_A = 0；
  - **A-wins**：胜者 = A，且场景有信息（某个臂比 best 低 ≥ 0.2：原样开是对的）。
  - 其余场景（胜者 = A 且无信息）不出行。
- 报告：全集有信息比例（按类）、各臂胜场（按类、按 A 的结果）、类型 × 类的场景数，写到 `results/s3/`。

## 3. 胜者带帧重滚与行（第 2 段）

- 收行场景的胜者臂用同一 serve + `PAI_DUMP=100000`、`KEEP_ASL=1` 重滚（每臂一个根，块 25 个）。先 r000 = 3 个场景（F、非 F 的非 A 臂、A 各 1 个）→ R1 → 其余。
- 行管线与 d402 / PAI-ROWS 相同，不改：onp_rows（rows + cold）→ onp_cache build（编码器按普通缓存同序，每场景按决策顺序成对编码，bs 8；第 410 条 fp16 分批教训）→
  rf_pai_pool（新增 `--fut poses`：fut = 该决策 serve 出去的 8 个位姿，即 drive.jsonl 的 `poses`，ACC / TTS 之后；名字 `on:paio:<scene>:<k>`，src = outcome）。
- 池名 **`on1_PAIO`**。行 = 胜者 rollout 每个可用（8 槽有效）、在胜者第一次计分事件之前、在日志结束之前的 10 Hz 决策（与现有 PAI 池同规则）；
  不在这里按「分开之后」或 2 Hz 截断，而是打标，由配方的抽取权重决定：
  - tab：`otype`（partial-fixed / zero-rescued / A-wins）、`cls`（stop_nolead / turn_sharp / launch / other）、`sub`（curation 小类）、`arm`；
  - `on1_PAIO/outcome.npz`（按 names 对齐）：k、post_hand（交接 1.6 s 之后）、slot2（k % 5 == 0，2 Hz 槽）、k_div_worst / k_div_A（胜者离开最差 / A rollout > 5 cm 的第一个决策）、
    s_win、s_A、adv、以及 **A 在同一决策 k 的 served plan**（`served_A`，A 自己的 rig 系）、A 的 anchor、`has_A`、`same_state_A`（两车 anchor 相距 ≤ 5 cm）。
- 合并只用零拷贝（front.parts.json），不复制 token 文件；`on1_PAIO@warp/front.npy` 是本池自己的行 token（按 tix 取出，与 rf_pai_pool 相同）。
