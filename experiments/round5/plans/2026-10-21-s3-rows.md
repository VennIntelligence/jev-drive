## 2. 胜者与结果类型（sel，全集 719 个）

每场景 4 个分数 s_A, s_F, s_S, s_L（results-summary.json 的 score）。best = max，worst = min，有信息 = best − worst ≥ 0.2。

- 优势 adv = best − s_A。adv ≥ 0.1：胜者 = 分数最高的非 A 臂（并列按 F、S、L 的顺序）；否则胜者 = A（并列与 0.1 以内都归 A）。
- 收行的场景与类型（只用胜者那一条 rollout；输家的行从不作目标）：
  - **partial-fixed**：胜者 ≠ A，0 < s_A < 0.98；
  - **zero-rescued**：胜者 ≠ A，s_A = 0；
  - **A-wins**：胜者 = A，且场景有信息（某个臂比 best 低 ≥ 0.2：原样开是对的）。
  - 其余场景（胜者 = A 且无信息）不出行。
- 报告：全集有信息比例（按类）、各臂胜场（按类、按 A 的结果）、类型 × 类的场景数，写到 `results/s3/`。

  - tab：`otype`（partial-fixed / zero-rescued / A-wins）、`cls`（stop_nolead / turn_sharp / launch / other）、`sub`（curation 小类）、`arm`；
  - `on1_PAIO/outcome.npz`（按 names 对齐）：k、post_hand（交接 1.6 s 之后）、slot2（k % 5 == 0，2 Hz 槽）、k_div_worst / k_div_A（胜者离开最差 / A rollout > 5 cm 的第一个决策）、

## 补记 1：事后重标注 on1_PAIOR（10-21 晨，第 422 条之后，写在任何重标注作业之前）

**为什么**：第 422 条：S3 行的标签是胜者 serve 出去的 plan；ACC 下 plan 本身不更快（D3 的「快的赢起步」来自 ACC 设定速度经控制器起作用），R5-A 把模型自己的慢起步教了回去。
**改动**：标签改为胜者 rollout 从该决策起**实际开出来的 4 s 自车轨迹**；token、输入、状态、行集合都不动（不重滚、不重编码）。

- **标签的定义（与人类行 `log_fut` 同格式同坐标系）**：onp_rows 的 `log_fut = rig_n(path.at_time(t0 + T_FUT), anchor)`，T_FUT = 0.5 … 4.0 s 共 8 个位姿，
  后轴 rig 系、以 t0 的 anchor 为原点、航向相对 t0。重标注用同一变换，只把「日志路径」换成**胜者 rollout 自己的 anchor 序列**（行文件 `rows/PAIO/<scene>.npz`
  的 `anchor`、`t0_us`，10 Hz、每个推理决策一个，即驾驶器在该时刻的自车 rig 位姿，未取整）；航向先沿序列 unwrap，时刻按 `t0_us` 线性插值（决策间隔恒为 100 ms，
  0.5 s 网格正好落在决策时刻上，插值等于取样；报告最大时间偏差）。
- **完整性 / 丢弃**：行的 t0 + 4 s 必须 ≤ min(最后一个决策时刻, 计分器最后读到的时刻 `t_end_us`, 第一次计分事件 `t_event_us` − 1 µs)（与现有行在事件前截断同规则：
  标签不能伸进事件之后或日志之外）。不满足的行**留在池里但 fut = NaN**：训练器的 `has_fut` 不对它做模仿，`r5.py weights` 只给 fut 有限的行权重 → 等于丢弃；
  按后果类型 × 原因（end / event）计数报告。
- **池 `on1_PAIOR`**：与 on1_PAIO 同行、同序、同名；tab 只有 `fut` 不同（`served` 仍是 serve 出的 plan），另存 `relabel.npz`（names、ok、why、旧标签）；
