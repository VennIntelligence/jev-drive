# NAVSIM v1：PDMS

主审代码是官方 [`v1.1` 分支提交 `3e8291bfa89ff247231e0227778840cd0a036896`](https://github.com/autonomousvision/navsim/tree/3e8291bfa89ff247231e0227778840cd0a036896)，官方主分支明确把 v1 和 `navtest` 指向 v1.1。为追溯版本差异，另读初版 [`v1.0` 提交 `b1e21ce7dcb03dce9d886b4aca0ccc1c043f5388`](https://github.com/autonomousvision/navsim/tree/b1e21ce7dcb03dce9d886b4aca0ccc1c043f5388)。两版 PDMS **不同**，本页攻击面以 v1.1 为准；未运行模拟器。[v1.1 官方 README 说明](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/README.md#L24-L27)。

## 指标公式

- `PDMS = NC × DAC × (5×TTC + 5×EP + 2×C)/12`；代码仍计算 DDC，但 v1.1 的 `driving_direction_weight=0`，且 `MultiMetricIndex` 仅含 NC、DAC，故 DDC 不入乘积。NC 对有责动态目标碰撞取 0、其他有责碰撞取 0.5；DAC 只要预测轨迹任意采样位置有非可行驶区域角点即为 0；TTC 和 C 为二值。[`docs/metrics.md:5–16`](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/docs/metrics.md#L5-L16)、[权重 `pdm_scorer.py:35–58`](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/navsim/planning/simulation/planner/pdm_planner/scoring/pdm_scorer.py#L35-L58)、[乘积与加权 `:156–183`](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/navsim/planning/simulation/planner/pdm_planner/scoring/pdm_scorer.py#L156-L183)、[NC 与 DAC `:330–358`](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/navsim/planning/simulation/planner/pdm_planner/scoring/pdm_scorer.py#L330-L358)。
- `EP` 是预测车辆轨迹终点相对起点在中心线上的正向投影距离；它与同组 proposal 中通过乘积门的最大进度相比归一化；最大进度不超过 5 m 时，未触发乘积零分的 proposal 的 EP 被设为 1。官方先用 LQR/自行车模型跑 4 秒，背景交通按日志重放，不响应 ego。[`pdm_scorer.py:398–412`](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/navsim/planning/simulation/planner/pdm_planner/scoring/pdm_scorer.py#L398-L412)、[归一化 `:162–183`](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/navsim/planning/simulation/planner/pdm_planner/scoring/pdm_scorer.py#L162-L183)、[协议 `docs/metrics.md:1–3`](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/docs/metrics.md#L1-L3)。
- 历史差异：**v1.0** `MultiMetricIndex` 包括 DDC，实际分数乘 `NC×DAC×DDC`；v1.1 把它改为零权。不能把这两个提交或后来的 v2 文档中的 v1 回述混用。[v1.0 `pdm_enums.py:159–171`](https://github.com/autonomousvision/navsim/blob/b1e21ce7dcb03dce9d886b4aca0ccc1c043f5388/navsim/planning/simulation/planner/pdm_planner/utils/pdm_enums.py#L159-L171)、[v1.0 `pdm_scorer.py:173–197`](https://github.com/autonomousvision/navsim/blob/b1e21ce7dcb03dce9d886b4aca0ccc1c043f5388/navsim/planning/simulation/planner/pdm_planner/scoring/pdm_scorer.py#L173-L197)。

## 攻击面与第一轮对照

| 攻击面 | 代码所证机制与边界 | 第一轮 |
|---|---|---|
| 在同一场景生成大量候选，用 PDMS 或学得的子分数代理挑高分 | 最终分数完全由固定乘积门与 5:5:2 加权项给出；候选筛选能直接针对这个有限目标，而不要求模型的原始单次预测改进。第一轮代码证实有代理筛选，但**没有同一 checkpoint 的非代理驾驶能力增益证据**。[`pdm_scorer.py:156–183`](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/navsim/planning/simulation/planner/pdm_planner/scoring/pdm_scorer.py#L156-L183) | `NAV1-DVM0-001`; `NAV1-DRIVOR-002`; `NAV1-TOAD-001`; `NAV1-RAP-001` |
| 把 DDC 当作可牺牲项 | v1.1 中逆行分数被计算、但其权重为 0 且不在乘积门；只要 NC/DAC 和其他项不受损，逆行本身不降 PDMS。这是**条件性计分空缺**，不声称已有方法故意逆行。[`pdm_scorer.py:38–58,144–183`](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/navsim/planning/simulation/planner/pdm_planner/scoring/pdm_scorer.py#L38-L58)、[`pdm_enums.py:159–170`](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/navsim/planning/simulation/planner/pdm_planner/utils/pdm_enums.py#L159-L169) | 未观察到 |
| 在 TTC 检查时让预测速度落在极低速阈值下 | 代码先查询碰撞；对 `speed < 0.005 m/s` 的相交候选跳过后续 TTC 失分处理；可保住 TTC 的 5/12 权重，代价可能是 EP 下降，所以净增分取决于场景和候选。[`pdm_scorer.py:455–472`](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/navsim/planning/simulation/planner/pdm_planner/scoring/pdm_scorer.py#L455-L472)、[加权 `:175–183`](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/navsim/planning/simulation/planner/pdm_planner/scoring/pdm_scorer.py#L175-L183) | 未观察到 |
| 利用非反应式场景先验调代理评分或提示 | 背景交通固定重放，4 秒分数只评价对此固定未来的轨迹；提示中写出评分规则与“非反应式”可让候选生成瞄准它。是否因此优于交互式驾驶是待验证推断。[`docs/metrics.md:1–3`](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/docs/metrics.md#L1-L3)、[`pdm_scorer.py:156–183`](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/navsim/planning/simulation/planner/pdm_planner/scoring/pdm_scorer.py#L156-L183) | `NAV1-DVM0-002`（观察到提示规格，未观察到该机制的独立增益） |

## 盲区与证据界限

v1.1 PDMS 不直接看 4 秒以后、真实背景车对 ego 的反应、v1.1 的逆行处罚，也不从单条 PDMS 证明复杂闭环恢复能力。代码中的相对进度还依赖参与比较的 proposal 集合。这些是协议与公式的可观察边界，不是第一轮方法已造成危害的证据。[`docs/metrics.md:1–3`](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/docs/metrics.md#L1-L3)、[`pdm_scorer.py:162–183`](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/navsim/planning/simulation/planner/pdm_planner/scoring/pdm_scorer.py#L162-L183)。
