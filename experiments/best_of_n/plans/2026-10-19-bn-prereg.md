# BEST-OF-N 预登记：多策略 best-of-N 自模仿（评分器当裁判）

写于 2026-10-19，任何 rollout / 行 / 训练输出之前（只做过只读的盘点：四个 checkpoint 在盒上、practice-starts 的层计数）。
依据：[research/knowing-vs-doing.md](../../../research/knowing-vs-doing.md)（「会做」只能从自己动作的、可归因的后果里学）、第 264 / 286 / 321 / 363 / 366 / 368 / 369 / 371 / 372 条。
硬约束：只用我们自己的 checkpoint（不用 garage / WA-JEPA / 第三方模型当老师），没有人的目标。

## 1. 问题

同一个起点让 N = 4 个自己的模型各开一次，评分器选出开得最好的那次；把那次 rollout 自己经过的状态、以及它当时自己 serve 的 plan
作为模仿目标（在策略流形上的自模仿，「裁判」是评分器，不是人），加上 S 的两个 hinge，混进 JTN-L18-s1 的配方做一个短续训。
问：**这些行能不能让 JTN-L18-s1 的短续训在大考场 held 划分的原生读数上比同样续训、不加这些行的对照高 ≥ +0.01？**

为什么这么做：第 321 条（规则专家的几何目标伤避让）、第 286 条（自身状态上的几何目标都伤）说明「给正确路线」不行；
第 371 / 372 条说明 JTN 与 RSG / NTV0 在静止窗、起步窗上分歧最大（JTN 靠低速偏移站住，RSG / NTV0 起步早）。
best-of-N 的目标是某个自己的模型在这个状态下真的开出来、评分器判好的动作：不是规则、不是人，是同一副身体做到过的事。

## 2. 窗口

- 候选：`alpasim_nuplan/practice-starts@v1`（4 612 窗，28 个 train log，从不含 held log；第 368 条）。
- 分层抽 1 200 窗（seed 0，层内均匀无放回）：static 400、launch 300、braking 200、turn 120、other 120、cruise 60
  （自然份额 static 49 %、launch 9.5 %；静止、起步过采样，因为模型在那里分歧最大）。
- 划分 `alpasim_nuplan/best-of-n@v1`（practice-starts 的子集），`check_disjoint` 对 onpol-held，按 log 断言不相交。
- 块：每个 shard 缓存内按 log / 时间切成 ≤ 110 窗一块（= pn.py select 的规则）。

## 3. 策略与滚动

- N = 4：`JTN-L18-s1`（原生 0.891，第 371 条最强）、`NTV0-L18-s0`、`RSG-L18-s0`、`NR1FB10-L18-s0`（四个都在盒上，不替换）。
- 每个模型每窗一次，nuPlan 默认 serve（sh30，`JEV_HOLD` 不设、无 ACC / GAP，= L18 各池滚时的 serve），存帧（`SH30_DUMP`），
  = pn.sh roll 的命令（只换 tag 与清单）。

## 4. 选胜者

- 每个 rollout 的分：评分器零分类型（at-fault 碰撞、走廊、出路）记 0，否则 `score`。任一模型在该窗有非评分器的失败（路线 sanity 折返等）或缺失：整窗不用。
- `best − worst ≥ 0.2` 的窗算「有信息」，只有它们出行。胜者 = 最高分；并列时按固定次序 JTN-L18-s1、NTV0、RSG、NR1FB10 取第一个（学生自己优先）。
- 报：每个模型的胜率（有信息的窗），按层；并列数；每个模型在 1 200 窗上的均分 / 零分（按层）。

## 5. 行

- 胜者 rollout 的每个决策一行：`on_rows.py geo`（原样，`ON_SPLIT=alpasim_nuplan/best-of-n`、`ON_TOK_TIMES` 用 practice_nuplan 的
  tok_times.json；通过一个只含胜者 rollout 的视图目录喂入，on_rows 不改）→ `tok`（token + teacher + R1，对照 smoke10e）→ `rm_build pool / anchor` → strip；
  每个 shard 一个池 `on1_BN<k>`（路线特征要该 shard 的场景加载器）。
- **模仿目标**：tab `fut` 换成该行自己的 `served`（胜者当时 serve 的 8 个位姿，行坐标系）；人的 `fut` 另存 `fut_human.npz`，不训练。
  `fut_reg` 保持日志（只被 arc 项读，本配方 arc 权重 0）。行模式 `both`：模仿 served + S 的 agent / road hinge（`--on-mode mixed`）。
- 池闸（每个 shard、每个 tag，在合池作业里判，不过的行抽样权重 0，如实记）：R1 (a) 前 15 个 plan 点 0.03 m 内 ≥ 0.99（每个 tag）；
  R1 (b) 照旧（smoke10e）；R1 (c) 只报（四个 tag 里有的没有换 seed 的 checkpoint）；R2 用 PN 修订 1 的读法（自车 ≤ 0.3 m、对齐 ≤ 0.1 m、
  车框 0.5 m 内 ≥ 0.995 且中位 ≤ 0.05 m）。

## 6. 训练

- 两臂都从 `JTN-L18-s1` 起（`--init JTN-L18-s1`），2 000 步、warmup 50，其余 = JTN 配方（`jt.sh train` 的命令：lr-scale 0.1、lr 下限 0.1、
  `ARCROWS=brake`、`--on-arc 0`、横向 0.5v2 含旁车、历史速度噪声、`--on-hold-pct 15`、`--on-k 70`），seed 1（JTN-L18-s1 的 seed）。
  命令由 `DRY=1 ARCROWS=brake WARM=50 jt.sh train` 打印后把 `--init RB0-F-s0` 换成 `--init JTN-L18-s1`、`--seed 0` 换成 `--seed 1`。
  - `BNX2K-L18-s1`：池 `on1_BNX` = on1_JT 的五个部分（同顺序，L18NR1v2 仍是前缀栅格）+ `on1_BN0..6`（`both`），抽样 `BNX`。
  - `BNC2K-L18-s1`（对照）：池 `on1_JT`，抽样 `JT00`。
  两条命令的 diff 只允许 `--tag`、`--on`、`--on-wfile` 三处（合池作业里核，不符则停）。
- 抽样 `BNX`：on1_JT 部分 = JT00 的权重 × 62 / 70；BN 行合计 8 / 70（每批期望 8 行，在可用 BN 行上均匀；JT00 的留出 log 上的 BN 行权重 0）。
  即每批的 on-policy 抽取里旧部分少 8 行，其余照旧。

## 7. 读数与闸

- 读数（全部 `--after` 串在训练后）：大考场 held 划分**原生**（不加 hold，`jt.sh aread <tag> off <c>`，18 块）；held 460 @18（`rm_chain.sh read`，6 块）。
- **闸（固定）**：大考场原生 `BNX − BNC` 配对 **≥ +0.01 且 CI 下界 > 0**（按 log 聚类 bootstrap，排除任一方 route-fail 的窗），**且** held 460 零分
  `zeros(BNX) ≤ zeros(BNC) + 2`。
- 只报（不进闸）：static / launch 层（及其余层）的配对与新增 / 修好的零分；零分类型；两臂对存档 `JTN-L18-s1@off` 的配对（续训本身的效应）；
  held 460 的配对、at-fault / offroad / 横向零分 / 蠕行 / 不起步。
- **读法（先写下）**：过闸 = 评分器选出的自己的动作作为目标，在短续训里给了原生增益 → 下一步第二个 seed、看胜者分布决定是否扩 N / 扩窗、全长臂。
  不过闸 = 这个剂量（约 4 千行、每批 8 行、2 000 步、一轮）看不到增益；不关这条范式，但不在它上面加量，除非层读数指出具体机制。1 seed。
