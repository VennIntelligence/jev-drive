# vlm_cmp: Qwen3-VL-4B against Qwen3-VL-8B as the slow-channel model (pre-registration)

2026-10-03. Offline only: saved CARLA frames, no CARLA, no closed loop. Written and committed before any answer of this study was read.
The only model outputs looked at beforehand are the 13 frames of a plumbing smoke run (cache path equals full forward, shapes, speed),
not used for any choice below; the prompts, the directive mapping and the selection were frozen before that run and were not changed
after it. Code: `scripts/vlm_cmp_*.py`. Result: `results/vlm_4b_vs_8b.md`. Design context: `tmp/2026-10-02-vlm-arb-next.md` sections 1-3
(prompt-borne conventions, two frames plus the previous directive, release timing) and `results/vlm_thin.md` (what exists for the 4B).

## 1. Question

Which size should be the slow-channel model of the driving stack, 4B or 8B? Measured once, on the same frames, with the same code path
for both, offline: (1) zero-shot reading by one forward pass with option scoring, (2) one "directive" prompt in place of separate questions,
(3) two frames (the current one and the one 1 s earlier) with the model's previous directive stated, (4) frozen features and a linear head
per layer (in-domain supervised, kept apart from the zero-shot rows), (5) a paired 4B-vs-8B table with latency and memory. A difference
inside the noise is reported as such; no winner is picked that the data do not support.

## 2. Data

**All framed requests**: every answered request of every unit under `$DATA_DIR/runs/vlm_arb/arms/*/attempts/*/*/` that has both camera
frames (`vlm_frames/<t>_wide.jpg`, `_road.jpg`, 1928 x 1208) and a `gt` block in `vlm_decisions.jsonl`: **33 806 requests, 21 routes, 42
units, 214 attempts** (earlier studies used the 3 281 requests of 4 units). The truth columns are the logged `gt` (ego light state and
distance to its stop line, all lights logged, stop-sign distance, block state and distance, bypass side, lead gap and speed, distance to
the next junction entrance) plus the ego speed of the arbitration step at the same instant. The route-level splits are the registered
`b2d/vlm-thin-{train,val,test}` v1 (9 / 4 / 8 routes), unchanged; the 21 routes are the same 21.

**Core set (what is run)**: measured cost of the 4B is 1.8 s per frame for the four resolutions with five questions each (13-frame smoke
run, includes warm-up); the 8B is expected near 3.3 s. All 33 806 requests would take about 48 h per card, so the core set is a
deterministic subsample (`vlm_cmp_frames.select`, no model output involved): per category a quota, spread evenly over routes (water-filling:
routes with fewer items keep all of them) and then evenly over time inside a route; a request in several categories is kept once. Every
route is kept; every event instant (yellow onset, red onset, red to green) is kept; hold frames are subsampled (the logged holds are 40-s runs of near-identical frames).

| red_A | ego light red or yellow, -5 <= dist < 50 m, front bumper before the stop line | 150 (4025) |

Position of the car (the split that decided the false releases in `release_replay.md`), from the logged gt fields: **A** front bumper
before the light's stop line (`tl_dist > 0`), **B** past the line and the junction not yet entered (`tl_dist <= 0`, `junc_dist > 0.01`),
**C** inside the junction (`junc_dist <= 0.01`). The replay computed the same classes from route progress; counts differ slightly.

Result (see `frames.csv` of the run): 1 263 requests, 21 routes (test 528, val 265, train 470), 1 197 with an earlier frame, **696 two-frame
instants** (every event instant, every 2nd request of the categories cones, vehicle, moving_lead, lead_*, hold, red_BC, green_BC,
junction_slow, every 3rd of the rest). Stop-sign requests exist on two routes only (9196, 17280, both in test); pass_right is the
truth of 0 core requests and wait of 7; the core set thus cannot score the bypass side beyond left_free. Stated before reading.

## 3. Directive truth (written before any answer was read)

Per request, in this priority order (`vlm_cmp_frames.directive`): ego light red or yellow within -5..50 m, then ego green within the range,
then a stop sign within 25 m, then a static block, then a moving lead, then a junction ahead, else `proceed`.

| condition | primary | accepted (when ambiguous) | note |
|:--|:--|:--|:--|
| ego red / yellow, dist >= 0 | stop_at_line | stop_at_line | strict |
| ego red, dist < 0 (past the line) | stop_at_line | + proceed | `red_past_line`: cannot stop before the line any more |
| ego yellow | stop_at_line | + proceed, slow | `yellow`: a comfortable stop depends on speed |
| ego green, ego speed < 1.0 m/s | go_now | go_now | strict |
| ego green, moving | proceed | proceed, slow, go_now | `green_moving`: slow vs proceed is a style choice |
| stop sign within 25 m, speed >= 1.0 | stop_at_line | stop_at_line | strict |
| stop sign within 25 m, speed < 1.0 | stop_at_line | + go_now | `sign_stopped`: the log does not say if the full stop is done |
| static block on a cones / vehicle route | pass_left if side = left_free, pass_right if right_free, wait if none_free | same | strict |
| static block on another route (queue) | same as above | + wait, slow, proceed | `block_not_a_scenario` |
| moving lead | proceed | proceed, slow | `moving_lead` |
| junction entrance within 0-40 m, nothing above | slow | slow | strict |
| else | proceed | proceed | strict |

"Strict" accuracy = answered the primary on the rows with no ambiguity note; "accepted" accuracy = answered a member of the accepted set on
all rows. Where it is ambiguous: yellow, past the line, moving on green, a stop-sign car at rest, queues, moving leads (above); also,
`slow` vs `proceed` depends on a junction distance the model sees only in the image.

**Composition from the separate questions** (the reading to compare with, the arbitration the stack has today without its timing rules):
light answered red_or_yellow_for_ego -> stop_at_line; green_for_ego -> go_now if ego speed < 1.0 m/s else proceed; else sign yes -> stop_at_line;
else block static_block -> pass_left / pass_right / wait from the side answer (left_free / right_free / none_free); else proceed. Same
priority order as the truth. The questions say nothing about junctions, so the composition never answers `slow` (stated, not hidden: scores are given on all rows and on rows
whose truth is not `slow`). The composition uses the real ego speed, as the directive prompt does (its prompt states it).

## 4. Prompts (verbatim, frozen)

All prompts put the text after the images; the forced assistant prefix is `ANSWER:`; options are scored by the log-probability of their first
token (log-softmax over the whole vocabulary); options that share a first token (`pass_left`, `pass_right`) add the log-probability of their
second token. The ego speed is formatted `%.1f m/s`, with ` (stopped)` below 0.5 m/s. The light prompt is the `four` prompt of
`vlm_thin_common` and the vred server, character for character.

**light**

```
The two images were taken at the same instant by the front cameras of a car (the ego vehicle): image 1 is the wide-angle camera, image 2 is the narrow road camera.
Traffic light status controlling the ego vehicle lane ahead. Options:
  no_light: no traffic light controlling ego lane ahead
  red_or_yellow_for_ego: red or yellow traffic light controlling ego lane ahead
  green_for_ego: green traffic light controlling ego lane ahead
  light_for_other_lane: traffic light visible but controlling another lane, not ego lane
End your reply with one line of the form `ANSWER: <option>`, <option> being one of: no_light, red_or_yellow_for_ego, green_for_ego, light_for_other_lane. Reply with that line only.
```

**sign**

```
The two images were taken at the same instant by the front cameras of a car (the ego vehicle): image 1 is the wide-angle camera, image 2 is the narrow road camera.
Is there a stop sign controlling the ego vehicle ahead at the intersection?
End your reply with one line of the form `ANSWER: <option>`, <option> being one of: yes, no. Reply with that line only.
```

**block**

```
The two images were taken at the same instant by the front cameras of a car (the ego vehicle): image 1 is the wide-angle camera, image 2 is the narrow road camera.
Obstacle status in the ego vehicle travel lane ahead. Options:
  clear: clear path ahead in ego lane
  moving_lead: moving vehicle or dynamic object moving ahead in ego lane
  static_block: stationary obstacle, construction cones, or stopped broken vehicle blocking ego lane
End your reply with one line of the form `ANSWER: <option>`, <option> being one of: clear, moving_lead, static_block. Reply with that line only.
```

**side**

```
The two images were taken at the same instant by the front cameras of a car (the ego vehicle): image 1 is the wide-angle camera, image 2 is the narrow road camera.
If there is a blockage ahead, which adjacent lane is clear and safe to bypass? Options:
  left_free: left adjacent lane is clear and available for bypass
  right_free: right adjacent lane is clear and available for bypass
  none_free: neither adjacent lane is clear, or no adjacent lane exists
End your reply with one line of the form `ANSWER: <option>`, <option> being one of: left_free, right_free, none_free. Reply with that line only.
```

**dir**

```
The two images were taken at the same instant by the front cameras of a car (the ego vehicle): image 1 is the wide-angle camera, image 2 is the narrow road camera.
You are the slow decision channel of a driving stack. Driving conventions:
- Approach a junction slowly.
- The traffic light that faces you across the junction governs you: red or yellow means stop before the line, green means go. Ignore lights that face other directions.
- A stop sign means a full stop at the line, then go.
- A stationary object blocking your lane is passed on a free side; if neither side is free, wait.
Ego speed: 0.0 m/s (stopped).
Choose exactly one directive:
  proceed: keep driving normally
  slow: reduce speed and approach carefully
  stop_at_line: stop before the line ahead (light or sign) and stay there
  go_now: start moving or drive through now, the way is open
  pass_left: pass the blocking object on the left
  pass_right: pass the blocking object on the right
  wait: stay stopped, you are blocked and cannot pass now
End your reply with one line of the form `ANSWER: <option>`, <option> being one of: proceed, slow, stop_at_line, go_now, pass_left, pass_right, wait. Reply with that line only.
```

**dir_2f (previous directive stop_at_line)**

```
Images 1 and 2 were taken about 1 second ago by the front cameras of a car (the ego vehicle): image 1 is the wide-angle camera, image 2 is the narrow road camera. Images 3 and 4 were taken now by the same two cameras, in the same order. Compare the two moments: a traffic light that changed, a vehicle ahead that moved or stayed still.
You are the slow decision channel of a driving stack. Driving conventions:
- Approach a junction slowly.
- The traffic light that faces you across the junction governs you: red or yellow means stop before the line, green means go. Ignore lights that face other directions.
- A stop sign means a full stop at the line, then go.
- A stationary object blocking your lane is passed on a free side; if neither side is free, wait.
Ego speed now: 0.0 m/s (stopped).
Your previous directive, about 1 second ago, was: stop_at_line.
If your previous directive was stop_at_line for a light, keep it until the light facing you is clearly green.
Choose exactly one directive:
  proceed: keep driving normally
  slow: reduce speed and approach carefully
  stop_at_line: stop before the line ahead (light or sign) and stay there
  go_now: start moving or drive through now, the way is open
  pass_left: pass the blocking object on the left
  pass_right: pass the blocking object on the right
  wait: stay stopped, you are blocked and cannot pass now
End your reply with one line of the form `ANSWER: <option>`, <option> being one of: proceed, slow, stop_at_line, go_now, pass_left, pass_right, wait. Reply with that line only.
```

**light_2f**

```
Images 1 and 2 were taken about 1 second ago by the front cameras of a car (the ego vehicle): image 1 is the wide-angle camera, image 2 is the narrow road camera. Images 3 and 4 were taken now by the same two cameras, in the same order. Compare the two moments: a traffic light that changed, a vehicle ahead that moved or stayed still.
Traffic light status controlling the ego vehicle lane ahead. Options:
  no_light: no traffic light controlling ego lane ahead
  red_or_yellow_for_ego: red or yellow traffic light controlling ego lane ahead
  green_for_ego: green traffic light controlling ego lane ahead
  light_for_other_lane: traffic light visible but controlling another lane, not ego lane
End your reply with one line of the form `ANSWER: <option>`, <option> being one of: no_light, red_or_yellow_for_ego, green_for_ego, light_for_other_lane. Reply with that line only.
```

**block_2f**

```
Images 1 and 2 were taken about 1 second ago by the front cameras of a car (the ego vehicle): image 1 is the wide-angle camera, image 2 is the narrow road camera. Images 3 and 4 were taken now by the same two cameras, in the same order. Compare the two moments: a traffic light that changed, a vehicle ahead that moved or stayed still.
Obstacle status in the ego vehicle travel lane ahead. Options:
  clear: clear path ahead in ego lane
  moving_lead: moving vehicle or dynamic object moving ahead in ego lane
  static_block: stationary obstacle, construction cones, or stopped broken vehicle blocking ego lane
End your reply with one line of the form `ANSWER: <option>`, <option> being one of: clear, moving_lead, static_block. Reply with that line only.
```

Two-frame variant: images in the order previous wide, previous road, current wide, current road; the previous directive is the model's own
answer to the single-frame directive prompt at the previous frame (with that frame's speed). Question prompts as above with the first
sentence replaced as shown (`light_2f`, `block_2f`, `dir_2f`). Resolutions: 559 / 1153 / 2335 / 4573 visual tokens for two images at 4B
token counts (max pixels 300 000 / 600 000 / 1 200 000 / native, per image), the same for both models; the two-frame run only at r1153
(four images, about 2300 visual tokens); r559 not run (cost; the 4-image r1153 prompt is no larger than the single-frame r2335 one).

## 5. Readouts and statistics

Zero-shot, per model and resolution, on the core set (cell = estimate [95% route-cluster bootstrap CI] hits/n, 2000 resamples, seed 0,
`vlm_arb_common.boot_ratio`):
- light: ego red answered red (by distance 0-20 / 20-50 m and by position A / B / C), red answered green, ego green answered green (by position),
  another-direction red answered red (ego not red), no light at all answered red; `light_for_other_lane` counts as not red and not green.
- sign: yes within 25 m, yes with none within 80 m, yes at 25-80 m (listed). block: static_block recall overall and per route kind (cones /
  stopped vehicle / other), clear answered static_block, moving_lead recall, stopped lead (block clear or static, lead < 0.5 m/s) answered
  static_block. side: correct among static_block requests with a side truth (left_free is 99.2% of the truth of the static-block requests among all framed ones: a
  constant answer scores the same; said in the table).
- directive: accuracy per true directive (strict and accepted), the confusion table, versus the composition on the same rows; paired
  difference model 8B - 4B and directive prompt - composition (same frames, route-cluster bootstrap, `jevdrive.stats.paired`, B = 10000, seed 0).
- two frames, on the 696 instants, same instants for the single-frame numbers: directive accuracy (strict, accepted); yellow onset: directive stop_at_line and
  light answered red_or_yellow among ev_yellow_onset and ev_red_onset instants; red to green after holding: directive go_now and light answered green among
  ev_red_to_green instants with ego speed < 1.0 m/s at the previous frame; stationary vs moving lead: Q_block answered static_block on stopped-lead rows
  (lead < 0.5 m/s), answered moving_lead on moving-lead rows, split by ego moving or not, and directive accuracy on vehicle-kind block rows.
- Latency: p50 / p95 / p99 (n = 100 core instants with an earlier frame, evenly spaced over the sorted ids, JPEG bytes in host memory to the
  answer on the host, batch 1, 5 warm-up requests discarded, one process alone on GPU 0, nothing else on that card), peak allocated GPU memory
  per variant (`torch.cuda.max_memory_allocated` after a reset; weights listed separately). Variants: `q1_<res>` one question in one forward pass with no cache (the path
  of the closed loop), `dir_<res>` directive prompt (prefill + suffix), `four_<res>` the four separate questions on one shared prefill, `two_<res>` the
  two-moment directive, `cut_<res>_<N>` first N language layers (answer-position state, linear head cost not included).

Frozen features: for each model and resolution, the answer-position hidden state after layer N (N = 2, 4, ..., 36; 36 = normed final state)
of the light, sign, block and directive prompts and the per-camera mean of the image tokens at layer N (0, 2, ..., 36). Linear heads exactly as
`vlm_thin_fit.py` (class-balanced multinomial logistic regression on standardised features, LBFGS, lambda in {1e-3 ... 10} by validation
balanced accuracy), train = train routes, test = test routes, plus the 7-fold route-grouped CV over all 21 routes (fold = rank of the route id
mod 7, route 17280 moved to fold 3 so that the two stop-sign routes are in different folds; lambda of the primary split). Labels: light
(red / green / none as in vlm_thin), sign (near yes / none), block (clear / moving_lead / static_block), lead (stopped vs moving among rows with
a lead). **Readable layer** of a label = the smallest N whose CV balanced accuracy is within 0.05 of the best layer's, if that best is >= 0.70
(else "not readable"), read per model and source (answer-position of the question's own prompt; pooled image tokens) at r1153 and r559; reported with
the test balanced accuracy at that layer, the zero-shot balanced accuracy of the same label on the same rows, and the measured latency of the cut.
Rows of a head table are in-domain supervised (fitted on CARLA frames), shown in their own table and never mixed into the zero-shot tables.
The registered split cannot fit a sign head (no positive in train or val: both sign routes are test routes); the CV is the only sign read and
rests on two routes.

Summary table (section 5 of the brief): every capability row at r1153 (the resolution of the closed-loop server) with 4B and 8B estimates, the
paired difference with its CI, and the latency ratio; the resolution sweep of the key rows follows. A difference whose CI contains 0 is called noise.

## 6. Estimate, cards, staged launch

Box: 3 GPUs; GPU 2 is the user's and is never touched; GPU 0 is used; GPU 1 only if `nvidia-smi` shows it idle at launch (another agent runs
a small job there at times). Estimated per card: extraction 4B 1 263 x 1.8 s = 38 min, 8B 1 263 x 3.3 s = 70 min; two-frame 696 x about 1 s (4B) and
2 s (8B) = 12 + 23 min; heads 20-30 min (eight fits in parallel); latency bench about 30 min with nothing else on GPU 0; total about 3 h on one
card, about 2 h if the 8B runs on a second idle card. Staged launch: smoke run on a few frames end to end (`--limit`), then the real run.
One chain script `scripts/vlm_cmp_chain.py` (Run: STATUS / DONE / ERROR; stages skipped when done; per-chunk caches via `jevdrive.cache`).

## 7. Known limits, stated before the run

- The core set is a quota sample, not the logged distribution (hold and queue frames are down-weighted, events are all kept): rates are rates of
  the sample; route-cluster CIs with 21 routes (test-only rows with 2-8) are wide.
- Several units re-run the same routes with different arms: frames of one route are correlated; the bootstrap resamples routes.
- Both stop-sign routes are test routes; pass_right is not in the core set; wait has 7 requests.
- One prompt wording per question, no prompt search; the directive prompt states the ego speed (the stack has it), nothing else about the scene.
- The 4B features of earlier studies (light prompt, native layer grid) are not reused: both models go through the same code path; the
  light option scores of the 4B are compared with the earlier cached ones on the overlapping frames as a check, not as data.
- Offline readings say nothing about closed-loop behaviour.
