# 预登记与执行计划：VLM 慢通道 + 仲裁表（红绿灯、stop sign、路口降速、绕行）

2026-10-02。本文件为 `experiments/vlm_arb` 的预登记文件，在任何正式闭环运行结果产出之前锁定、commit 并 push。

---

## 1. 核心问题

冻结的 openpilot Cinque 在 CARLA Bench2Drive（B2D）闭环中缺乏三类高级决策能力：为自己车道的红灯和 Stop sign 停车、进路口前降速、绕过本车道的静止障碍。先前的特权上限诊断（第 82 条决定 [082.md](../../../research/decisions/082.md)）表明：
- 特权红灯 + 绿灯放行在 3 条目标路线上取得 **+20 DS**（75.0 → 95.0），且官方违规 5 → 1；
- 特权绕行（`pbyp`）让施工路线完成度从 **31.9% 提升到 100%**，但绕过障碍物后仍发生碰撞；
- 三项特权规则简单叠加（`pall`）时，碰撞从 5 次暴增到 17 次，规则互相干扰导致收益被吞噬。

本实验的总体设计思想：**不训练任何模型，不让大模型端到端输出轨迹**（第 42、44 条决定已证明 zero-shot 输出轨迹抖动有害）。把「特权真值决策」替换为一个看相机的视觉语言模型（VLM）慢通道，回答离散选择题；决策输入到 op-drive 的**仲裁层（Arbitration Layer）**，openpilot 继续承担 20 Hz 快通道的轨迹控制与低级避障。

回答三个核心问题：
1. **感知与归属能力**：VLM 在 CARLA 的前视相机帧上能不能答对这几类决策，特别是“当前红灯是否管本车道（ego）”，以及 Stop sign 和前方静止障碍物；
2. **闭环收益保留率**：考虑端到端推理时延和感知不确定性后，特权版本的上限收益能保留多少：$(\text{VLM} - \text{drive}) / (\text{Privileged} - \text{drive})$；
3. **仲裁表协同**：将五条规则（R1–R5）放入一张带有明确压制与兜底机制的仲裁表中，能否消除 `pall` 出现的互伤负交互。

## 2. 仲裁表设计（核心协议与固定参数）

### 2.1 架构原则
- **决策与归属来自 VLM，空间位置来自地图与自车里程计**。VLM 不预测连续公制距离；
- 停止线位置取地图路线上前方下一个路口入口（导航路网信息，不属于特权感知）；
- 障碍物的位置与横移几何沿用 `pbyp` 的真值几何（本实验量的是“感知决策替换”，不量“3D 检测定位替换”，这一点在读法中明确声明）；
- **延迟必须进入仿真时间**：CARLA 为同步模式，若不注入时延则相当于给 VLM 开了无限推理时钟。设阶段 A 实测单请求延迟 p95 为 $L$，则在 $t$ 时刻采样的相机帧，其 VLM 答案严格在仿真时间 $t + L$ 之后才允许被仲裁层读取。

### 2.2 四道选择题与选项定义
每隔 0.5 s 仿真时间，向 VLM 发送一组前视相机图像并请求回答以下四题：

| 题目 | 选项 | 语义定义 |
|:---|:---|:---|
| **Q-light** | `no_light` | 前方无交通信号灯控制本车道 |
| | `red_or_yellow_for_ego` | 存在红灯或黄灯控制本车道 |
| | `green_for_ego` | 存在绿灯控制本车道 |
| | `light_for_other_lane` | 画面中有灯，但控制的是其他车道（非本车道） |
| **Q-sign** | `yes` / `no` | 本车道入口处是否存在生效的 Stop sign |
| **Q-block** | `clear` | 本车道前方道路畅通 |
| | `moving_lead` | 前方有正常移动的跟驰前车或动态物体 |
| | `static_block` | 本车道前方有静止障碍物、施工锥桶或故障静止车辆 |
| **Q-side** | `left_free` | 左侧相邻车道畅通可用 |
| （仅在 Q-block 为 static_block 时评估） | `right_free` | 右侧相邻车道畅通可用 |
| | `none_free` | 两侧均不可借道，或无可用车道 |

### 2.3 仲裁表规则（R1–R5）与防冲突压制机制

| 规则 | 触发条件 | 信号来源 | 执行动作 | 通路 | 放行条件 | 压制关系 |
|:---|:---|:---|:---|:---|:---|:---|
| **R1 `jslow`** | 路线前方 $N$ m 内有路口入口，直到驶出路口 | 地图路网 | 限速 $v_j$ | base governor cruise cap | 驶出路口 | 无 |
| **R2 红灯** | `Q-light == red_or_yellow_for_ego` 连续 $K$ 次 | VLM | 在路口停止线前停住 | 现有 IDM stop profile | `Q-light == green_for_ego` 连续 $K$ 次；`no_light` 不放行 | 无（最高优先级） |
| **R3 Stop sign** | `Q-sign == yes` 连续 $K$ 次 | VLM | 在路口停止线前停满 $T_s$ | 现有 IDM stop profile | 停满 $T_s$ 秒立即放行；每个路口仅触发一次 | 被 R2 压制 |
| **R4 绕行** | `Q-block == static_block` 且 `Q-side != none_free` 连续 $K$ 次 | VLM 决策 + 局部几何 | 生成平滑变道平移路径绕障并回正 | 现有 `pbyp` P7 跟踪 | 完成回正回到原路线 | 被 R2、R3 压制；路口内及入口前 $N$ m 严禁启动 |
| **R5 兜底** | 任意停车约束持有超 $T_{max}$，或 VLM 答案超过 TTL 过期 | 计时器 | 撤销 VLM 停车约束，恢复基础控制 | R1 resume 2s 窗口 | 恢复车速 $> 1$ m/s 后重置 | 最高兜底权限 |

### 2.4 预登记锁定参数（不可事后调整）
- $N = 25.0$ m（路口减速响应距离）
- $v_j = 4.5$ m/s（路口内部巡航上限，约 16.2 km/h）
- $K = 2$（连续一致判定次数，防止单帧闪烁）
- $T_s = 2.5$ s（Stop sign 强制停等时间）
- $T_{max} = 25.0$ s（单次停车最大容忍时间，防止死等卡死）
- $\text{TTL} = 2.5$ s（VLM 决策最大有效时效）
- $L = 0.5$ s（预估基准延时，阶段 A 实际 p95 实测更新并在阶段 B 锁定）
- `cruise_base` = 8.0 m/s，`idm_s0` = 2.5 m，`idm_T` = 1.2 s，`idm_b` = 2.0 m/s²

## 3. 多模型设计与阶段 A（Shadow 离线/半在线评测）

为全面评估大模型作为自动驾驶慢通道决策者的能力，本实验设计覆盖多模型横向对比：
1. **OpenJev (DiffusionGemma-26B-A4B-it-NVFP4)**：基于 vLLM 定制内核的 System One 决策服务，原生输出各选项概率与置信度；
2. **DiffusionGemma-26B (原生多模态生成)**：直接调用模型生成文本答案并结构化解析；
3. **Qwen3-VL-4B-Instruct**：紧凑型开源 SOTA 视觉语言模型；
4. **Cosmos-Reason2-8B**：物理世界推理与感知大模型；
5. **AutoVLA (Qwen2.5-VL-3B)**：轻量级自动驾驶 VLA 模型。

### 3.1 阶段 A 执行流程
在 58 条评测路线上跑 `drive`（不控车，shadow 模式），每 0.5 s 仿真时间录制保存模型输入的三摄图像，并记录真值上下文（`_ctx` 灯态与距离、自车道 Stop sign、前方静止障碍物及邻道占用状态）。

对保存的真实 CARLA 帧运行上述各模型，按路线聚类 Bootstrap（2000 次，seed 0）计算：
- **Q-light 混淆矩阵**：
  - 自车红灯召回率（Recall，距离分档：0–20m, 20–50m）；
  - 邻道红灯被误判为自车红灯的比例（False Positive on other lane）；
  - 无灯场景误停率（False Stop Rate on no_light）；
- **红灯转绿放行延迟**：绿灯亮起后模型首次连续 $K$ 次判定为绿灯的时延；
- **Q-sign / Q-block / Q-side 准确率与误报率**；
- **推理耗时分布**：各模型在 batch 1 条件下的 p50、p95、p99 延迟与显存占用。

### 3.2 阶段 A 预登记准入门槛（入围阶段 B 闭环的条件）
- **红灯题 Q-light**：自车红灯召回率 $\ge 80\%$；邻道红灯误触发率 $\le 10\%$；无灯场景误报率 $\le 2\%$；
- **Stop sign 题 Q-sign**：召回率 $\ge 70\%$，误触发率 $\le 5\%$；
- **静止障碍题 Q-block**：静止障碍召回率 $\ge 80\%$；
- **推理时延**：单请求 p95 延迟 $\le 600$ ms（确保时延注入后不破坏控制稳定性）。
哪道题不达标，阶段 B 对应闭环臂不予开启；若全部通过，优先选择综合指标最高且时延稳定的模型主导阶段 B 全闭环评测。

## 4. 阶段 B：闭环评测设计

### 4.1 评测臂定义
所有臂均建立在冻结的 openpilot Cinque 与 R1 resume 基础上：
- `drive`：基线基准（Cinque 原生横向 + 基础纵向）；
- `dslow`：对照臂，无仲裁规则，通过 `cruise_by_route` 将全路巡航限速降到与 `jslow` 相同的均速，用于剥离“路口降速”与“全路变慢”的贡献；
- `jslow`：仅开 R1（地图路口降速）；
- `vred`：开 R2 + R3 + R5（VLM 红灯 + Stop sign + 兜底）；
- `vbyp`：开 R4 + R5（VLM 障碍物绕行决策 + 兜底）；
- `vall`：开整张仲裁表（R1–R5）；
- `pred`, `pbyp`：特权上限对照（沿用第 82 条特权臂结果，计算收益保留率）。

### 4.2 评测路线（58 条，DEV 10 条 + 48 条针对性场景路线）
为保证每项技能在非目标路线上测无害、在目标路线上有充足机会：
- **Dev 10 条**（必跑）：`27043, 15102, 24944, 27870, 22535, 37969, 24497, 27297, 9196, 28147`（覆盖各类经典场景）；
- **Junction 补充路线 24 条**：涵盖非信号灯左转/右转、让行车、信号灯左转/右转、T字路口、汇入车流等；
- **Obstacle 补充路线 24 条**：涵盖事故车、施工障碍、双向施工、路侧违停等；
- 每条路线跑 2 个交通 seed（seed 0, 1），总计 58 条 × 2 seed。

### 4.3 读数口径与预登记判定线
- 统计量：DS（Driving Score）、RC（Route Completion）、官方违规次数（碰撞、红灯、Stop sign、卡死、超时）、平均车速；
- 所有配对差均为相对同 route/seed 的 `drive` 的配对差，按路线聚类 Bootstrap（2000 次，seed 0，95% CI）。

**预登记判定准则**：
1. **无害线（Safety on non-target routes）**：
   各单项臂在非目标路线上相对 `drive` 的配对 DS 差 CI 下界 $\ge -5.0$，且新增官方卡死为 0、新增碰撞为 0；
2. **有用线（Efficacy on target routes）**：
   - `vred` 在含灯路线上官方闯红灯显著下降，DS 配对差 CI 下界 $> 0$；收益保留率 $(\text{vred} - \text{drive}) / (\text{pred} - \text{drive}) \ge 50\%$；
   - `vbyp` 在障碍路线上 RC 显著提升，完成绕行且回正；
3. **`jslow` 分离线**：
   比较 `jslow` 对 `drive` 与对 `dslow` 的配对差：若 `jslow` 仅胜 `drive` 但不胜 `dslow`，判定收益纯属“整体变慢”；若胜 `dslow`，判定路口针对性减速有独立价值；
4. **叠加防互伤线（Non-destructive arbitration）**：
   `vall` 官方总碰撞次数 $\le drive$ 的碰撞次数，且 DS 均分不低于最佳单项臂。

## 5. 执行与交付规约

- **分级推进**：
  1. 阶段 1：1 路线 × 1 臂（验证 checklist：延迟生效、停车与放行事件完整、平滑绕行几何、R5 兜底触发、无崩溃）；
  2. 阶段 2：~10 单位小批量验证；
  3. 阶段 3：全量 58 条路线自动化推进。
- **资源与调度**：
  - 调度通过 `python -m jevdrive.cl lease` 租用空闲卡，在 tmux 会话 `jev` 中使用 `scripts/tmux_run.sh` 运行；
  - 严格通过精确 PID 管理子进程，绝不执行 `pkill -f`。
- **录像留存**：
  为每个 VLM 臂在远端留存至少一段成功和一段失败的追车相机视频（`.mp4`），并记录在交付表中。

### 6.1 接手时核实到的事实

- 旧链 `vlm_arb_chain.py` 串行跑 Phase B，只用 GPU 0 × 4 worker；Phase A 只读了 27043 一条路线 63 帧就进了 Phase B，没有检查任何登记线。
