## 3. B2D 闭环（2026-10-04，跑之前；已知的数：vmerge2 批里 shipped `drive` 的 seed 2 / 3，19 条路线，DS 均值 s2 65.9、s3 69.8，每条路线跨 seed 的 DS 标准差均值 3.4）

- **臂**：都是 vlm_arb 的 `drive` 臂（agent、控制器、配置不动），只换 openpilot 服务端：
  - `drive`（shipped）：不重跑，复用 vmerge2 批的 seed 2、3（`v2-drive-s{2,3}-q*`）。服务端和 agent 的改动在不设 `SRV_ONNX` / `OP_SEL` 时不生效，代码路径相同。
  - `od2it`：`SRV_ONNX` = it_dw3-s0 的 serving ONNX。
  - `od2sel`：再加 `OP_SEL=0.6`（d101 的比例；如果第 1 节重拟合给出别的 x，B2D 仍用 0.6，另一个 x 只在时间够时补跑，单列）。
- **选择器在 B2D 上的形式**（HUGSIM sel3 的移植，写在 op_arb_server.py 里）：速度 < 3 m/s 且缓冲的 5 s（100 帧 20 Hz）历史里有 ≥ 0.05° 的
  朝向变化时，第二个 session 看「原地转到参考朝向」的历史帧（绕相机竖轴纯旋转，出画面的像素填黑，同 HUGSIM）；参考朝向与当前朝向差
  ≥ 0.5° 或刚进入触发区时重建（reset + 重放缓冲），否则只把新帧转到参考朝向步进一次。它的 0–4 s 横向 plan std 之和 < 0.6 × 原生的才换
  plan（位置、速度、朝向、加速度、曲率；lead / meta 头仍用原生的）。与 HUGSIM 的差别：HUGSIM 每步都完整重放（5 Hz 仿真，代价低），
  这里用 0.5° 的参考朝向容差换算力；朝向来自 agent 自己的位姿滤波，不是真值。
- **冒烟**（路线 17280，seed 2）：`dbg-od2chk` 不旋转、每步重建，重放 plan 与原生 plan 的最大位置差 < 0.05 m（缓冲满之后）才算重放忠实；
  不过就把重建前的首帧预热（`OP_SEL_WARM`）加到 HUGSIM 的 100 步再查一次。`dbg-od2sel` 跑完、有触发、服务端 RSS < 40 GB、
  选择器单步耗时 p95 记下来。两个都过才放批量。
- **批量**：19 条路线 × seed 2、3，`od2it`、`od2sel` 各 6 个 unit（3 workers）。
- **读数**：DS、RC、碰撞与各类违规，按（路线, seed）配对、按路线 bootstrap 95% CI：`od2it − drive`、`od2sel − drive`、`od2sel − od2it`。
  分组同 vmerge2（障碍、红灯、stop sign、其他）。选择器触发率（低速步里 sel=1 的比例、真正换 plan 的比例）。
- **判读**（事先定）：`od2sel − drive` 的 DS CI 含 0 或为正 → 「B2D 上不掉」，d101 的 driver 在 B2D 成立；CI 上界 < 0 → B2D 掉分，
  写明掉在哪类路线。`od2it − drive` 同理。单个配对差的绝对值 < 3.4（drive 的 repeat 噪声）一律写「在噪声内」。
  不对 B2D 结果调任何参数；选择器比例、速度门、容差都按上面固定。
