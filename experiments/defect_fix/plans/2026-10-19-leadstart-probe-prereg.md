能不能看见、是 2 Hz 输入格式的限制（「眼睛看不见」）还是渲染 / 合成的限制（「渲染藏住了」）？规则（memory）：可见性只靠探针模型特征。
机制沿用第 362 / 373 条（`rf_stopprobe.boot_auc` / `fit_lin`、`redline_probe.fit_tok` 的 token 网络、log 分折、log 聚类 bootstrap）。

## 输入格式给的预期（sh30_core.py，写死在代码里，不是猜）

每次决策 t0（2 Hz）有 4 个真关键帧 K(t0 − 1.5 / 1.0 / 0.5 / 0)；8 个槽 t0 − 1.4 … t0（0.2 s）里只有槽 2（−1.0）和槽 7（0）是关键帧本身，
其余是最近关键帧沿自车轨迹的路面 backwarp（`op_interp.synth_cpu` 的 `src = i0 if s <= 0.5 else i1`）：槽 0 ← K−1.5，槽 1-3 ← K−1.0，
槽 4-5 ← K−0.5，槽 6-7 ← K0。合成槽里别的车不动。token 是图像对（槽 − 0.2 s，槽）上的编码，所以：
- 槽 7 的对（K0 的 warp，K0）里前车**没有运动**，只有位置；前车在两关键帧之间的运动只出现在跨源的对里：槽 6（K−0.5 → K0）、
  槽 4（K−1.0 → K−0.5）、槽 1（K−1.5 → K−1.0），且 0.5 s 的位移被压进 0.2 s。
- 前车在 (t0 − 0.5, t0] 起动（本登记的 0-0.5 s 箱）：只有源自 K0 的槽 6、7 带「动过」；0.5-1 s 箱再加槽 4、5；1-1.5 s 箱再加槽 1-3。
- **预期**：起动后第一次决策（0-0.5 s，前车只走了 0.3 m 到约 0.8 m）弱或读不出；某个槽的 AUC 只在它的源关键帧晚于起动的箱里上升。
  在起动发生前没有任何真关键帧带它：标签按决策时刻定义，这一条由构造成立，不检验。

- 前车（R1 / R2）：launch_diag 的规则，窗口起点 w0 上 |ey| < 1.8 m、车头前间隙 < 30 m 最近的车，再限 ≤ 15 m；要求它在 w0 是停着的
  （w0 后 0.5 s 位移 < 0.1 m），否则整窗不用（「前车已在动」）。轨迹按 track token 取 20 Hz 原始框。
- 前车（T）：每个 log 里自车 v0 < 0.3 m/s 的连续 2 Hz 段，段首 s0 上（自车坐标）x > 0、|y| < 1.8 m、间隙（x − l/2 − 4.049）在 −0.5…15 m 的最近车辆；
  要求它在 s0 后 1 s 内位移 < 0.15 m。轨迹按 track token。tv_census 的 G_L 事件数（1 403）只作对照报告。
- **标签**：位移 d(t) = 前车到它在 w0 / s0 处位置的距离；起动时刻 τ = d 首次 ≥ 0.3 m（R：20 Hz 帧；T：两帧间线性插值）；决策 / 帧 t
  标正 ⇔ d(t) ≥ 0.3 m；Δt = t − τ。
- **用哪些行**：自车站着（喂入的 v0 < 0.3 m/s，且 1.5 s 前那个历史位姿离 t0 < 0.3 m）；R 去掉 k = 0（force-GT、只有 1 个关键帧）；
  正例只要 0 ≤ Δt < 2 s；负例 = 起动前（Δt < 0，T 只取 −3 s 以内）以及整窗前车没到 0.3 m 的决策。
- 箱：Δt ∈ [0, 0.5)、[0.5, 1)、[1, 1.5)、[1.5, 2)（2 Hz 下每个起动事件每箱至多一行）。

## 特征集（每行；探针只用策略自己算的东西）

- **KIN** = 喂给 adapter 的 ego 行（20）+ 关键帧数 one-hot（R 的 k = 1、2 是冷启动；T 恒为 4）。
- **LEAD-RSG / LEAD-JTN1** = KIN + RSG-L18-s0 / JTN-L18-s1 在同一 token 上前向的 lead 均值（72）+ lead_prob（3）。route memory 一律置零
  （launch_diag 的 `--rm-drop` 输入；T 没有 route memory，三个来源一致）。判读用两者中较强的（保守）。
- **ACC 读数**（不拟合，直接当分数）：RSG 的 dRel = lead[0, 0, x] − 相机到前保险杠，vLead = v_ego + lead v − plan v(0)（serve_fix 的 radard 规则）；
  `ACC-v` = vLead；`ACC-dd` = dRel 减去同一窗 / 段里第一行可用行的 dRel。
- **TOK-s j**（j = 0…7）= KIN + 槽 j 的 32 × 512 token（redline 的网络：逐 token LN → 16 → MLP 256，batch 64，30 epoch，3 种子平均）。
- **TOK**（主）= KIN + 全部 8 个槽（同一网络，8 × 32 × 16 展平）；**TOK-lin** = KIN + 8 个槽各自的 token 均值，逻辑回归。
- 线性集：标准化逻辑回归，C = 0.1，balanced。
- 交叉拟合：每个来源单独，5 折 sha1(log) % 5；训练用该来源全部正负行，打分在没见过该 log 的折上；各箱的 AUC = 该箱正例对该来源全部负例。
  另报 R = R1 + R2 合并（折规则相同）。95 % CI：log 聚类 bootstrap，B = 2000，配对差同一组抽样。

## 判读（每个来源、每个箱，TOK）

- **可读**：AUC ≥ 0.75 且 CI 下界 > 0.60。**第一可读箱** = 「第几次决策看得出」的答案。
- **超出头**：TOK − LEAD ≥ +0.05 且 CI 下界 > 0；否则「不超过 lead 头」。
- **眼睛 vs 渲染**：比较 T 与 R（R1、R2、合并）同一箱：
  - T 可读、R 不可读 → **渲染 / 合成藏住了**（真相机同一 2 Hz 格式看得见）；
  - T、R 都不可读 → **2 Hz 输入格式（或编码器）看不见**；
  - 都可读 → 不是输入问题，是训练信号问题（第 373 条同型的结论）。
  - 该箱任何一个来源正例 < 20 行或 < 8 个 log：记「样本不足」，不判。
- **lead 头距离读数在第一秒变不变**（ACC 用的信号）：RSG 与 JTN1 的 dRel 相对同事件最后一次起动前决策的变化，在 0-0.5 s 与 0.5-1 s 箱的中位数
  （log 聚类 CI），对照日志框里前车同期位移；「变了」⇔ 中位变化的 CI 不含 0，且大于起动前相邻两次决策之间 |ΔdRel| 的 p90（读数自身的抖动）。
  同样报 vLead 与 lead_prob。

## 次要（全部先列出，只描述）
