## Setup and deviations from the shipped protocol

- Model, config and client: AFARI-Research/WA-JEPA at bec2966, `close_loop/hugsim_client.py` + `hugsim_planner.py` unmodified, launched through their own `scripts/evaluation/run_hugsim_ad.sh` (preflight included) by `experiments/hugsim/scripts/wajepa_e2e.sh`; weights `model_state_dict.pt` (epoch 139, step 112840), `configs/wa_jepa_hugsim.yaml` unmodified: `flow_inference_seed` 1, `num_inference_steps` 4 (the seed is re-applied in every call, so the sampling noise is the same at every step), fp32 weights under bf16 autocast, history stride 2 (0.5 s), 4 history frames, cameras FRONT_LEFT / FRONT / FRONT_RIGHT / BACK at 512x256, command map `[2, 0, 1]`. Median latency ~230 ms per step on the RTX 6000D; 0 inference fallbacks in all 64 runs; 6 padded-history steps at the start of every run (their buffer repeats the first frame; no pre-start history exists in HUGSIM).
- Run through our batch runner `experiments/hugsim/archive/zs_run.py` (new agent `wajepa`, ad slot `wj`; their docs use the `ltf` slot, which only selects which launcher path the simulator reads), scored by the simulator's own `hugsim_evaluate`, same 64 scenarios (`derot_all64.txt` = `scored.txt`), same 400-step cap, one run per scenario. Env `envs/wajepa` (torch 2.14+cu130, not their pinned versions).
- Environment: Python 3.10 uv venv built by `third_party/wajepa/jev_install.sh`; SAVE_VIZ=1 (per-step model inputs and plans archived, no effect on the plan).
- **Controller: our tree `HUGSIM-zs/fixed` (official + PR #57), not their monkey-patch.** Offline equivalence (`wajepa_ctrl_equiv.py`): their `traj2control_fixed` verbatim against our patched `traj2control` on 62 plans (zero, straight, jitter, random) with random ego states: max difference 0.0e+00. Their patch was not used.
- Compat patches: their `run_upstream_compat` was not applied. Our base trees already carry the same three release-compat fixes (`patches/hugsim/0003-release-compat.patch`) for every arm, including Cinque. **One further simulator crash** needed a patch: scene-3000_3200-medium-00 reached the route end ("Complete") at step 68 and then raised `IndexError` in `HUGSimEnv._get_info` (`commands[nearest_cam_idx]`, no `eval.json`). That scenario was rerun once in tree `fixedc` = `fixed` + `patches/hugsim/optional/command-index-clamp.patch` (index clamped to the last command); it completes with HD 0.867 in 69 steps. Its row is the only one with controller `fixedc` in the CSV; the crashed attempt is not in it. Cinque completes the same scenario in 51 steps without the crash.
- Cameras: all four render. CAM_BACK is an all-black image on KITTI-360 and Waymo (mean pixel 0.0 and 0.1) and a real image on nuScenes and PandaSet (99 and 104), as WA-JEPA's docs state; the front tile is ~100-109 everywhere. Nothing was filled in.
- Pool: all jobs went through the GPU pool. Card 0 carries a whole-card hold (`8c3c07`, "reserved for the user's other agent"); a `--gpus 0` job queued behind it and was cancelled, the runs executed unpinned on card 1 (instruction: keep it there).
- Cost: 64 scenarios, 2.2 h summed scenario wall time over 5-6 parallel workers, ~25 min of elapsed pool time in all (plus setup); 4.2 GB of run directories on the box (`runs/hugsim-wajepa`).

## Classes

Failure class of a run: `spin` (heading error >= 60 deg against the recorded route at some step; the definition of [controller_spin.md](controller_spin.md), `scripts/spin_analysis.py`, applied identically to both arms) takes precedence; otherwise the runner's end reason (`stuck` = max_steps, `bg_coll`, `fg_coll`, `off_route`, `complete`). A `complete` run can be labelled spin (Cinque: 1 of its 10 spins). Launch stall: peak speed over the first 40 steps below 1.6 m/s.

## What this says

- Our 64 reproduces WA-JEPA's published 436-scenario HD (0.451 vs 0.4462), so the set is not unusually easy or hard for a model that was trained on the HUGSIM-style data; it is the right size for model-vs-model comparisons with CI half-widths of ~0.1. Our LTF (0.279) is above their 0.2310 on 436 and cv (0.292) is above both LTF numbers, so the 64 is not harder than the 436 for the baselines (their published LTF number was produced with the unfixed controller, controller_spin.md section 1, so it is not a like-for-like reference).
- Cinque's HD gap to WA-JEPA is mostly standing still (7 of 16 reversals) and launch-time spin (3), i.e. the launch failures documented in launch_lean.md and op_control_stack_long.md. WA-JEPA never has a launch speed problem except two runs (2510_2710-hard, 021-extreme-02).
- WA-JEPA is not better where the scenario is about avoiding a hit: 26 fg collisions for both arms, extreme tier equal near 0.1. Its comfort is lower (0.833 vs 0.930) and its NC and TTC are lower (0.700 / 0.647 vs 0.791 / 0.741): Cinque's stuck runs (15) cannot collide, which probably explains part of its higher NC and Comfort [I].

## Caveats and open issues

- **The early-read gate was written after the subset ran.** The pipeline was chained (smoke, the 10 spinners, then all 64). When the gate was requested the 10 spinners' HD and end reasons and one-line results of 25 other scenarios had already been seen; the spin counts had not been computed. Subset members were then fixed by a rule on Cinque data only (10 spinners, the first 4 non-spinner Cinque failures in nuScenes / Waymo file order, the first 2 Cinque-complete easy scenarios). The first full job was cancelled after 25 of 54 and resumed; finished scenarios were kept. The gate passed (1 spin, subset HD 0.546 vs 0.365), so nothing in the run depended on it, but it is not a blind gate.
- One run per scenario and the closed loop is not deterministic across restarts; per-scenario differences below ~0.2 are not evidence. The CIs bootstrap scenarios (and, in T2, scenes); the 64 scenarios are 45 scenes.
- Cinque is the PR #57 `cinque-fixed` run of 2026-09-25 (HD 0.278), not rerun; its spin classification here uses `infos.pkl` and the same 60 deg rule (10 / 64, matches controller_spin.md T1). LTF / cv class columns are the runner's end reasons without the spin rule.
- WA-JEPA had a GT-route command (`info["command"]`, same source as the other arms' desire / nav) and the simulator's GT ego speed and acceleration; Cinque has no route input beyond desire and runs image-only. The comparison is "shipped WA-JEPA client vs our openpilot adapter", not model-only.
- The `fixedc` clamp affects only the step after route completion; the other 63 runs are tree `fixed`.
- Not done: no 45-degree spin sensitivity for WA-JEPA, no check of how many Cinque stuck runs would also be rescued by a GT route command.
