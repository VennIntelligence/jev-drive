# 第 9 轮 NTV1 S-NU：用学生自己的 nuPlan 滚动刷新 S 池（预登记，10-24，任何滚动输出之前写定）

用户批准用当前干净模型自己的滚动刷新 S 池（on-policy S，第 264 条的想法）；1 个 seed，不加 seed。代码：[../scripts/snu.sh](../scripts/snu.sh)（整条链一次提交）、
[../scripts/snu.py](../scripts/snu.py)（argv / 差异、配置比对、复现、池闸、合并核对、栅格核对、抽样文件、恒等比对、判定报告）。滚动 → 行 → token → 路线特征
复用 RB0-F-s0 建 `on1_L18RB0` 时的四个作业体，原样（`ol_chain.sh roll1 / geo / tok / strip`、`rm_build.py pool --workers 32`，作业环境为空，同 10-13 那次的池作业记录）；
侧向栅格复用 `df_lat.py build --dilate 6 --points ra --prefix`（L18NR1v2 的建法）。盒上 `$DATA_DIR/runs/round9/ntv1_snu/`；结果 [../results/ntv1_snu/](../results/ntv1_snu/)（英文）。
并行的 S-PAI 线（plans/2026-10-24-ntv1-spai.md）与清理线的文件不碰。

## 0. 学生

主会话定的规则：学生 = D3 = NT4D3-F-s0，除非 D3 两 seed 的 PAI 281 均分（新评分器、Harmonizer 关）低于 D1 两 seed 的 0.852，那时学生 = D1 = NT3D1-F-s0。
D3-s1 的 281 报告已出（第 475 条，[../results/ntv1_step4/s1_pai281.md](../results/ntv1_step4/s1_pai281.md)）：**D3 两 seed 均值 0.859 ≥ 0.852 → 学生 = D3 = NT4D3-F-s0**。
对照（登记线的基准）= D3-s0（0.879）。注意 D3 的 seed 差 s1 − s0 = −0.039，单 seed 的 ±0.015 线很弱，同时报对 D3 两 seed 均值的差。

## 1. 建池 S-NU（on1_L18D3，部分名 `d3s`）

- **滚动**：NT4D3-F-s0 在 onpol-train（1 031 个场景，`runs/onpol_long/lists/c0..c5.txt`，RB0 那次的同一份 6 块交错表）18 决策滚一遍：`ol_chain.sh roll1 NT4D3-F-s0 <i>`，
  每块一个池作业（--vram 32 --cpu 8 --ram 60，与 RB0 的 `ol-roll-RB0-<i>` 相同），nuPlan 默认 serve（不设任何 JEV_*；无 ACC / GAP / Harmonizer）。
  **分段启动**：先只滚 c0（172 个场景），过 c0 闸后再提交 c1–c5。
- **c0 闸**（`snu.py c0chk`）：(a) 配置与 RB0 的 c0 比对：driver / controller / eval / trafficsim 配置逐字相同；generated-user-config / wizard-config 只允许
  `n_concurrent_rollouts`、`sensorsim_cache_size`、`nre_cache_size`、`log_dir`、`baseport`、`localhost:<端口>` 这些行不同（10-13 c0b_chain.OVERRIDES 的吞吐改动：并发 8 → 4、
  缓存 9 → 5，不是 serve），其余任何差 = 停；(b) 172 / 172 个 rollout 有分、有 onpol_sim.pkl。
- **行**：`ol_chain.sh geo NT4D3-F-s0 L18D3`（on_rows geo + ol_labels build）→ `tok L18D3 smoke10eY`（token + 老师 + R1 / R2）→ `strip`（删 dump 的 `cur` 帧）
  → `rm_build.py pool --name L18D3 --workers 32`（route.npz + 路线记忆特征）→ 池 `on1_L18D3`。
- **静止行**：不排除。理由：当前抽样 JT00S-rb0（= JT00S 只留 rb0）对 rb0 的规则是「S 行里不在留出 log 上的行全部等权」，没有 < 0.5 m/s 的排除（第 377 条的规则没进 JT00S）；
  为了只改一个变量，新池用同一规则。`snu.py weights` 先在 on1_JTDC2 的 rb0 行上重算这条规则，必须逐行复现 NTV1D2 的 13 793 个非零 S 行（权重相同到 1e-12 相对）。
- **留出**：按 log，crc32(log) % 100 < 15（= `--on-hold-pct 15` 与 jt.py weights 的同一规则），留出 log 上的 d3s 行权重 0，训练器同样不抽。

## 2. 池的闸（全部在队列里；任何一个不过即停，下游作业随之失败）

- **R0 复现**（与滚动并行；`snu.py repro`）：用今天的代码在 RB0-F-s0 自己的存档滚动上重跑 `on_rows.py geo` 与 `rm_build.py pool`（临时名 `L18RB0X`），
  与存档 L18RB0 / on1_L18RB0 / feat 比：rows meta、all.npz、池 tab / agent / road / drivable、route.npz、路线特征的每个键，逐行相等（NaN 视为相等）的份额都 ≥ 0.99、形状相同。
  过了说明「今天的建池代码 = 当年建 rb0 的代码」。比完删掉 L18RB0X 的临时文件（只删本线自己的临时名）。
- **R1 输入复现、R2**（ol_labels gate 的 gates.json，与 rb0 的同一判据）：R1 (a) 一个 fp16 ulp 内 ≥ 0.99、(b) 解释控制、(c) 错 seed 控制（NT4D3-F-s1）< 0.20；
  R2 ego ≤ 0.3 m、他车 0.5 m 内 ≥ 0.9999。K0（kc 标签项）照报，不进规则（本配方不用 kc）。
- **池闸**（route_follow poolgate.py，原样）：行 ≥ 10 000、route ok ≥ 0.95、route0_share_005 ≥ 0.99；cov20 照报（rb0 0.461）。
- **合并**（rf_pait merge，`--nan-keys fut_reg`，token 零拷贝）：
  - **臂池 `on1_JTSNU`** = d3s + on1_JTDC2 去掉 rb0 后的 6 个部分，顺序 `d3s, rtb1, ys, y, tv, pd, pd2`（S 部分在最前，侧向栅格是前缀栅格）。
    `snu.py afix`：tab 键集合与 on1_JTDC2 相同；d3s 之后的每一行在 tab / agent / road / drivable / route / 特征 / 老师 / token 抽样上与 on1_JTDC2 的同名行逐位相同；
    d3s 行与 on1_L18D3 逐位相同。另记：on1_JTDC2 里 rb0 的 agent ok 与 on1_L18RB0 相同（S 部分没有合并后的修正，d3s 也不做）。
  - **恒等池 `on1_JTSNUZ`** = on1_JTDC2 的 7 个部分 + d3s（在最后）。`snu.py zfix`（dag.py mfix）：前缀与 on1_JTDC2 每个文件逐位相同、部分行数 = on1_JTDC2 的 + d3s。
    只供权重 0 恒等用，恒等比完即删。
- **侧向栅格 `SNUv2`**：`df_lat.py build --pool on1_JTSNU --rows L18D3:d3s,L18RTB1:rtb1 --dilate 6 --points ra --prefix`（覆盖 d3s + rtb1，与 L18NR1v2 覆盖 rb0 + rtb1 同形）。
  `snu.py latchk`：错误 ≤ 1 %；rtb1 那一段的 onc / soft / ok / own_found / junction_share 与 L18NR1v2 的 rtb1 段逐位相同（栅格建法复现）；d3s 与 rb0 的 ok、own 车道找到率、
  路口格子份额照报。`snu.py latgate`（df_lat gate 原函数）：人的日志路径上 hard 并集（onc 深 0 ∪ side 0.4 m）与 soft（深 0）的激活份额，各 ≤ 旧栅格（L18NR1v2，0.0176 / 0.0359）的 1.5 倍；
  served plan 上的激活照报。侧向开关 = D3 argv 里的原值，不随 gate 改。
- **抽样文件**（`snu.py weights` / `wcheck`）：
  - **NSNU**（臂）：d3s 的非留出行等权、份额 0.8（期望每批 32 行）；DAgger 行（pd / pd2）权重与 NTV1D2 同名行逐位相同（0.0995 / 0.1005）；其余 0；grp 同 NTV1D2 的约定（S / S_held / pd / pd2）。
  - **NSNUZ**（恒等）= NTV1D2 原样 + d3s 全 0。
- **argv 差**（`snu.py diff`）：臂的 argv 与存档 NT4D3-F-s0 的 argv 只差 `--tag`、`--on`、`--on-wfile`、`--lat-file` 四处；按 dg4.py 重建的 D3 argv = 存档。
- **G0b 臂的 T 前**：臂的 argv 跑到第 125 步，≤ 100 步全部标量与存档 NT4D3-F-s0 逐位相同。
- **权重 0 恒等**：D3 的 argv `--steps 60 --on-start 30`（T = 30）在 on1_JTDC2 / NTV1D2 与 on1_JTSNUZ / NSNUZ 上各跑一次，≤ 60 步全部标量逐位相同、池行真被抽到。
  - 这两条比对都**不比**训练器的留出池诊断 `pool_held/*`、`pool_fit/*`。原因：它们在第 0 步和最后一步从「全部 self 行」的留出 / 拟合样本上算，换了 S 行（G0b）或多了 self 行（恒等）就一定变。
  - 这些键单列、照报差异；其余任何标量不同 = 停。
- **冒烟**（臂的 argv 60 步、T = 30、`--on-mix-log`；dgc.py smoke --var b + p1l.py lrcheck）：批构成 75 / 13 / 40 mixed；T 前 S 行 0、T 后 S 份额 0.72–0.88；
  训练器记录的抽样组份额 = NSNU 的；S 项 T 后有限非零；lr 与公式一致。
- **训练中 / 后**：T 后 500 步 S / 模仿梯度比在 0.21–1.04（出带 → 取消、不读）；DONE、末步 dev ADE ≤ 0.566、整段 lr 对公式。

## 补记 1（10-24，提交后、任何滚动之前）

c0 闸的配置比对在一次干跑（RB0 的 c0 对一个更新的 nuPlan sh30 读数 NPB30-L18-s1）里发现 wizard-config 还有两类行不同：
- 本次运行目录的挂载路径；
- 渲染器的 `--cache-size=<n>`，与 `nre_cache_size` 是同一个 10-13 吞吐改动。

所以比对前先把两边各自的运行目录替换成同一个占位符，并允许 `--cache-size=` 行不同。其余判据不变：driver / controller / eval / trafficsim 四个配置逐字相同，
那次干跑里它们也逐字相同。

## 补记 2（10-24 19:30，建池之后、任何训练输出之前；主会话决定）

**失败.** 第 1 次的栅格 SNUv2 没过 latchk。其余子项都逐位相同（rtb1 段的 onc / ok / own_found / junction_share）。只有 soft 栅格在 17 489 个 rtb1 行里有 19 行
（3 个场景）与 L18NR1v2 不同，差异是整行的 soft 掩码。

**原因.** `df_lat.py build` 选「自己车道链」时依赖 Python 的字符串哈希顺序。`snu.py latdiag` 用 `df_lat.work` 原样重建这 19 行：
- `PYTHONHASHSEED=1` 时与 L18NR1v2 逐位相同；
- `PYTHONHASHSEED=0` 或不设时，与第 1 次的 SNUv2 相同。

见 [../results/ntv1_snu/latdiag_1.json](../results/ntv1_snu/latdiag_1.json)。

**修法（主会话选 b）.**
- 整张新栅格（d3s 与 rtb1 全部）在 `PYTHONHASHSEED=1` 下重建，写进 `snu.sh lat`，可复现。
- latchk 原样重跑，不放宽；latgate 也在新栅格上重跑。
- 之后按登记跑后半段：G0b、冒烟、训练、梯度比、训练后闸、PAI 281、val160、报告。
- 第 1 次的栅格和从未运行的读数目录移到 `$O/attempt1/`。
- 其余已过的闸不重跑：复现、R1 / R2、池闸、合并核对、抽样文件、argv 差、权重 0 恒等。它们与栅格无关。
