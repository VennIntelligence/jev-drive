# 第 9 轮 INTERP：NTV0 ↔ R8K 零训练权重插值（BCWI 式基线，描述性，10-24 夜，任何读数之前写定）

代码：[../scripts/interp.py](../scripts/interp.py)（合并 / 加载与前向检查 / 报告）、[../scripts/interp.sh](../scripts/interp.sh)（整条链一次提交）。
盒上 `$DATA_DIR/runs/round9/interp/`；结果 [../results/interp/](../results/interp/)（英文）。主会话按用户「今晚空卡做诊断」的授权派发；
不训练、不构建镜像、不提交。

## 1. 问题

[research/method-search/notes.md](../../../research/method-search/notes.md) 的 A-1：脆弱前沿锚定（FA）必须打赢的零训练基线。
θ = (1 − a) · θ_NTV0-L18-s0 + a · θ_R8K-L18-s2，a ∈ {0.5, 0.75}：插值能不能保住 R8K 的增益、同时去掉它在 NTV0 满分场景上的新坏？
这是基线，不是今晚的候选；不设读数线，只描述。

## 2. 合并（CPU，`interp.py merge`）

- 两个 checkpoint 的 `ckpt-final.pt` 结构已核：`model.net`（109 个可训练张量：策略的 temporal summarizer / hydra 头，以及 ONNX 图里
  被训练的 val_* 初始化量；共 16.2 M）与 `model.parity`（适配器 + 路线记忆分支 `route.*`，97 个张量，3.16 M）键集、形状、dtype（全 fp32）完全相同；
  R8K 没有多出的模块（`--twin PAIHTW:1.0` 是训练数据侧的孪生 token 换入，不加参数）。冻结的编码器不在 checkpoint 里，两者都从出厂
  Cinque 加载；检查时在加载后的模型上逐位比较所有不在 checkpoint 里的参数。
- 每个张量 (1 − a) · x + a · y（fp32），`net` 和 `parity` 全部插值；`adapter.pt` 写插值后的 parity（源里 adapter.pt 与 parity 逐位相同，已核）。
- 非张量（`cfg`、`onpol`、`route_mem` 头配置、`arm`）取 R8K 的（两者 `route_mem` 头配置 / `arm` 相同；`cfg` / `onpol` 只是训练记录，serve 不读），
  另加 `interp` 字段记 a、两个源和它们的 sha256。sidecar `route_mem.json`：两者 head / n_pt / nf / offs 必须相同（不同则停），复制 R8K 的并加 `interp`。
- 输出 `$DATA_DIR/runs/op_parity/runs/INTP50-NR`、`INTP75-NR`；另写 a = 0 / a = 1 的两个临时点 INTPCHK0-NR / INTPCHK1-NR 只供检查，检查后删除。

## 3. 检查（小 GPU 作业，`interp.py check`，不过则整条链停）

- 用 serve 的 `sh30_core.Core(tag)` 加载 NTV0、R8K、两个临时点、两个插值点（证明 serve 能加载）。
- 冻结参数：六个模型的全部非 checkpoint 参数逐位相同。
- 前向：4 组固定种子的随机帧 + 随机 ego / 路线记忆行，经编码器和策略；INTPCHK0 的输出与 NTV0、INTPCHK1 与 R8K 逐位相同；
  NTV0 重新加载一次再跑作为确定性对照；插值点输出有限且与两端都不同。

## 4. 读数

PAI 281 ACC + GAP、Harmonizer 关，与 R8K-L18-s2 存档读数（`round8/s2/pai281/R8K-L18-s2-ag`）相同：serve
`JEV_VCONT=1.0 JEV_LEAD=1 JEV_ACC=1 JEV_GAP=0.7,2.7`，wizard `controller.gains.rel_front_steering_angle_weight=10`，CONC 4，FAST，
NTV0 的 8 个 chunk 表。R8K 的 serve 与 NTV0 的完全相同（两份 config.txt 只差代码版本；无孪生 token / JEV_CMD 之类的 env，
孪生 token 只在训练时用、且只对 Harmonizer 开的状态），两个插值点都用这一份。每个点 8 个 chunk 作业 + `pai_fix.sh tax`。

## 5. 报告（`interp.py report`）

新评分器（scorer_v2 new，READS 加两条）为主，旧的同列。共同场景 = 四份读数都有分且都无 RPC 错误的场景。每个点：均分；
对 NTV0-s0、对 R8K-s2 的配对 bootstrap CI；零分数与零分类别（旧 facts 的 fclass，新评分器的零分数）；NTV0 满分场景
（NTV0-s0 ≥ 0.98）上的新坏数（该点 < 0.98），与 R8K-s2 自己的新坏数并列；以及 NTV0 未满分、该点满分的「修好」数（与 R8K 并列）。
