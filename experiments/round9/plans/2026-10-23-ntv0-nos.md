# 第 9 轮 NTV0-NOS：NTV0 的 +0.09 来自 S 行，还是来自续训本身（预登记，10-23，任何训练输出之前写定）

代码：[../scripts/nos.sh](../scripts/nos.sh)（整条链一次提交）、[../scripts/nos.py](../scripts/nos.py)（冒烟闸 / 恒等对照 / 判定报告）。
盒上 `$DATA_DIR/runs/round9/ntv0_nos/`；结果 [../results/ntv0_nos/](../results/ntv0_nos/)（英文）。

## 1. 问题

NTV0-L18-s0 在 PAI 281（ACC + GAP，Harmonizer 关）0.744，它的底座 RB0-F-s0 0.650（第 449 条，同块表同 serve；均为旧评分器）。中间的 L18 段一次改了
好几样：S 池 on1_JT（4 个老策略滚出的 on-policy 行，带 agent / road hinge 和侧向项），低 lr 续训 9 500 步（lr-scale 0.1、warm-up 500、lr floor 0.1），
历史速度噪声。问：+0.09 是 S 行带来的，还是续训本身（更多步数的 navtrain + yaw 模仿、低 lr、噪声）？这决定干净的单段配方（"NTV1"）能否完全离线，
还是需要自己滚的 on-policy 行。

## 2. 臂 NTV0NS-L18-s0（定的选择）

- **命令** = NTV0-L18-s0 存档 meta.json 的 argv（盒上 `runs/route_mem/train-NTV0-L18-s0/20261018-234030/meta.json`，代码 1599227，编译；已核对与
  `jt.sh ntv` / `train` 的拼法一致：ONK=32、JT00S、ARCROWS=brake、arc 0、9 500 步、seed 0、`--init RB0-F-s0`），只改三处。`nos.sh dry` 的逐词 diff：

  ```
  replace: --tag NTV0-L18-s0            -> --tag NTV0NS-L18-s0
  replace: --on-k 32                    -> --on-k 0        （第二个 --on-k；RSG 串里的 --on-k 13 本来就被它覆盖）
  delete:  --on-wfile runs/defect_fix/w/JT00S.npz
  ```

- **为什么这样删**：`--on-k 0` 时 on_train.setup 的 nN = 128 − 13 − 0 = 115，批仍 128，原来 32 个 S 槽由 navtrain 普通行补上（83 → 115），yaw-rate 13 行、
  历史速度噪声（只加在非 anchor、非池行上，现在 115 行都可能被加）、路线记忆 25 % 置空都不变。池 on1_JT 仍装入，hinge / 侧向 / nr1_lat 的设置原样建立，
  只是没有任何池行进入批：LossesOn 在批里没有池行时直接返回 Losses43 的结果（`if not m.any(): return`），所以 S 行的 agent / road hinge、lat_onc /
  soft / side 都不计算；`--agent-on-only` 下普通行本来就没有 agent hinge。`--on-wfile` 必须去掉：rm_train 断言它需要 k_on > 0；它在 NTV0 里只决定
  S 行的抽样（JT00S：S 组份额 1.0，trainval 行权重 0）和 JT 的等待 / 起步探针（只监控）。`--on-hold-pct 15` 留着：只决定 held 池日志，现在只用于
  池切片监控（pool_held 指标，前向不回传）。**不改训练代码**。
- **与 NTV0 的全部差别**：(1) 每批 S 行 32 → 0、navtrain 行 83 → 115；(2) 因此主行流 [seed, 0] 每步多抽 32 行，之后的抽样序列不同（必然）；
  (3) S 行抽样流 [seed, 0, 53] 不再使用，探针行不建。lr、步数、warm-up、floor、初值、噪声参数、seed 都一样。
- 只跑 seed 0，编译（默认，与 NTV0 相同）。

## 5. 判读线（写定）

旧评分器（读数自带的评分，0.744 / 0.650 也是旧评分器），主表共同场景上 NTV0NS 的均值：

- **≥ 0.72** → "NTV0 的增益不来自 S 行"（续训本身就带来大部分，NTV1 可以考虑完全离线）；
- **≤ 0.67** → "增益来自 S 行"；
- **之间** → 未定，照报，提议跑 seed 1，**不跑**。

同时报：对 NTV0-s0 的配对均值差与 95 % CI（主），对 NTV0-s1、RB0-F-s0 的配对；零分按类（offroad、漂移 / 变道 = zero-other + side、路线转、停止线冲过
= overshoot、自责碰撞 AF-front、被追尾 / 慢的部分分 = rear-hit / slow、起步数 launched / 37）与 NTV0、RB0-F 并列；navtrain dev ADE（route_mem.json）。
第 453 条之后本地数字以新评分器为准：另用 scorer_v2（`--reads` 只评本读数，自己的 root）重评，对存档新评分器的 NTV0-s0 / RB0-F-s0（NTV0-s1 只算
部分）配对，**只报，不改判读线**。
