# Probe v0：先立 baseline，再在 nuScenes mini 上打通 feature → probe pipeline

状态: done（v0 在 mini 上跑通；结论见「结果」，v1 换 trainval）
主题: ../research/qwen-latent-driving.md

## 目标

v0 不回答科研问题，只做两件事：

1. **先把 baseline 和标签立住。** 不看 Qwen，先回答"这个任务光靠 ego 运动状态能做到多少分"。
2. **把 pipeline 端到端跑通。** nuScenes mini → label → Qwen3-VL-4B 多层 feature → linear probe → 指标表。
   跑完以后，换 trainval 只需要改数据路径。

## 为什么这样设计

- **Ego-state baseline 是整个故事的前提。** 未来 2s 转不转弯，很大程度上由当前速度、yaw rate 决定。
  Qwen latent 必须**超过**"只看过去轨迹"的 baseline，才能说明它从画面里读出了东西。
  所以 baseline 放在 Qwen 之前做：如果 ego-state 已经接近满分，说明标签太容易，要先改任务定义。
- **要区分"Qwen 特有"和"任何视觉 feature 都行"。** 加一个小视觉 backbone（DINOv2）作对照。
- **mini 只能 debug。** CAM_FRONT 只有 404 个 keyframe，val 只有 2 个 scene、不到 100 个样本。
  v0 的数字一律不当结论。有统计意义的实验在 v1 用 nuScenes trainval 做。
- **v0 只做单帧。** z 怎么取（vision mean-pool / last token / 带不带 prompt）本身就是变量，
  先在单帧上把它定下来，再上 temporal。

### 实现

代码在 `jevdrive/`：`nuscenes_index.py`（直接读 JSON 表建 keyframe 表和每个 scene 20 Hz 的 ego 轨迹，
不用 devkit 的 `NuScenes` 类，因为它在 trainval 上要加载全部 annotation，很慢）、`labels.py`、`features.py`、
`probe.py`，入口是 `probe_v0.py`。feature 存在 `$DATA_DIR/processed/nuscenes/<version>/features/<backbone>/`，
每个 (layer, pooling) 一个 `(n, d)` 的 float16 `.npy`，加一个 `index.parquet` 记录行对应的 sample token。

几个实现上的选择：

- **标签**：用 LIDAR_TOP 的 20 Hz ego pose 做线性插值，yaw 先在 scene 内 unwrap（消除 ±180° 跳变）再插值。
  未来 2 s 的 Δyaw > +5° 为 left，< −5° 为 right，其余 straight。
- **ego-state 特征**：过去 2 s 每 0.5 s 采一个 pose，得到 4 段速度、4 段 yaw rate、3 个加速度，共 11 维。
- **Qwen 输入**：chat template 里只放一张图，不带文字 prompt，加 assistant 的 generation prompt，
  所以 last token 就是模型开始作答的位置。原始分辨率 1600×900 → 1400 个 visual token，序列长 1410。
- **Qwen feature**：`vit_mean`（patch merger 之前的 ViT 输出，1024 维）、`vis_mean`（merger 之后、LLM 看到的
  visual token，2560 维），以及 LLM 第 9/18/27/36 层（共 36 层）残差流的 image-token mean 和 last token。
  用 forward hook 在 GPU 上直接 pool，不保存完整 hidden states。
- **DINOv2**：ViT-B/14，整帧 resize 到 252×448（不做 center crop，否则会裁掉左右两侧），取 CLS 和 patch mean。
- **Probe**：linear probe（冻结 backbone，只训一个线性分类器，用来测 feature 里有没有线性可读的信息）用的是
  standardize + multinomial logistic regression，正则强度 C 在训练 scene 内做 scene-grouped inner CV、按 NLL 选。
  "+ego" 是把 Qwen feature 和 11 维 ego-state 直接拼接。
- **额外加的 baseline `ego_rule`**：不训练，直接把当前 yaw rate 外推 2 s 再套同样的 ±5° 阈值。
  它用来衡量"标签有多容易"。它输出的是平滑过的 one-hot（ε=0.05），所以它的 NLL/Brier 只反映 ε，不能和其他行直接比。

### 检查点结论

ego-state 本身**已经能解释大部分转弯，但学习型的 ego probe 在 mini 上学不出来**：

- 不训练的 `ego_rule` 在 LOSO（leave-one-scene-out，每次留一个 scene 做测试，10 折预测拼起来，n=314）上
  acc 0.914、macro-F1 0.817、turn recall 0.764。55 个转弯样本里有 45 个在当前时刻已经有 ≥1°/s 的 yaw rate。
  也就是说，这个标签大部分是"正在转的车会继续转"，确实偏容易。
- 学习型 `ego` probe 反而只有 macro-F1 0.424，因为训练样本太少、类别极不平衡，inner CV 选出很强的正则（C≈0.03），
  预测几乎全是 straight。单独试过：固定 C=1 能到 acc 0.873，再加 `class_weight="balanced"` 能到 macro-F1 0.741。
- 按计划真正该看的是 hard subset（当前 yaw rate ≈ 0、但未来要转）。mini 上只有 10 个这样的样本（val 上 3 个），
  在 mini 上没法评估。**决定：标签定义不变，v1 的主指标改成 hard subset 上的指标，全量指标作为辅助。**
  按 mini 的比例（10/314）估算，trainval 大约有 ~800 个 hard 转弯样本，够用。

- 优化前后：原分辨率下，把 decode + preprocess 挪到 DataLoader worker 里（pinned memory，和 GPU 计算重叠）
  从 215 降到 182 ms/frame（快 1.18×）；再加大 batch 没有收益，因为已经是 GPU 算力瓶颈。
  profile 显示 vision encoder 约 75 ms/frame（~40%），LLM 约 115 ms/frame；实测 bf16 matmul 峰值约 142 TFLOPS。
  800 px 时 token 少、kernel 小，batch 才有用（83 → 41 ms，2×）。
- 正式 run（batch 8，16 workers）：Qwen 404 帧 100 s，216 ms/frame，比 benchmark 慢约 15%，当时 box 上
  trainval 解压占满了磁盘 I/O。模型加载 3–16 s（page cache 热/冷）。
- 存储（float16）：Qwen 10 个 feature 共 **47 KB/sample**（9×2560 + 1024 维），DINOv2 **3 KB/sample**。
  如果改存全部 37 层 × 2 种 pooling，约 370 KB/sample。
- 整条链路 wall time：**170 s**（index 1.3 s，labels 0.2 s，features 111 s，probe 57 s：25 个 feature set × 11 折 = 275 次 fit，并行跑在 128 核上）。

### 遇到的问题

- box 上 uv 从 GitHub 下 Python 3.11 会卡住（直连和 turbo 都一样），改用 npmmirror 的 python-build-standalone 镜像，已写进 `docs/python-env.md`。
- `from_pretrained` 在 box 上会卡在访问 HF hub，所以 `features.py` 默认设 `HF_HUB_OFFLINE=1`，模型只从 `scripts/download_models.sh` 下好的 cache 读。
- transformers 5.17 的 Qwen3-VL 必须传 `mm_token_type_ids`，不然算不出 M-RoPE（多模态旋转位置编码）。
- nuscenes-devkit 1.1.x 会把 matplotlib 锁到 3.5（不兼容 numpy 2），所以用 1.2.0，并且只用它的 `create_splits_scenes`。
- tmux 里的非 login shell 拿不到 `$DATA_DIR`，所以长任务要用 `bash -l` 启动；wrapper 脚本已经处理。

### 给 v1（trainval）的建议

1. **主指标看 hard subset**（当前 yaw rate ≈ 0，未来 2 s 转弯）。全量指标会被"正在转弯的车"主导，ego_rule 已经能拿到 0.9 的 acc。
   阈值 1°/s 可以在 trainval 上再扫一遍，看 hard 转弯样本数和 ego_rule 的表现。
2. **probe 要处理类别不平衡**：加 `class_weight="balanced"`，或者额外报和阈值无关的指标（每类 AUROC / AUPRC）。
   inner CV 用 NLL 选 C 在小数据上会选出很强的正则，trainval 上应该好很多，但仍然建议同时报 balanced 的版本。
3. **"+ego" 拼接要改**：2560 维图像 feature 和 11 维 ego 共用一个 C，ego 信号被淹没（+ego 行和 image-only 几乎一样）。
   建议先把图像 feature 用 PCA 降到 ~64 维再拼接，或者做 late fusion：ego probe 的 logit 作为 offset，只学图像部分的残差。
4. **加 scene-level bootstrap CI**（按 scene 重采样），不然层与层之间的差距没法判断是不是噪声。
5. **层数**：probe 本身很便宜，瓶颈是抽 feature。建议 trainval 上存全部 36 层的 last token 和 image mean（约 12.6 GB），
   一次就能画出完整的 layer 曲线，不用反复抽。
6. **分辨率**：800 px 快 4.6×（41 vs 187 ms/frame）。建议先在 trainval 的一个子集上比较 800 px 和原分辨率的 probe 结果，
   差距不大就全量用 800 px。
7. Qwen 深层 last token（L27/L36）在 NLL 和 balanced turn recall 上都是图像 feature 里最好的，v1 重点验证这一点，
   以及它是不是只比 ego 多出一点"路口/车道形状"的信息。
