# Probe v0：先立 baseline，再在 nuScenes mini 上打通 feature → probe pipeline

状态: draft
主题: ../research/qwen-latent-driving.md

## 目标

v0 不回答科研问题，只做两件事：

1. **先把 baseline 和标签立住。** 不看 Qwen，先回答"这个任务光靠 ego 运动状态能做到多少分"。
2. **把 pipeline 端到端跑通。** nuScenes mini → label → Qwen3-VL-4B 多层 feature → linear probe → 指标表。
   跑完以后，换 trainval 只需要改数据路径。

## 为什么这样设计

- **Ego-state baseline 是整个故事的前提。** 未来 2s 转不转弯，很大程度上由当前速度、yaw rate 决定。
  Qwen latent 必须**超过**"只看过去轨迹"的 baseline，才能说明它从画面里读出了东西。
  所以 baseline 放在 Qwen 之前做：如果 ego-state 已经接近满分，说明标签太容易，要先改任务定义。
- **要区分"Qwen 特有"和"任何视觉 feature 都行"。** 加一个小视觉 backbone（DINOv2）作对照。
- **mini 只能 debug。** CAM_FRONT 只有 404 个 keyframe，val 只有 2 个 scene、不到 100 个样本。
  v0 的数字一律不当结论。有统计意义的实验在 v1 用 nuScenes trainval 做。
- **v0 只做单帧。** z 怎么取（vision mean-pool / last token / 带不带 prompt）本身就是变量，
  先在单帧上把它定下来，再上 temporal。

## Setup

- 数据: nuScenes mini，只用 CAM_FRONT keyframe（2Hz）。已在 `$DATA_DIR/datasets/nuscenes`。
- 划分: 官方 `mini_train` / `mini_val`，**按 scene 划分**，不能按帧随机切。
- 模型: Qwen3-VL-4B-Instruct，BF16，frozen，已在 HF cache。不量化，先不装 flash-attn / vLLM / SGLang。
- 对照 backbone: DINOv2（ViT-S/14 或 ViT-B/14），frozen。
- 环境: `$DATA_DIR` 下用 `uv` 建 venv，Python 3.11。
- 输出: feature → `$DATA_DIR/processed/`，run → `$DATA_DIR/runs/`，都不进 git。
- 算力预算: 单卡 4090 D，总共不超过半天。超了就停下来重新想。

## 步骤

### 0. 环境
- [ ] 用 uv 建 venv，装 torch / transformers / nuscenes-devkit / scikit-learn 等。
- [ ] 确认 Qwen BF16 能加载，并跑一次单图推理，记下显存占用和单帧耗时。

### 1. 标签 + baseline（不用 GPU，先做）
- [ ] `inspect_nuscenes`：列出每个 keyframe 的时间戳、ego pose、CAM_FRONT 路径。
- [ ] `build_labels`：
  - 转向标签：未来 2s 的 Δyaw → left / straight / right（阈值 ±5°）。
  - ego-state 特征：过去 2s 的速度、加速度、yaw rate。
  - 打印类别分布。
- [ ] baseline：
  - majority（永远猜最多的类）
  - ego-state only（logistic regression 或小 MLP）
- [ ] **检查点**：如果 ego-state baseline 已经接近满分，先改标签定义再往下走。
      候选方案：只在"当前 yaw rate ≈ 0、但未来要转"的 hard subset 上评估，
      也就是光看运动状态还猜不出来的那些时刻。

### 2. 抽 feature
- [ ] `extract_features`（Qwen）：单帧输入，hook 出 vision encoder 输出，以及 LLM 等距 4 层的 hidden states。
      每层存两种 pooling：vision token mean-pool、最后一个 token。先不带 prompt。
- [ ] `extract_features`（DINOv2）：CLS + patch mean-pool。
- [ ] 存成一个便于按 (sample, layer, pooling) 索引的格式，记下文件大小。

### 3. Probe
- [ ] `linear_probe`：每个 (backbone, layer, pooling) 训一个 logistic regression。
- [ ] 同一套划分下跑 "Qwen feature + ego-state" 拼接的版本，看画面信息有没有**增量**。

### 4. 出表
- [ ] 一张表，行 = majority / ego-state / DINOv2 / Qwen 各层 × pooling / Qwen + ego-state，
      列 = acc、macro-F1、NLL、Brier，加上样本数。
- [ ] 整条链路一条命令能从头重跑。

## 并行准备（不阻塞 v0）

- [ ] **nuScenes trainval 只解压 CAM_FRONT。** 原始 blob 294G，box 数据盘只剩 37G，
      所以要用 tar 的通配符只取 `samples/CAM_FRONT`（keyframe 约 34k 张，估计 < 10G），
      先不取 sweeps。再加 `v1.0-trainval_meta`。给 `scripts/extract_nuscenes.sh` 加一个 `trainval-front` 模式。
- [ ] 提交 Waymo Open Dataset license 申请。

## 成功标准

- 第 4 步的表完整生成，一条命令可重跑。
- 第 1 步的检查点有明确结论：标签定义可用，或者已经换成了 hard subset。
- 工程数字记下来：单帧抽 feature 的耗时和显存；每个样本的 feature 占多少盘。
  这些数字决定 v1 在 trainval 上怎么存、要跑多久。
- **不要求** Qwen 赢过 baseline，v0 的样本量说明不了这个。

## 不做

- temporal probe（D）、candidate logits（B）、autoregressive（A）
- temperature scaling / ECE、latency 对比
- 纵向（加减速）和横向位移类别，v0 只做转向

→ 在最好的层上加 temporal probe（D）。
