# Controller scorecard（Task 10 v2）

规则：[controller-eval-rules.md](controller-eval-rules.md)；操作协议与冻结后五处接口修正：[controller-eval-protocol-v2.md](controller-eval-protocol-v2.md)；调参记录：[controller-eval/tune/README.md](controller-eval/tune/README.md)。数据：`controller-eval/results-v2/`（L1 每例与汇总、L2/L3 每例与汇总）。

参评：A（TFv6 作者 route/target-speed PID，即 LEAD PDM-Lite expert 的控制器）、B（作者 waypoint PID）、C（我们的 pursuit + PI）、D（C + rear_slip 瞄点 + ackermann 反解）、P（D 的横向 + 新的 plant 反解纵向，dev 两轮调参选出）、P2（P + 低速刹车规则，见下）。TCP 另有原生 N（official `only_traj`）。所有 C/D/P/P2 在各 planner 上用同一套参数。

## 结论

**按冻结规则，没有任何控制器被判为"更好"。** C、D、P 在 L1 上显著优于 A 和 B，但 L2 在 TFv6 上没有全部指标不变差，L3 的 DS 非劣护栏在两个 planner 上都没有成立（CI 太宽或明确更差）。

| 控制器 | L1（ramp 与 profile 都显著优于 A、B） | L2 可行 plan（TFv6，相对 B） | L3（DS 相对原生，下界 ≥ −3） | 判定 |
|---|---|---|---|---|
| C | 是 | 位移显著更好、jerk 显著更好、速度误差显著更差（+0.14 m/s，超过 0.10 界） | TFv6 −7.6 [−16.8, +1.2]；TCP +3.7 [−15, +27] | 未确立 |
| D | 是 | 同 C | TFv6 −8.1 [−17.6, +1.0]；TCP −13.8 [−30, +5] | 未确立 |
| P | 是（且最平顺） | 位移、速度误差都显著更差 | TFv6 −16.8 [−29, −5] | 更差 |
| P2 | 未在 held-out L1 上跑（dev 上与 P 相当） | 位移与 B 持平、速度误差更差 | TFv6 −6.3 [−16.3, +0.4]；TCP −4.8 [−24, +13] | 未确立 |

核心发现：**L1 上可以做出又准又平顺的执行器（P），但在闭环里这点优势传不过去。** TFv6 闭环的额外 jerk 由 plan 本身的变化主导（A 25.6、B 5.4、C 4.4、D 4.2、P2 4.9 m/s³），执行层平顺化的空间被模型 plan 的抖动吃掉；而 P 的碰撞暴露了一个 L1 覆盖不到的工况（跟车蠕行到停）。

## P 的失败与 P2

P 在 TFv6 上撞车 10 次、在同路线两个 seed 上都复现。逐帧看 26456：前车停下，TFv6 plan 要求停车（v_plan = 0），车以 0.5–0.6 m/s 蠕行，P 输出油门 0.25、不刹车，C 同时刻输出刹车 0.45–0.7。原因：执行器映射在 2–9 m/s 上测得，那里油门 0.25 意味着约 −1.2 m/s² 的减速；近静止时没有发动机拖曳，同样的油门让车继续前爬，而 P 只在命令低于滑行减速（约 −2.8 m/s²）时才刹车。P2 加一条规则：车速 < 2 m/s 时负加速度命令一律用刹车。这是 held-out 上发现的问题，所以 P2 先过 dev 闸门（dev L1：primary 0.63、0 失败，D 1.01；dev 8 条 scenario 路线 TFv6 闭环：车辆碰撞 P2 3、C 4、P 1、A 1），再上 held-out。P2 把碰撞降到与 C 相同，DS 与 C/D 持平，但精度和速度跟踪不如 C/D。P2 的 held-out L1 未跑。

## 对评测规则本身的教训

1. **L1 的公平性要靠接口逐项核对。** v1 的 L1 有七处接口伪差（起步阶跃、C 自驾的"expert"、A 的 route 塌缩、5 Hz plan、plan 过带噪定位、时间轨迹要求倒退、ramp 过弯不可行），多数偏向 C（其余对各控制器都有害）；修完后 C 的 L1 优势依然成立，但幅度从 v1 的 primary 1.04 vs 3.70 缩到 0.92 vs 2.38。
2. **L1 对闭环没有足够的预测力。** 缺两类工况：跟车蠕行到停（P 的失败）和带模型式噪声/抖动的 plan。下一版 L1 应加入这两类。
3. **TFv6 是与 A 共同优化出来的**：A 就是 TFv6 训练数据的 expert 控制器。在 TFv6 上 L3 非劣本来就难；TCP 上 C 与原生打平（+3.7，CI 宽）更能说明执行层本身的价值，需要更多路线把 CI 收窄。
