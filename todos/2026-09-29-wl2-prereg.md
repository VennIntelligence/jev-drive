## 为什么要做

WL-1 用干预数据（动作不由看见场景的策略选择，而是按与未来场景无关的规则选的分支）重训了 W 的预测器，纵向动作效应读对了（刹车 > 保持 90.5%，W 原版 10.3%），
critic（给每个候选的推演结果打 unsafe 分的模块）在推演 latent 上 AUC 0.909，而且在训练时拿掉的动作类型上远好于 model-free Q（不推演、直接读 [z_t, 动作] 的对照，0.885 对 0.489）。
没过的三条，事后看各有一个具体原因，其中两条是**判据本身不能区分好坏**，一条是**考卷数据里可解的题太少**：

1. **C1 shift 一致率 61.7%**：在全部分叉点上算，但多数分叉点 `op` 与 shift 两边 2 s 时本车道都空（`occ` 标签都是 0），「下降」的真值为假，推演 logit 的微小差随机落在一边。
   W 原版（已知动作效应反向的阳性对照）在同一口径上也是 61.7%，所以这个口径分不开好模型和坏模型。只看 `op` 分支本车道被占的子集，main 76.0%、W 原版 55.9%——这个子集能分开。
2. **C3 x⁺ unsafe 只降 30%（线 50%）**：oracle（每个分叉点直接挑真实最好的分支）自己还有 28.1% unsafe，登记的「相对 `op` 降一半」隐含假设 oracle ≈ 0。
   按「选择挽回了 `op` 到 oracle 之间差距的几成」算，WL-1 是 0.545 [0.22, 0.80]（事后计算，只作设计依据，不改 WL-1 的判格）；CI 这么宽是因为 64 个 x⁺ 评测分叉点里真正「`op` 不安全而有安全候选」的只有 22 个。
3. **C4 行人 0%**：考生输出是 7 个候选之间的离散切换（所选候选的 2 s 速度），只换天气的 null 对里 51–60% 换了候选，τ（null Δ 的 95 分位数）高达 7.5–8.1 m/s。
   事后把输出换成 critic 对 `hold` 的风险，行人翻转 43–47%——信号在 critic 里，被离散规则吃掉了。

另外，WL-1 的 130 个评测分叉点已经被看过、并且上面的口径设计就是看着它们做的，所以 WL-2 必须在**新的留出分叉**上判。

## 要回答的问题

在新的留出分叉上，用事先写死、能区分好坏的口径：
(1) 加显式 ego 横向状态通道后，世界模型能否读对横移的后果（障碍离开 ego 走廊）；
(2) WL-1 的纵向因果与 critic 结论能否复现；
(3) 在更密的分叉时刻和扩充的候选集上，选择规则能挽回多少可挽回的安全；
(4) critic 的连续风险读数在配对考卷上是否对行人与 cut-in 有反应。
四个问题的结果决定要不要进入想象训练（imagination training：策略只在世界模型推演出的 latent 轨迹上展开和更新）的**设计讨论**；WL-2 本身不开始任何想象训练或策略更新。

## 从 WL-1 数据估出的 headroom（设计依据）

表里的「headroom」指 `op` 的 unsafe 率减去 oracle 的 unsafe 率，即候选集在这里最多能挽回多少。数字按 `runs_full.csv` 的 2 814 个分支 run 的模拟器标签算（训练 + 评测全部 x⁺ 分叉点，没去渲染剔除的 run，标签不受渲染影响）。
「cg 标签」= 碰撞或本车道最小间距 < 2 m，也就是登记的 `unsafe` 去掉 TTC（time to collision，间距除以接近速度）< 1.0 s 这一项。

| x⁺ 分叉点 | n | `op` unsafe | oracle unsafe（登记标签） | oracle unsafe（cg 标签） |
|:--|--:|--:|--:|--:|
| 行人 k1（hazard 首次可见） | 41 | 0.51 | **0.05** | 0.00 |
| 行人 k2（k1 + 0.6 s） | 38 | 0.66 | 0.13 | 0.03 |
| 行人 k3（expert 反应前 0.4 s） | 20 | 1.00 | **0.95** | 0.50 |
| cut-in k1 / k2 / k3 | 18 / 19 / 25 | 0.06 / 0.05 / 0.60 | 0.00 / 0.05 / 0.08 | 0.00 / 0.00 / 0.00 |
| 障碍 k1 / k2 | 4 / 5 | 0.25 / 0.40 | 0.00 / 0.00 | 0.00 / 0.00 |
| 障碍 k3 | 33 | 0.97 | **0.42** | 0.03 |

读法：
- **headroom 主要由分叉时刻决定，不是候选集**。行人 k3 几乎无解（oracle 95%），行人 k1 / k2 几乎全可解。WL-1 的 k3 占 x⁺ 的 38%，把它们混进「相对 `op` 降一半」的分母，线就过不了。所以 WL-2 把分叉时刻加密在 k1–k2 之间（这本身就是「变道 / 刹车时机」的维度），C3 改成 headroom 口径。
- **障碍 x⁺ 的「候选里没有好答案」大半是 TTC 项**：登记标签下 14 个 oracle 仍 unsafe 的障碍分叉点里，13 个至少有一个候选只因 TTC < 1 s 被判 unsafe（没撞、间距 ≥ 2 m），其中 12 个是 `shift_L`。
  也就是横移绕过去了，但绕的过程中对走廊里的 actor（被绕的障碍或对向车）接近速度偏高。登记标签下 22% 的 unsafe 只来自 TTC 项。这给「慢速横移」一个具体的上界估计：障碍 x⁺ 的 oracle 最多能从 0.33 降到约 0.02（全部 42 个障碍 x⁺ 分叉点）。
- **更硬的刹车没有余量**：用 `hold` 未碰撞时的 3 s 行驶距离估 v₀（中位 7.2 m/s，273 个分叉点），`brake_hard` 实测行驶距离的中位是「无延迟 −6 m/s² 运动学」的 0.75，执行器已饱和，所以不加 emergency brake 候选。
  反过来，中间档有用：`op_slow` 安全而 `op_stop` 不安全的分叉点有 15 个，`brake_hard` 安全而 `op_stop` 不安全 14 个，风险对刹车强度不单调，加一档轻刹。
- 组合动作（横移 + 减速）在 WL-1 里没有分支，它在行人上的 headroom 无法从数据估，只给上面障碍的上界。

### 生成配置（与 WL-1 的差别）

- **不跑分支后的 20 s 续跑，也不跑 D2**：续跑的随机窗口主要给运动学量，WL-1 已有 71 585 个干预步；去掉续跑，每个从头 run 从约 181 s 降到约 111 s（BA），而且是回退变体的前提（续跑依赖分支，没法共享）。
- 其余不变：全程渲染前缀（no_rendering 在 WL-1 第 1 级不过）、不挂 TFv6 影子、灯光用 stock（**不开** `B2D_KEEP_STREET_LIGHTS`，来源 run 是 stock 画面，开了会让夜间前缀与来源不一致）、修正 (a)(b)(c) 的剔除规则原样。
- 每个分支 run 额外存 route 的稠密中心线（agent 的 global plan），供 ego 横向通道用。

## 模型与臂

### 主改动：显式 ego 横向状态通道

每个 5 Hz 步加一个 5 维 ego 状态 s_t = [e_y（相对 route 中心线的有符号横向偏移，m），e_ψ（航向误差，rad），v（m/s），a（m/s²），ω（yaw rate，rad/s）]。
- WL-2 的新 run 用存下的中心线算；WL-1 的 run 用 route XML 离线插值：`carla.Map(town, xodr)` 不需要 server，就能用 GlobalRoutePlanner 重建稠密路线，只花 CPU。
- 预测器：输入 token = [z_t ; s_t]（s 按训练集标准化），输出 Δ[z ; s]；损失在 openpilot 块、V-JEPA 块、s 块三者之间等权平均（W 原来是两块等权），其余结构与 `W.CFG` 一字不改。
- probe（`occ`、`ped`、`d_front`、`v`）与 critic 都读 [z, s]（推演时读 [ẑ, ŝ]）；Q 也读 [z_t, s_t, 动作序列]，保证对照公平。
- 为什么是这个而不是先换 latent：WL-1 里横移失败最直接的解释是 pooled latent 对「ego 横向在哪」编码弱（C-probe 读推演 latent 只有 AUC 0.69），显式通道把 ego 自身的横向运动从 latent 里拿出来，成本几乎为零；
  如果加了它 shift 还读不对，问题就在「障碍在画面哪一侧」这一层，才需要空间 token。
- 部署口径的限定：中心线是 CARLA 的 route，相当于导航路线；换成 openpilot 自己的 lane line 输出是可部署版本，更吵，本轮不做（开放问题 3）。

### 副臂：V-JEPA 2 空间 token

- latent 的 V-JEPA 块从 `mean`（每相机 1 024 维）换成 patch token 在最后一个 temporal slice 上池化成 2 × 4 网格（上下两行、左右四列，横向分辨率优先），每相机 8 个 token、共 24 个 × 1 024，加 openpilot `temporal` 一个 token；预测器改成每步 25 个 token 的 token Transformer（层数、宽度同 W）。
- **存储**：fp16 每行 48 KB；新 WL-2 训练 run 约 7.6 万行（3.7 GB）+ W 日志帧 4.9 万行（2.4 GB）；如果 WL-1 分叉 run 的 JPEG 还在，再加 30.8 万行约 15 GB。可选 PCA 到 256 维（约 1/4）。数据盘剩约 1.4 TB，不是约束。
- **WL-1 的 JPEG 可能已删**：`wl_data prune` 这一步存在，`wl_full.sh` 的 STEPS 里没调，WL-1 登记里写过「抽完删 JPEG」。批准后先在 box 上核一次（只读）。如果已删，token 臂只能在 W 日志帧 + WL-2 新数据上训练，这时同时训一个同数据的 B 臂（`B-same`）做公平对照。
- **算力（估，第 1 级实测后改）**：抽取与 `mean` 同一次前向，新数据约 0.3 GPU·h（若 WL-1 JPEG 在，再加约 1.2 GPU·h）；序列长 25 倍，单个预测器约 30–60 min，3 seed 约 2–3 GPU·h。需要改 `jevdrive/features.py` 加一个 grid tap。
- 只描述，不进判格；它回答「B 臂 shift 不过时，是不是表示问题」。

  WL-1 单个预测器 112–119 s，5 seed 很便宜。

## 判据（写在任何 WL-2 数字之前；只在新评测分叉上、`B` 臂上判）

CI 一律按 base 路线整组 bootstrap（2 000 次），seed 的处理同 WL-1（C1 对 seed 均值判，C2 / C3 用 seed 平均的概率）。
每条线都给了最小样本量：不够时写「不可判」，不按字面判过或不过。

### C1 动作因果

| # | 量 | 线 | 理由 |
|:--|:--|:--|:--|
| C1a | `brake_hard` 对 `hold`，推演 2 s 后 `d_front` 读数「刹车更远」的比例 | ≥ 85%（不变） | WL-1 过了；在新分叉上复现 |
| C1b | 推演 Δd 与真实 Δd 之差的中位数 | ≤ 3 m（不变） | 同上 |
| C1c | **被占子集上的横移可分性**，定义见下 | AUC ≥ 0.75，且 `B` − `worig` 的 AUC 差 CI 下界 > 0 | 见下 |

**C1c 的精确定义**：
- 子集 S = 所有 (评测分叉点, 横移侧 ∈ {L, R})，满足：`op` 分支在分叉 + 2 s 时 `occ` 真实标签 = 1（`occ` = ego 坐标系前方 0–30 m、|y| ≤ 1.75 m 内有道路 actor，与 W 的 `nq4_w` 标签同一定义）；`op` 与该 shift 分支都有标签、都没被渲染剔除；该分叉点没有退出成对读数。
- 真值：该 shift 分支在分叉 + 2 s 的 `occ` 标签（0 = 已离开被占走廊，1 = 仍被占，例如横移进了有车的邻道）。
- 分数：`B` 对该 shift 候选推演第 10 步（2 s）的 `occ` probe 概率。AUC = 这个分数区分「仍被占」与「已离开」的能力。
- 最小样本：两类各 ≥ 20 对、来自 ≥ 8 条 base 路线。**「仍被占」一类不足 20 对时**，换成 WL-1 的差分口径（推演 `occ` 概率 shift < `op` 与真实「已离开」一致的比例）在 S 上 ≥ 75%，且 `B` − `worig` 的差 CI 下界 > 0，并注明用了回退口径。
- 理由：只在 `op` 走廊真被占的地方，「横移让障碍离开走廊」才是有真假的问题；绝对概率的 AUC 不依赖两边 logit 的微小差、也不受「多数横移都会离开」的基线率影响（总是说「离开」的 AUC = 0.5）；
  0.75 沿用登记原线的数值；加上对 `worig` 的判别要求，是因为 WL-1 暴露了「W 原版也拿到同样分」的口径失效，线必须同时证明阳性对照在这里输。
- 描述并列：WL-1 原口径（全部分叉点的一致率）；`ŝ` 的横向偏移对真实 e_y 在 2 s 的误差（只有 `B` 有）；新横移类候选（`shift_*_slow`、`nudge_L`）上的同一 AUC。

### C2 推演出的后果（与 WL-1 完全相同的线）

C-learn 在推演 latent 上对真实 unsafe 的 AUC ≥ 0.85；同分叉点内 unsafe 对 safe 分支成对排序 ≥ 80%；(a) C-learn − Q 的 AUC 差 CI 下界 ≥ −0.02；(b) `B-holdout` 在 `shift_R` / `op_slow` 分支上 C-learn − Q 的 AUC 差 CI 下界 > 0。
在全部 11 个候选上判；原 7 个候选子集并列（与 WL-1 可比）。`B-holdout-combo` 上的同一个差只描述。

### C3 离线选择（改成 headroom 口径）

记 x⁺ 评测分叉点上 U_op、U_sel、U_or 分别为永远选 `op`、选择规则、oracle 的真实 unsafe 率（结果都是模拟出来的真实分支，不是推演）。

| # | 量 | 线 | 理由 |
|:--|:--|:--|:--|
| C3a | H = (U_op − U_sel) / (U_op − U_or)，x⁺ 全部分叉点合并计算 | H ≥ 0.50 且 H 的 CI 下界 ≥ 0.25；另要求 U_op − U_sel 的 CI 下界 > 0 | 见下 |
| C3b | x⁻ 上 3 s 进度 / `op`（配对均值）；x⁻ unsafe | ≥ 0.90；≤ `op` + 2 pp（不变） | 不能靠一律刹车换安全 |
| C3c | H(C-learn) − H(Q)，Q 用同一选择规则，进度用候选指令自带的 2 s 进度 | CI 下界 > 0 | 世界模型在「选择」上是否比 model-free 必要；**不进 go / no-go**，只决定叙述 |

- 最小样本：「可解」分叉点（`op` unsafe 且 oracle 有安全候选）≥ 40 个、来自 ≥ 15 条 base 路线，否则 C3a 不可判。
- 理由：登记原线「相对 `op` 降 50%」的本意是「挽回一半的风险」，它默认 oracle ≈ 0；WL-1 的 k3 分叉点上 oracle 自己几乎全 unsafe，这部分没有任何候选能挽回，不该算进分母。H 把同一个 0.5 放在可挽回的部分上，**数值与原线相同，没有按 WL-1 调**；
  透明起见：WL-1 事后按此口径是 0.545 [0.22, 0.80]，点估计会过、CI 下界 0.22 不过 0.25，也就是在 WL-1 的样本量下这条线过不了，要靠 WL-2 的样本量说话。
  0.25 的下界要求「至少可靠地挽回四分之一」，按 WL-1 的方差和 WL-2 的目标样本量（约 60 个可解分叉点），真实 H = 0.5 时下界大约 0.3。
- 描述并列：按 k 与类分层的 U_op / U_sel / U_or；「挽回率」（可解分叉点里选对的比例，WL-1 = 14 / 22）与「伤害率」（`op` 本来安全、选择反而 unsafe 的比例，WL-1 = 2 / 24）；cg 标签下的同一套数；
  最优的单一固定候选（在满足 C3b 的前提下）的 H；只用原 7 个候选时的 H（候选扩充本身的贡献）；「非行人危险两边都有」分叉点单列（修正 (b)）。

### C4 配对考卷（考生改成连续风险读数）

- **考卷**：与 WL-1 C4 相同（P5 v1 BA 的 20 条评测 base 路线、seed 0 / 1 / 2、`p5_exam.exam` 原样、null 表只取这 20 条路线，τ 与样本外 null 误翻在这个子集上重算）。
- **考生**：对每个考卷帧，`B` 用该帧前 8 步的 [z, s] 推演 `hold` 候选（路线中线、当前车速）10 步，C-learn 读推演结果得 p̂；5 个 seed 的 p̂ 取平均。**考生输出 = −p̂**（风险越高输出越低，与「规划的 2 s 速度」同号），obs / null 的 Δ 定义不变。
  选 `hold` 而不是 `op`：`hold` 在 x⁺ 与 x⁻ 里是同一个动作，Δ 只来自场景；`op` 的风险会混进 openpilot 自己在 x⁺ 里的反应。用概率而不用 logit：logit 在 0 / 1 附近放大微小差，null 的尾巴更长。
- **判格**：行人 = 翻转率 CI 下界 > 样本外 null 误翻 + 10 pp（第 48 条的判格，按考卷代码的 null 下限）；cut-in = **同一个 null 判格**，`ridge_late` prior 只作参照。
  理由：WL-1 的 cut-in 线「不低于 prior − 5 pp」衡量的是规划输出，prior 本身就是 openpilot 对 cut-in 的反应；风险读数不是规划，拿它比 prior 的 85.5% 是不同的量。
- 描述并列：每个 seed 单独的翻转；Q 对 `hold` 的风险（model-free 的同一种读数）；M-C `pair [cinque]`；WL-1 的离散选择考生（原定义）。
- 限定：这份考卷在 WL-1 事后读数里看过（`hold` 风险 43–47%），WL-2 的考生是事先写死、模型重训后的新读数，但不是新考卷。P6 bypass 翻转仍不做。

### 中期前能做多大

09-30 中午后只剩 2 卡，D2–D8 两张卡按排期给 op-adapt 第二轮和 openpilot 闭环；box 按天计费，WL-2 花的是卡时的机会成本（1 卡 12 h 约 80 元），不是额外的钱，约束是空档。
一个空闲夜里的一张卡（约 12 h × 6 worker ≈ 70 worker·h）是现实的上限：
- **rewind 过**：全量（约 35 worker·h）一晚能完，还富余；
- **rewind 不过**：只能做缩减变体（约 67 worker·h，正好一晚）。缩减后可解分叉点约 55 个（按 WL-1 在 k1 / k2 与障碍 τ 规则下的可解率约 45% 估），刚过 C3a 的最小样本；训练侧只补 P6 障碍，BA 的横移样本仍靠 WL-1。
- 时间线（批准后）：代码 0.5–1 天（Mac 写、box 小测）→ 第 1–2 级约 2 h → 全量一晚 → 特征、训练、读数约半天。rewind 的结论预计 09-30 出，出了再选变体。结果预计 10-04 前后，给中期留 4–5 天。

## 开放问题（给用户）

1. **主 unsafe 标签是否换成 cg（碰撞或间距 < 2 m）**：障碍 x⁺ 的 oracle 在登记标签下 33%、cg 下 2%，22% 的 unsafe 只来自 TTC 项。本草案为了 C2 可比保留登记标签作判格、cg 只描述；如果换，C2 的线不变但 AUC 不再与 WL-1 直接可比。
2. **变体选择**：rewind 过 → 全量；不过 → 缩减。是否接受「rewind 只过 R1–R3 时评测用回退、训练用从头」的混合（约 104 worker·h，一晚放不下，要两晚或 2 卡）。
3. **ego 横向通道的来源**：本草案用 CARLA route 中心线（特权但等价于导航路线）；是否要求同时做一个用 openpilot 自己 lane line 输出的可部署版本。
4. **token 副臂是否做**：约 2.5–4 GPU·h，且 WL-1 JPEG 若已删，只能在较小数据上与 `B-same` 比。可以推迟到 C1c 不过之后再做。
5. **新评测分叉只换了世界（seed 1 / 2），路线几何是 WL-1 看过的 40 条**：是否足够算「新的留出」，还是要另找新 base 路线（需要新建 P5 / P6 来源 run，成本另算，中期前不现实）。
