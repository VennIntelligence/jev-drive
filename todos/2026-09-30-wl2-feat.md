# WL-2 特征抽取（z 与空间 token）

状态：完成（2026-09-30 15:17 起，16:25 收尾）。预登记见 [wl2-prereg](2026-09-29-wl2-prereg.md)，WL-1 的做法见 [wl-spatial-tokens](2026-09-29-wl-spatial-tokens.md)。

## 做了什么

WL-2 输出的布局与 WL-1 一致（`runs/wl2/gen/<set>/done`、attempt 目录里的 `frames.jsonl`、`cams/`、`route.json`），所以没有另写 pipeline，只加了一个小 adapter：[jevdrive/wl2_feat.py](../jevdrive/wl2_feat.py) 和 [scripts/wl2_feat.sh](../scripts/wl2_feat.sh)。
它按 run 而不是按 index 行 chunk 做键（index 要到生成结束才定型），对已完成的 run 循环扫描，生成结束后再扫一遍。

- V-JEPA：一次前向同时出 `mean`（写成 `wl_data` 的 `vjepa/c*.npz` 格式）和 2×4 grid token（`tok/x*.npz`）。每帧在 worker 里只解码一次（LRU），输出与 `VJepaFeatures.transform` 逐位一致，JPEG 解码少 4 倍。
- ego 通道：e_y、e_ψ 用 WL-1 dry-run 同一函数（相对每个 run 的 `route.json` 折线），存 `tok/x*.npz` 的 `ey`，装配后得 `ey.npy`（N×2）。v、a、ω 仍从 index 的列取。
- openpilot `temporal`：流的布局与 `wl_data.opspec` 一致（来源 run 前缀帧 + 本 run 帧），用 `p5_openpilot.py --keys` 按 run id 分 shard 跑，直接写进 `op_streams_vis/cinque`，wl_full 后续的 `index opspec op / vjepa z` 因此几乎是空操作（op 162 s，vjepa 4 s）。
- 生成结束后 wl_full 自己完成了 `index` 与 `z`；本 lane 再 `assemble` 出 `tok.npy`、`ey.npy`、`tok_ok.npy`。

## 计时

- V-JEPA：215 045 行（645k clip）从 15:21 到 16:22，稳态约 260 clip/s（8 核 + GPU 2；第一次误按 WORKERS=2 启动只有约 120 clip/s，登录 shell 导出了 `WORKERS=2`，改用 `WL2_WORKERS` 后翻倍）。WL-1 的 144 clip/s。
- openpilot：单卡 11 ms/frame（模型段），首段 2 worker 时渲染受限 17 ms/frame；共 8 276 条流（含 742 条 pilot 复用），生成结束时余下 1.7k 条分到 GPU 3、5、6 三个 shard，约 6 min 清完。
- 全程比生成只晚 about 10 min：生成结束 16:10，最后一次扫描与装配 16:25。GPU 只用 2、3（生成结束后加 5、6），VRAM 每卡 < 20 GB。
